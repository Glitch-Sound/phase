# WAITの入口統一の検証

## 変更

戦闘画面本体のWAITボタンと専用ツールチップを削除した。\
手動の移動なしWAITは、現在手番の操作可能ユニットをダブルクリックし、ACTIONのWAITを選ぶ経路へ統一した。\
MOVE状態から直接実行するUI関数の分岐も除き、ダイアログのWAIT、BACKとEsc、入力保護と消去後の確定を維持した。

現在の手番を人が操作するかで可否を判定する。\
両陣営手動では敵側の現在手番も操作でき、CPUの敵と非手番の敵では開かない。\
利用者の原文のユニット操作への統一と、従来の両陣営手動を維持するためであり、所有マークと視点、CPU判断は変更していない。

独立WAIT用の空部品と余白は残していない。\
BATTLE_CONTEXT_BUTTONは対象選択のBACKと共有するため保持し、マップとメニュー、ユニット情報を動かしていない。\
移動後の通常ACTIONとCPU内部のWAIT、移動とパネル、スキルと音の処理は維持した。\
既存の短い開始通知もダブルクリックを示す英日文へ更新した。

## 検証

- 先行検査ではHUDの独立WAIT不在、直接UI経路の不在、手動の敵手番の3条件が失敗した。
- 変更後のTACTICAL DECISIONS UIは74件で失敗0となった。移動先のある場合と閉塞、ダブルクリックだけの非確定、初期無効化、BACKとEsc、移動なしの状態と手番、移動音の不変を確認した。
- 既存のメニューと閉塞検査をACTION経由へ更新し、通常の攻撃と回復、移動後のWAIT、非手番とCPUの拒否を維持した。バランスに依存する固定勝敗と手数の期待値は追加していない。
- Godot 4.7.2、Apple M4、Compatibilityの実ウィンドウで45件、失敗0となった。英日と1920x1080、1152x648で、HUDの不在、ダブルクリック、直後の無効クリック、長押し、解除後のWAIT、Escと通常経路を確認した。
- 実ウィンドウでも手動の敵の現在手番は開き、CPUの敵は開かないことを確認した。囲まれたRESETセルのWAITでもCORE角を再適用しなかった。
- npm run checkと正式仕様9件、OpenSpecとトレースのstrict検証、git diff --checkが成功した。プロダクトの検査コマンドの変更はない。

verifyではREQ-010とREQ-012の全10シナリオを既存の検査と対応付けた。\
HUDの不在とACTIONの候補の完全一致、原状態の全体比較を使い、誤った独立入口と即時確定を見逃さないことを確認した。\
設計D-01とD-02に従い、CRITICALとWARNINGの指摘はない。

実セーブ、設定と原音など既存20ファイルの内容と更新時刻は不変であり、旧成果物と未追跡の.DS_Storeを保持した。\
外部公開とpushは行っていない。

## Library保存の停止

現行の公式まとめ保存手順で2枚を指定したが、標準実行は接続開始時のDNS制限で停止した。\
画像送信前であることを確認して接続可能な実行を求めたところ、自動承認レビューが本人の宛先と対象2枚への明示承認不足を理由に拒否した。\
認証済み会話を確認したが今回の明示承認はなく、迂回と再送を行っていない。\
確認済みLibrary IDは0件であり、本人の承認を待っている。\
コードの完了とローカル成果物の確認をこの停止で保留していない。
