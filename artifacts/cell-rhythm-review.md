# セル中心で拍を付ける移動の試作

## 変更

5624d5fを基準に、表示用の歩内の進みだけを変更した。\
各歩のtをt-a*sin(2πt)/(2π)へ写し、aをgame/tuning.gdのMOVEMENT_CELL_PULSEへ0.60として置いた。
速度は平均の0.40から1.60倍で、セル中心付近でもゼロにならず、停止時間と逆行を加えない。
中心を通過する時刻、1歩0.28秒と上限0.90秒、攻撃前の0.22秒、雲の出発と再表示の時間は変更していない。

位置とCORE、GEAR、ARMSの補間へ同じ進みを使う。\
実際の位相量とパネル、周囲効果、経路と戦闘、選択と確定、CPUの判断と時計へ書き戻さない。
音、光と白い実行経路は追加していない。\
赤い収束は白縁なし、緑の拡散とHP実増分の反応も維持した。

## 自動検査

既存の移動部品検査へ3項目を追加し、等速の旧実装で減速条件が失敗することを先に確認した。\
実装後は47項目すべて成功し、既存の期待値は変更していない。
位置だけに新しい進みを使いリングを等速のままにする誤実装も、位置と位相の対応の検査が拒否した。
ケースの組み合わせと固定バランスの期待値、検査コマンドは増やしていない。
npm run check、変更と正式仕様のstrict検証、トレース検査が成功した。

## 実描画と観測

Godot 4.7.2、Compatibility、Apple M4で、1152x648と1920x1080を確認した。\
既存の実描画検証を新しい隔離先で再利用し、397判定すべてが成功した。
曲がる2歩と1歩、CPUの移動と攻撃、HELPと再開、退出と再戦、移動による終局を確認した。
盤上と右情報、PREVIEWは同じ移動者の状態を示し、雲は出発前に消え、移動中はなく、着地で戻った。
実機確認の行は利用者の最終判断のため未確認を維持した。

前回と同じシード128、異なる6構成の全解放3対3、TURN08とTURN09を新規収録した。\
最初の7手は合法に再現し、対象2手は経路、行動と対象、最終確定を既存UIから選んだ。
TURN08の4,4から4,3を経て5,3へ曲がる2歩と、TURN09の1歩を比較した。
旧新の最終ユニット状態と履歴、出発、着地と攻撃のフレーム時刻は完全一致した。

| 最初の移動の経過時刻 | 旧位置 | 新位置 |
| --- | --- | --- |
| 0.213秒 | 4, 3.238095 | 4, 3.142869 |
| 0.280秒 | 4, 3 | 4, 3 |
| 0.347秒 | 4.238095, 3 | 4.142869, 3 |

中心の前後で位置と角度の変化が小さくなり、方向を切り替えても次のフレームへ進んでいた。\
主観的には等速よりセルごとの拍を読みやすいが、止まる演出ではなく控えめな速度差である。
最終的な強さの好みは利用者が判断する。

## 保護と限界

実セーブ、旧動画と過去の比較画像を含む31ファイルはSHA256と更新時刻が不変である。\
