# 手番ユニットのその場行動の検証

## 変更

盤面の現在手番ユニットをダブルクリックすると、0マスのWAITだけを選べるACTIONを開く。\
自軍の判断は既存のview_campを使い、通常はPLAYERである。\
既存のCPU操作の遮断とモーダルの入力遮断を保ち、単クリックは従来どおり経路を取り消すだけとした。

turn_plan.beginのstationary指定と既存のACTIONを共用する4行の入口追加である。\
ダブルクリックは予定を開くだけで、WAITの確定と消去後のフレーム待ち、移動なしの手番進行は既存経路を使う。\
BACKとEsc、開いた直後の入力保護、通常の移動先のダブルクリックは変更していない。\
位置、パネルと回転、戦闘式、音源と音の条件、CPU判断を変更していない。

## 検証

- 先行検査では、空いた移動先のある場合と囲まれた場合の入口が開かず、2件失敗した。
- 追加後はTACTICAL DECISIONS UIが72件で失敗0となった。既存の検査本体は変更せず、REQ-010-S06の入口検査だけを追加した。
- 候補の全体集合がBACKとWAITだけであり、初期無効化、連続ダブルクリックの非確定、BACKとEscでの状態不変、明示WAITだけの実行を確認した。
- 非手番の味方と敵、CPUの手番、所有視点の敵の手番、HELP表示中から開かないことを確認した。
- 通常の0マスWAITが位置とHP、3角度、パネル、移動音を変えない既存検査も成功した。固定勝敗、決着手数とダメージの期待値は追加していない。
- Godot 4.7.2、Apple M4、Compatibilityの実ウィンドウで39項目、失敗0となった。英日、1920x1080と1152x648の表示と入力を確かめた。
- GodotのGUI入力へマウスの押下と解除を送り、盤面の単クリックとダブルクリック、直後の無効なクリック、押下解除後のWAIT、Escを確認した。通常の経路終点のダブルクリックも実画面で維持した。
- npm run check、正式仕様9件の検証、OpenSpecとトレースのstrict検証、git diff --checkが成功した。プロダクト検査コマンドの変更はない。

## verifyと限界

4タスクとREQ-010の全6シナリオを実装と検査へ対応付けた。\
期待値は候補の完全一致と戦闘状態の全体比較であり、誤って別の能動行動を混ぜる場合と即時WAITの確定を見逃さない。\
設計D-01に従って既存予定の接続だけを変更し、CRITICALとWARNINGの指摘はない。

囲まれたキャプチャは隔離した盤面配置を用い、CORE上のRESETが再適用されないことも確認した。\
入力はGodotの実ウィンドウへInputEventを送り、OSの物理マウスによる最終確認とは区別する。\
既存の実機台帳の未確認を今回の観測で完了扱いにしていない。\
検証用Godotは通常BUILDへ戻して終了し、ユーザー側の既存Godot画面を操作していない。
