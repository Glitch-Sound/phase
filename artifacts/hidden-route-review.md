# 実移動中の経路線を非表示にする改修

## 変更範囲

ゲーム本体の変更はui/main.gdの実移動分岐から経路線を描く2行を除いたことだけである。\
計画、行動と対象の選択、最終確認には既存の線を残す。\
人とCPUの移動中は線を描かず、ユニットと左右のリング更新、0.20秒/セルと上限0.65秒、着地から技への連続性とBACK、Escを維持する。\
移動、戦闘計算と保存の部品は変更していない。

## 自動検査

- 既存の画面接続検査へ、実描画中に経路線分が要求されたかの観測を追加した。
- 計画、対象選択、最終確認とCPUの予告で線があり、人とCPUの移動中には線がないことを確認した。
- 旧実装では移動中の線が2項目で検出され、修正後は24項目すべて成功した。
- 計画中の線まで消す変異実装では4項目が失敗した。製品とは別の検証用複製で試した。
- headlessの既定の小さいウィンドウでは線の余白計算で経路が見えなくなるため、画面検査のサイズを基準の1920x1080へ明示した。
- 既存の移動部品23項目を含むnpm run checkが成功した。製品検査のコマンドは変更していない。
- バランス依存の勝敗と固定手数の期待値は追加していない。

## 実Godotの確認

macOS、Apple M4、Godot 4.7.2のCompatibility描画で、1152x648と1920x1080を確認した。\
実画面への拡縮後の入力、計画と最終確認の線、線のない連続移動、各歩のリング、CPUの予告と実行、HELP、BACKとEsc、RESTARTと移動での終局を186項目で検証し、失敗は0だった。

最初の実描画検査では戦闘開始直後の入力が届かない回があった。\
その作業専用の検証プロセスだけを終了し、開始後の実フォーカス確認と失敗時の安全な終了を検査側へ追加して再検証した。\
ゲーム側のフォーカス処理は変えていない。\
最小と標準の原寸画像を確認し、計画線と移動中の非表示を実ピクセルで区別できた。
