# 装備枠と戦闘数値の検証

## 変更

装備枠を400x44から224x28へ縮めた。\
有効な配分は正の整数5個の合計100で各値が最大96であるため、型番の数値部分は常に10桁の16進表記となる。\
突然変異は-M-と5文字の置換なので、GEARとARMSの最長識別名は23文字である。\
現在の15pxのMenlo系では208pxであり、左右8pxを残した。\
文字のbaseline、2つの枠の間隔、MOVEとスキル、CLASSとリングの位置は維持した。

時間軸の上にTURNを加え、battle.turnを最低2桁で表示する。\
TURN 01、TURN 99、TURN 100、TURN 1000のように3桁以上も全桁を保つ。\
これは各ユニットの行動完了ごとに進む既存カウンターであり、陣営全体のラウンド、実時間や待ち量ではない。

各状態のIとRへコロンを付け、各数値へ3文字の固定領域を確保した。\
例えばI:100% R: 83%となり、数値の桁が減っても%とRの位置は動かない。\
項目の間は等幅書体の1文字分の空白とし、従来の大きな隙間を詰めた。\
既存のINFとRESの色、字体と大きさを保つ。

## 値と範囲

| 入力と状態 | 表示 |
| --- | --- |
| 百分率0、9、83、100 | それぞれ2、2、1、0文字の左余白で3文字へ右寄せする |
| 0.49、0.5、99.5 | 0、1、100へ四捨五入し、固定幅を保つ |
| 有限値0から999 | 整数へ四捨五入して表示する |
| 負数、999を超える値、無限と非数値 | 数値領域だけを---にし、戦闘値を変更しない |
| 正のターン | 最低2桁で全桁を表示する |
| 0または負のターン | TURN --とする |

現在の戦闘式は最終補正率を10から200%の範囲へ制限する。\
0、一桁、999と不正値の画面は表示境界の明示的なfixtureであり、実戦でその値が発生した証拠ではない。\
表示の都合によるclampや戦闘式の変更は行っていない。

## 検査

- 表示の変更前にTURN、固定幅と装備余白の検査を書き、旧実装で失敗を確認した。
- time_axisは196項目、battle_labelsは114項目、side_informationは86項目で成功した。
- ターン非表示の旧期待値はユーザーの新指示に従い、TURNを必須とする表示集合と全体件数の検査へ更新した。他の削除済みの見出しは引き続き禁止する。
- 百分率の0、一桁、二桁、三桁、丸め境界と範囲外、無限と非数値、ターンの各桁と64bit整数最大値を、独立した完全一致の期待値で確認した。
- 最大ターンでも左情報の横幅内に収まり、HPと最初の節点に重ならないことを文字の実寸で確認した。
- GPU538項目が成功した。最小1152x648、基準1920x1080、拡大2560x1440と縦長1200x1600で、全ユニットのI文字上のホバーと選択、経路保持と取消を実入力で確認した。
- 最長の突然変異名、REVERSEと全3スキル、数値境界と長いTURNの明示的な描画fixtureも確認した。
- 可変幅、異常値のclamp、ターンの打切り、旧間隔、広すぎる枠とTURNなしの6変異は全て失敗し、構文エラーによる失敗ではなかった。
- npm run checkはheadless2476項目、既存の戦闘再生、4仕様とトレース検査に成功した。プロダクト検査コマンドの構成は変更していない。

Apple M4、Godot 4.7.2、Compatibilityで確認した。\
両陣営の10行動をGUIで進めたTURN11で味方2を選択し、前回と同じ場面を撮影した。\

同一場面では装備枠とI、R、TURNの領域内10586画素だけが変わり、対象外差分は0だった。\
盤面、リング、経路と予測、灰色の接続線、右の他の情報とメニューは同じ描画を維持した。

通常の1438x809埋め込みではTURN 01から02への更新、攻撃によるAのHP100から90への減少、2桁と3桁の補正率を観測した。\

最後にRESTARTでBUILDへ戻し、画面操作を終了した。

最小倍率では既存と同じ13pxと15pxの文字が縮小されるため、最終的な読みやすさはユーザーの通常の表示倍率でも確認する必要がある。\
全カスタム配色と独立全画面の手動比較、自然な一戦の完走は今回再実施していない。\
整数最大値は表示fixtureであり、実際にその回数まで戦闘を継続した耐久検証ではない。\
