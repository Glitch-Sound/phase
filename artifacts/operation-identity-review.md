# 作戦の識別と表示の確認

## 原因と修正

説明の行内紋章は作成時のユニット辞書を保持し、図は現在の編成を参照していた。改名時に既存説明も更新し、役割の参照は不変IDからBUILDの現在編成、戦闘の実ユニットへ解決する。同名と空欄の既存規約を維持し、表示名を勝敗や所属の照合に使わない。ユーザー名は戦闘へ表示せず、非表示のアクセシビリティ情報は更新する。

OPERATIONでは共通の装備プレビュー用タイトル位置が図のSTART AREASと同じ高さだった。この画面だけタイトル、図、図の注記、説明を縦に分け、説明の折返しと操作を残した。

## その他の表示

- SETTINGSの配色セクション上へ16px加え、見出し以下を同じ量で動かして内部の間隔を維持した。
- 戦闘右上に作戦名と一行の目的を置き、02の対象は実ユニットの紋章で示す。  CLASSとリング、装備の上部だけを調整し、MOVE、スキルと下部メニューを維持した。
- BUILDの編成ボタンをUNIT 1から3へ変更した。  スキルのSLOTは別の意味のため維持し、内部キーと保存形式は変更していない。

## 検証

- 修正前の既存検査で、改名4例、作戦タイトルと図の重なり2例、戦闘の作戦表示2例の失敗を確認した。
- 変更後のBUILD DIALOGSは91件、SIDE INFORMATIONは93件で失敗0となった。  Orion、日本語の澄、既存のUNIT 2と同名のVesper、空欄、対象外の改名を確認した。  各戦闘で対象の不変IDと勝敗条件が元と一致することを確かめた。
- Godot4.7.2、Apple M4、Compatibilityの実描画で62件、失敗0となった。  英日、1920x1080と1152x648、UNIT 2、3、1、02適用後のLineEditへの文字入力、BUILDの既存説明、再表示した図、実戦の一致を確認した。  両作戦の説明図と折返し、短い戦闘目的、確認ユニット切替と移動後のTURN02を確認した。
- 最終4画面はゲーム画面だけを実ピクセルで確認し、個人情報とデスクトップを含まない。  取得中に一部の描画が欠けた1枚は成果物から除外し、安定したフレームを再取得した。  戦闘画像は隔離したseed48、改名したUNIT 1が1マス移動してWAITしたTURN02である。
- npm run check、strict OpenSpec検証、トレースと差分検査を行い、バランスに依存する固定勝敗と手数の合否条件は追加していない。

## 限界と保護

GUI入力はGodotの実ウィンドウへInputEventを送り、OSの物理キー操作による最終確認と自然な一戦の終局までは未実施である。既存の実機台帳の未確認30件を完了扱いにしていない。検証用Godotは通常BUILDへ戻して終了し、既存のユーザー側実行は操作していない。セーブと設定は検証専用パスを使い、既存の保存、設定と旧画像、動画は保持する。
