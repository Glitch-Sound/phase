# 位置操作と防御スキルの検証記録

## 変更

SWAP、PUSH、GUARDとPANEL IGNOREを追加した。
既存9種のIDと順序、初期2種、共有3枠、通常移動と攻撃、回復の基礎式を維持する。
MOVE-1、PANEL SENSEとLAST STANDは追加していない。
新4品は戦利品の未開放候補へ加わり、取得後にBUILDで装備する。
旧保存を読み込むだけでは自動取得や自動装備しない。

| スキル | 実装した意味 |
| --- | --- |
| SWAP | 上下左右の生存味方1体との位置交換。全快でも使用でき、自分には使用できない |
| PUSH | 上下左右の生存敵1体を反対側の空きセルへ1マス押す。無傷、盤外と連鎖押しは不可。戦闘不能のセルは空き扱い |
| GUARD | 移動後に自分を選び、次のDAMAGEを1回だけ軽減する。初期残存倍率0.5。通常式の整数化後に掛けて切り捨てる |
| PANEL IGNORE | 装備した本人の特殊COREパネル効果だけを無視する。通常の装備回転と移動力は変えない |

GUARDの軽減率はgame/tuning.gdの調整値であり、50%は暫定値である。
次の攻撃が0ダメージでも消費し、予測では消費しない。
重ね掛けは不可、移動、回復、WAITと手番交代では残り、新しい戦闘で解除する。
戦闘中の防御を版1の保存へ加えない。

強制移動も到着先への通常1歩へ統一した。
SWAPの両者、PUSHの対象は自分のGEAR、ARMSを1歩分回転させ、到着先のCORE効果を自分の受動に従って適用する。
対象のnext_timeと移動数、HP、防御は変えず、行動者だけが通常どおり行動を終える。
交換は全員の位置を確定してから移動した全員のREACHを判定し、同時成立は敗北優先とする。
OCCUPYは従来の手番終了の判定を使う。

## 表示とCPU

対象範囲と無効な行動の禁止を維持し、有効対象へのホバーで移動先の既存角枠と変化後のリングを予測する。
左側は行動者、右側は対象の予測であり、右側に作用名とPREVIEWを明記する。
盤面とタイムラインの実ユニットは予測で動かさない。
新作用を回復の+0として描かず、SWAP、PUSH、GUARDの名前を使う。
防御は既存Lucide shieldと詳細のGUARD表示で示す。
新しい画像資産と権利条件の変更はない。
HELPの既存説明を残し、SKILLSから作用と強制移動、消費の説明を開く。

CPUは同じ対象条件とbattleの確定処理で候補を評価する。
GUARDの軽減を反撃危険へ反映し、PUSHでは移動後の敵位置から脅威を再計算する。
位置操作の補助評価は目標距離差と直ちに届く攻撃機会の差であり、既存の攻撃と回復の重みを変えない。
敵の初期装備は旧攻撃と回復のままとし、新種CPUは明示的な検証用構成で確認した。

## 自動検査

テストを先に追加し、新品の未登録、COREの無視とCPU予測、新作用の表示未対応を検出した。
初回REDはutility_skillsが22検査8失敗、utility_cpuが6検査2失敗、utility_uiが7検査6失敗だった。
既存カタログの完全一致も追加4品を検出して失敗し、今回の追加仕様に従う13品の完全一致へ更新した。
既存の範囲、基本ルールの期待値を弱めていない。

| 検査 | 結果 |
| --- | --- |
| utility_skills | 59検査、失敗0。進入、交換と押し先、予測と確定、防御、到達判定、収集と保存 |
| utility_cpu | 6検査、失敗0。新3行動の合法候補、非破壊と決定性、実行、受動予測の代表接続 |
| utility_ui | 9検査、失敗0。作用表示、予測接続、対象識別、防御、HELPとBUILD復帰 |
| utility_capture | 実GPUで41検査、失敗0。新3行動の代表クリック、各サイズのPUSHとHELP |
| npm run check | 全体成功。既存のモデル、UI、CPU、静的検査と仕様5件も成功 |
| 差分strictとstrictトレース | 成功。11要件と41シナリオの対応を確認 |

プロダクト検査scripts/check.shへ新しいheadlessの3スイートを接続した。
GPU検証は実画面の観測用であり、headlessの標準検査へ重複登録していない。
同じ受動を持つ交換対象、回復とWAIT中の防御保持の追加確認は、既に共通進入とDAMAGEだけの消費で成立していたため初回から成功した。
GPU検証の初回失敗は、手番自動追従前のホバー設定、CLOSEボタンの検索名、行動者の通常時刻更新まで効果予測へ含めた検証側の誤りだった。
検証の入力時点と比較対象を実際の操作契約へ合わせ、製品側を検証へ合わせて変えていない。

誤実装の検出では、占有した押し先を許可する、防御を消費しない、パネル無視を無効にする、到達判定を行動者だけにする4変更を一時的に適用した。
全て対応する検査が失敗し、その都度元のコードへ復元した。
結果はartifacts/runtime/utility-mutations.jsonにある。
勝敗、終了手数、固定戦術の回復量を合否とする検査は追加していない。

## 実Godotの操作

macOS、Godot 4.7.2、Compatibility、Apple M4の通常の埋め込み画面4442x2499で操作した。
本番ステージINTERFERENCE、パネルシード1、初期HPから、明示した機能確認用の編成でCPUと11行動を進めた。
1はSWAP、GUARD、PANEL IGNORE、2はPUSH、DAMAGE DIAGONAL 2、HEALを装備し、取得はメモリだけで用意した。
ユーザーの構成を読み込んだり保存したりしていない。

- 1が反時計回りパネルへ移動してもCORE0を維持し、GEARとARMSは通常回転した。
- SWAPの予測、Escによる対象取消と再選択、実際の1と2の交換を確認した。
- 交換された2だけには到着パネルのCORE効果が適用された。
- 2のPUSH予測と確定でAが(6,4)から(6,3)へ動き、HPを減らさず装備が回転した。
- CPUは移動と攻撃を続け、2が負傷した実際の途中状態でGUARDを予測して実行した。
- 防御は他ユニットの手番と次の自分の移動、WAITをまたいで残った。
- Aの攻撃は1へ14、続くBの攻撃は28となり、最初の攻撃で盾が消えた。

最後の数値はこの実戦の観測であり、固定した合否ではない。
TURN12の時点で1はHP58、防御なし、2は戦闘不能、敵2体は生存していた。
履歴と全ユニットはartifacts/runtime/utility-native-play.jsonに保存した。
攻撃を持たない支援役の1を使った機能確認であり、通常編成の決着や新4品の戦力バランスを評価した一戦とは扱わない。
新しい位置操作は確認しやすかったが、支援だけで埋めた3枠は単独で攻撃できないため、装備選択の対価が明確だった。
この観測を理由に攻撃力や回復量を再調整していない。

別の実GPU検証では1152x648、1920x1080、2560x1440、1200x1600で代表対象のクリックとHELPの文字領域、閉じる操作を確認した。
最小サイズの盤面、予測ラベルとHELPの実ピクセルを確認し、対応する内容の欠落とクリッピングは見られなかった。
リサイズ時の手番自動追従と対象ホバーの優先も検証用の入力時点に含めた。
通常のGodotはBUILDへ戻して画面操作を終了した。

## OpenSpecのverify

Using change: add-position-and-defense-skills。
別変更を対象にする場合はopenspec-verify-changeへ変更名を指定する。

| 観点 | 確認結果 |
| --- | --- |
| 完全性 | タスク9/9。変更8要件と追加3要件、全41シナリオの実装と検証経路を確認 |
| 正しさ | battleの合法性と原子性、phase_mathの計算、catalogとcollectionの互換、UIとCPUの接続を確認。手動対象の5シナリオには開発側の観測と利用者の未確認を明記 |
| 整合性 | D-01からD-04に対応。共通進入、複製予測と確定、戦闘中だけの防御、既存3枠を維持。新しい外部依存なし |
| 指摘 | CRITICAL 0、WARNING 0、SUGGESTION 0 |

期待値は対象の関数で作らず、モデルの角度は独立した具体値、防御率は調整定義を参照する数式で確認した。
上位のクリック検証は同じ効果式を再定義せず、共有予測と確定への接続を確認する。
対象41シナリオのうち手動確認の最終承認を自動検査へ置き換えていない。
仕様同期とアーカイブは利用者の最終承認を意味しない。
2026-11-18-add-position-and-defense-skillsへアーカイブした。
CLIのarchiveは標準英語見出しWhy、What Changesがないという非阻止の通知を出したが、ears-bddの日本語テンプレートに従う成果物であり、差分strictとトレースは同期前に成功していた。
同期後、移動前の追加IDと正式仕様が一時的に重複する段階でstrictトレースを再実行すると3件を検出した。
差分と正本の全11ブロックの完全一致を確認してからアーカイブし、最終の全体検査では重複を解消して成功した。

## 継続確認とデータ保護

全ステージの新スキル編成による完走、自然な戦利品で全4品を取得する過程、新スキル同士の長期的な連携とCPUの強さ、全カスタム配色と全サイズの組み合わせは未確認である。
CPUは1手先の評価であり、多手の読み合いを保証しない。
新GUARDの軽減率と位置操作の強さは利用者の実プレイで継続調整する。
敵の初期構成へ新種を自動装備していないため、通常の敵が新種を使用する状態を自然に遭遇済みとは扱わない。

全体の実機確認表は15件の未確認を維持した。
検証前後で実phase-save.jsonのSHA-256とmtime_nsが一致し、ui-settings.jsonは存在しないままだった。
追加アプリを導入せず、実セーブと設定の保存、GitHubへのpushと公開は行っていない。
