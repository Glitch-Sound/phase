# COREパネルの検証

## 合意内容とデータ

特殊パネルをRESET、CLOCKWISE、COUNTERCLOCKWISEへ変更した。\
旧SHIFT、LOCK、REVERSEのパネル効果は本番にも検査用fixtureにも残していない。\
クラス名REVERSEのセクター順は別の機能であり、変更していない。

現行COREのSPDは既存の5値にあり、開始角は位相計算で0度に固定されていた。\
別の開始角を編集する機能や、保存された開始角は存在しない。\
この既存値と合意内容の間に未解決のデータ矛盾はなかった。\
戦闘生成時にCOREの現在角と開始基準を0度で保持し、RESETは開始基準を参照する。\
これらは戦闘中の値であり、保存する7項目のビルドへ加えていない。

| セル | CORE | GEAR | ARMS |
| --- | --- | --- | --- |
| NORMAL | 現在角を保持 | 自身のSPD x 1.5度を反時計回り | 自身のSPD x 1.5度を時計回り |
| RESET | そのユニットの戦闘開始角へ戻す | 通常と同じ | 通常と同じ |
| CLOCKWISE | COREのSPD x 1.5度を時計回り | 通常と同じ | 通常と同じ |
| COUNTERCLOCKWISE | COREのSPD x 1.5度を反時計回り | 通常と同じ | 通常と同じ |

経路順に操作し、角度は360度で循環する。\
開始CORE40度、開始基準10度、CORE:SPD20の検査では、時計回りの後のリセットは10度、リセットの後の時計回りは40度となった。\
予測は実状態の複製で計算し、確定後は次の手番へ角度を保持する。\
再戦では全員の開始基準と現在角を再生成する。\
能力配分、HP、移動力と手番の式、攻撃と回復と抵抗の式、勝敗条件は変更していない。\
角度の変化による同期と特異点の変化は意図した結果である。

## 表示と配置

RESETはLucideのundo-2による戻す形、CLOCKWISEはrotate-cw、COUNTERCLOCKWISEは既存rotate-ccwの円形矢印で区別する。\
新規2点は既存と同じ公式コミット55782beff3a0133df79c417eb68f96e8f19e2404から取得し、NOTICEへ追記した。\
ISCとFeather由来部分のMITの同梱LICENSEを保持した。\
盤面には文字の略号を置かず、ホバーとHELPで対象CORE、SPDと戦闘開始角を説明する。\
HELPは全セルで通常のGEARとARMS回転があることも明記した。

共通の領域計算へCORE角を反映したため、盤面、時間軸、右詳細、予測とBUILDのリングは同じデータを使う。\
円形予測の署名へCORE角を追加し、COREだけが変化した場合も一度だけ再生成する。\
3リングの確定角を履歴に記録し、モデル再生の停滞検出にもCORE角を含めた。

配置率、端数、除外、分散とシードは前回の方式を維持した。\
全100セルを母数に20枚、初期位置と目標を除外し、4区画へ分散して隣接を許可する。\
3種類は6、7、7枚となり、同じステージとシードで再現できる。\
512シードでは96候補すべてが75～135回選ばれ、隣接観測数2984と512種類の配置を確認した。\
1000pxの盤面、周囲の配置、色設定、メニューと指定外の意匠を変更していない。

## 検査

npm run checkが成功し、headless2403項目、モデル再生、4仕様とトレース検査が通った。\
プロダクト検査scripts/check.shへcore_panelsとcore_panel_uiを追加した。\
npm testだけでもOpenSpecと分離したプロダクト検査を実行できる。

- 新規の位相と戦闘37項目: 開始基準、4種類、能力値とHPと時刻の不変、独立したSPD、1と96の境界、角度循環、順序、複数踏み、同期、特異点、クラス順、共通描画、予測、取消、確定、BACK、持続、敵、再戦と保存形式を確認した。
- 新規UI9項目: COREだけの変化によるキャッシュ更新、4箇所のリングへの接続、経路予測、EscとHELPを確認した。
- パネルUI100項目: 3種類の全セルと効果の集合、SVG、役割色、意味、HELP、シードと4サイズのクリックを確認した。
- 配置539項目: 数量、候補不足、分布と乱数独立を新しい種類で確認した。
- 既存検査: 経路、回復上限、目標の優先、描画、モーダル、色と保存境界の検査を維持した。

旧実装で部品24件、配置4件、新しいUI種類1件、COREだけのキャッシュ更新などの失敗を確認してから実装した。\
3リング履歴の検査も追加前に1件失敗した。\
RESETを0度に決め打ちする、COREの代わりにGEARのSPDを使う、逆回転の符号を誤る、RESETでGEARを止める、経路順を逆にする、COREを領域へ反映しない、開始基準を毎回更新する、キャッシュ署名からCOREを外す、時計回りアイコンを逆向きにする9種類の変異を一つずつ加えた。\
すべて検出し、元のコードへ復元した。\
期待値を対象の関数で生成せず、テストを無効化していない。

旧効果に依存した角度の期待値は、新しい契約の独立計算へ実装前に変更した。\
比較攻撃の敵HPは新ルールで90となるため、旧89から変更した。\
他の操作と表示に関する期待値を緩めていない。

## プレイの観測と限界

本番の生成盤面を両陣営の経路と攻撃と回復の評価方策で再生し、シード0、1、7の全滅戦は29、27、23手でVICTORYとなった。\
両陣営の攻撃があり、両陣営の回復を含むのはシード0で、全シードでWAITは0回だった。\
生成4ステージの初手570経路でも即時勝利と報酬ループは発生しなかった。

到達戦では旧方策は3シードとも12手で敗北した。\
取得可能なMOVEを空き枠へ入れ、ステータスを変更せず、初動を(5,6)から(6,5)の迎撃へ変えると、3シードともBREACHとANCHORで19手の勝利となった。\
固定配置の検査でも同じ迎撃が勝利した。\
勝利を求める既存の検査条件は維持し、戦闘式や生成シードを勝利へ合わせていない。

相互回復を観測する固定配置の再生は評価1.8で64手、初期役割の再生は1.4で42手となり、両陣営の攻撃と回復を含んで決着した。\
旧評価0.88では回復せず23手の敗北、高い評価10では161手で未決着となった。\
回復を優先しすぎる方策で停滞する課題は残る。\
操作と結果はartifacts/panel-play.json、contested-play.json、playthrough.jsonへ更新し、以前の記録はGit履歴に保持する。

これらはモデルの再生であり、人間が自然に一戦を完走した実プレイとは区別する。\
通常起動では上記5手程度の操作を確認し、全シードの最適攻略、全配色、縦長の手動操作、独立全画面と長時間性能の網羅は行っていない。\
最終的な分かりやすさとバランスはユーザー確認の対象として残す。
