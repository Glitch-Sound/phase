# 先頭手番行の囲い削除

## 変更範囲

基準はc6b9f5aである。\
利用者の明確化に従い、先頭手番行に残していた枠と背景も除去した。\
製品コードはui/main.gdの6行の削除だけであり、専用分岐、説明コメントと矩形描画を除去した。\
先頭位置、順序番号、既存の文字色とリング、係数、入力領域を維持し、新しい囲いや装飾を加えていない。\
前回除去したTURNを含む10表示と他の囲い、盤面、メニュー、他画面、配置、機能、配色とルールを変更していない。

## 検査

既存のGPU検査を231件から255件へ拡張し、先頭行も背景検査の対象にした。\
先頭行の維持という旧期待値は、今回の明示的な削除指示に合わせて変更した。\
比較元は前回のTURN2画像とし、変更を許す範囲を先頭行の矩形と元の1ピクセル枠の広がりだけに狭めた。\
修正前は255件中25件が失敗し、修正後は255件すべてが成功した。

基準1920x1080、1440x810、最小1152x648の開始、無効移動、無効対象と、1440の一致と不一致、TURN2の計12画像を実Godotで描画した。\
同じTURN2、手番2、経路(4,6)から(5,6)、敵AのHP89、INF130.6%、RES94.5%で比較した。\
変更は先頭行の19,989画素だけで、先頭行の範囲外、盤面、システムメニューの画素差はいずれも0だった。\
背景の変更による文字と線のアンチエイリアス部分の差も先頭行の中だけに収まる。

npm run checkは1,354件のheadless検査、戦闘再生、4仕様とトレースを含め成功した。\
114件の文字表示検査と既存の入力、状態とフォーカスの検査を維持した。\
プロダクト検査の入口と規則は変更せず、独立したGPU検査の対象を拡張した。

```sh
godot --path . --script tests/battle_containers_capture.gd
```

制限されたheadless実行では既知のmacOS証明書取得警告だけが出た。\
検査を弱めたり、実装に合わせて許容差を広げたりしていない。

## 実Godotの操作

通常の1438x809埋め込み表示で修正後のゲームを起動した。

1. BUILDからSTARTし、全手番行の囲いがなく、先頭の位置、01の番号、既存の文字色とリングで手番1を識別できることを確認した。
2. 通常行のAを選び、次に先頭行をクリックして右詳細が1へ戻ることを確認した。
3. (4,4)から(5,4)へ経路を選び、ダブルクリックからACTIONへ進み、TabとEnterで攻撃を選択した。
4. Aを攻撃し、-11、敵HP合計189、先頭行のユニット2への更新を確認した。先頭行の囲いは復活しなかった。
5. (4,6)から(5,6)へ経路を選び、AのHP89/100と手番2のINF130.6%、RES94.5%を同時に確認した。
6. 更新後の先頭行をクリックし、右詳細が2へ切り替わり、経路と予測を維持することを確認した。
7. RESTARTでBUILDへ戻し、画面操作を終了した。

実ユーザーセーブと設定の保存、上書き、pushと公開は行っていない。
