# 公開候補の個人情報整理

## 対象

8a2230bの後に、利用者の依頼に従って現行ファイルの端末固有パスを整理した。\
第三者の正当な著作権表示、ゲームの動作、実セーブと設定は変更しない。\
追加の本人承認により、READMEに列挙した汎用コード2ファイルだけをMITとする。\
個人情報の整理を、自作全体への許諾には広げない。

## 現行ファイル

22ファイルの26箇所を、プロジェクトのルートからの相対パスまたはルートの説明へ置き換えた。\
対象はopenspec/product.md、artifactsの過去の検証文書、画像検証用のJSONである。\
ゲームとテストのソース、機能上の保存先、原音、フォント、画像のバイナリは変更していない。\
要求事項の参照は同階層にある別フォルダの相対パスとし、別フォルダの内容をコピーへ追加していない。

調査開始時の追跡ファイルには、元履歴の個人メールと一致する文字列はなかった。\
GodotのCOPYRIGHT.txtには第三者の連絡先が3箇所あり、原文の一部として残す。\
これらを利用者のメールと混同して削除しない。

## 元履歴と公開候補の分離

調査開始時の113コミットには、それぞれauthorとcommitterのメール欄がある。\
113件ずつ、合計226欄に同じ個人メールが記録されている。\
コミット本文には端末固有のホームパスを検出しなかったが、履歴中のファイルには過去の絶対パスがある。\
実値はこの報告に転記しない。

元のコミットをamend、reset、filter等で書き換えず、整理した現在版を通常の追加コミットで保持する。\
今回の新規コミットのメールだけは、そのコマンド内でsource@phase.invalidへ差し替え、既存の著者名を保持する。\
この中立値はGitHubアカウントやnoreply IDを推測したものではない。\
グローバル設定と既存のメール設定は変更しない。

公開候補は、管理対象のファイルだけをartifacts/runtime/public-source-20261126/phaseへコピーし、別のGitリポジトリとして作る。\
元の.git、refs、reflog、remote、キャッシュ、実データ、無視される生成物を持ち込まず、今回の1件の初回コミットだけを持つ。\
原本のGitオブジェクトへのalternatesやworktreeの参照も持たせない。\
コピーにも同じ中立メールを使い、第三者原文を維持し、個人メールと端末固有パスがないことを再検査する。

~~~mermaid
flowchart LR
  A["元リポジトリの113コミット"] --> B["個人パス整理の追加コミット"]
  B --> C["管理対象ファイルだけをコピー"]
  C --> D["公開候補の初回スナップショット"]
  A --> E["元履歴はローカルに保持"]
~~~

公開候補から過去のGit履歴、blame、タグ、以前のコミットを復元することはできない。\
過去SHAを参照する研究用スクリプトも、そのコピーだけでは旧版を取得できない。\
過去のレビュー文書に残るSHAは説明として保持するが、コミットのオブジェクトは含めない。\
OpenSpecの文章アーカイブと現行ソースは含める。\
元リポジトリからそのままpushすると過去の個人情報も含むため、今回の公開候補とは区別する。

## 確認

元と公開候補の両方で、npm run checkとgit diff --checkを実行する。\
公開候補では、管理対象のバイト列と元の整理後の内容、第三者原文と素材のハッシュを照合する。\
Gitの全コミットのauthor、committer、本文、全blobも検査し、個人メールと端末固有ホームパスの非検出を確かめる。\
検査が再生成する2つの追跡JSONは元に戻し、過去の検証資料へ差分を残さない。

元リポジトリの過去113コミットは、整理後も同じオブジェクトとして取得できることを確認する。\
通常の追加コミット以外のrefは変更せず、元の実セーブと設定17ファイルのハッシュも照合する。\
このローカルコピーにはremoteが登録されておらず、今回も接続先を追加しない。\
既に外部へ公開されたリポジトリやコピーの有無は、この確認だけでは断定できない。

既知の文字列とパスの検査は、全画像の画素、未知の個人情報、将来作るコミットのメールまでを保証しない。\
今後GitHubの本人確認済みnoreplyを使う場合も、本人の設定画面で確かめた値を使う。\
push、外部公開、履歴改変、OSやグローバルGit設定の変更は行わない。
