# 合成輪郭だけの強調

## 結果

基準は255fd51で、開始時の作業ツリーは空であった。
CORE、GEARとARMSの個別3輪郭の描画データと座標、周期とSPDの関係を変えず、合成結果だけを調整した。
局所一致が強い区間では、同じ3装備の基礎速度に対して1.8倍の時計を使い、係数2.4のtanhで有界に増幅した波へ滑らかにつなぐ。
増幅係数は変位の一律2.4倍を意味せず、小さい合成を読みやすくしながら最大包絡を保つための値である。
強調開始の局所一致度は0.35であり、不一致と2者一致だけの場面の動きは旧版と同じである。
強い領域との境界では従来の色補間に従って強調も滑らかにつなぐ。

角度ごとに時間の速度を変えず、共通の速い時計の波を固定した角度の重みで混ぜる。
色と一致領域の角度は時間で移動しない。
合成結果の不一致の透明度は0.12から0.07へ下げ、強一致の透明度1とグラデーションのRGBは維持した。
個別3輪郭の色と透明度、塗りなし、他UI、戦闘式と保存は変えていない。

## 検査

| 検査 | 結果 |
| --- | --- |
| 先行失敗 | 旧合成の期待値をユーザー指定の新しい振る舞いへ更新。旧実装で強一致の速度と有界増幅の1項目が失敗 |
| 部品 | phase_previewの169項目成功。新しい合成、個別3輪郭、不一致と2者一致、周期、色と包絡、状態と縮尺入力を確認 |
| 全体 | npm run check成功。既定の戦闘、CPU、移動、保存とOpenSpecの検査を維持 |
| 実描画 | Godot 4.7.2、Compatibility、Apple M4、本番main.tscnから2360項目、失敗0 |
| 旧新の不変部分 | 個別3輪郭の全データが255fd51と完全一致。強調しない全角度の動く座標も旧版と完全一致 |
| サイズ | 1920x1080と1152x648の全景でリングとHP、見出し、タイムラインと通知の余白を確認 |
| 長時間 | 表示時刻3600秒と86400秒でも角度方向のねじれが蓄積せず、最大隣接距離は1.755px未満 |

新しい固定勝敗とダメージ、手数の期待値は追加していない。
既存の合成の1項目を新しい計算へ置き換え、弱一致を保つ2つの分岐確認だけを加えた。
期待値は検査対象の関数を呼ばず、独立した正弦波の計算と調整定数から求めた。
誤ったままの従来合成では失敗し、個別まで速める変更と弱一致への一律強調を区別できる。

## 動きの観測

前回と同じseed 128の試合を7手合法に進めたTURN 08のユニットを使った。
弱一致は移動前、強一致は合法な2マス経路の着地点予測であり、確定した位置とHP、手番は動かしていない。
30秒を1/30秒間隔で調べた観測は次のとおりである。
数値は論理pxであり、ゲームバランスの合否条件ではない。

| 観測 | 旧版 | 新版 |
| --- | --- | --- |
| 強い場面の合成半径 | 76.109から81.497 | 73.134から84.478 |
| 弱い場面の合成半径 | 77.045から80.567 | 完全一致 |
| 強い場面の3者一致区間の変位RMS | 基準 | 約2.43倍 |
| 強い場面の最大フレーム間移動 | 前回観測0.151未満 | 0.815未満 |

強い場面でも円全体を強調せず、重なる赤い領域などが大きく速く動く。
半径の安全包絡14pxは拡張しておらず、理論上も線の半幅を含めて内側半径62.9px以上、外側94.7px以内である。
基準半径60pxのリングと見出しを避け、塗りと明滅のレイヤーは追加していない。
性能の別GPU比較と厳密なフレーム時間の測定は未実施である。

## OpenSpecのverify

変更はboost-result-contour、設計判断はD-01とD-02である。
1つのMODIFIED要件と6シナリオを、5つの自動検査の対応と1つの開発時の実描画へ対応づけた。
実施した範囲でCRITICAL、WARNINGとSUGGESTIONの指摘はない。
5タスクの完了と差分のstrict検査、同期前のstrict台帳を確認した。
アーカイブはopenspec/changes/archive/2026-11-20-boost-result-contourであり、正式のREQ-033だけを同期した。
既存の題名とPurpose、他の15要件は変更していない。
利用者の最終的な見た目の判断、物理入力、スマートフォンと動画プレイヤーでの操作、別OSとGPUは未確認として分離した。
これらを合格扱いせず、manual-checks.mdは未確認を維持する。
