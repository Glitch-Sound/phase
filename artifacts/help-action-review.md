# HELPとACTIONのレビュー修正

## 修正

既存のREQ-020-S01とNREQ-002-S01に沿った不具合修正として直接変更した。
戦闘式とゲーム条件は変更していない。

HELPの誤説明を、次の3行へ修正した。

~~~text
−はダメージ、＋は回復。
INFは攻撃と回復、RESは抵抗。
SAVE / LOADは明示操作。以前の保存は退避する。
~~~

配色設定のINFとRESからも符号を除き、回復がRES依存と誤解させる組み合わせをなくした。
要求書のINFが攻撃と回復を決め、RESが被ダメージを軽減する定義と既存の数式を確認した。

ACTIONだけは全画面の暗幕を透明にし、不透明な黒い操作パネルをアクセント枠で区別した。
配色設定で許容した境界付近の色を、暗幕によって再び低コントラストにしないためである。
値と理由はui/palette.gdのACTION_SCRIM_ALPHAに集約した。
BUILD、RESULT、HELP、SETTINGSの暗幕、入力遮断、モーダル内のフォーカス循環を維持した。

## 回帰テスト

- HELP本文を完全一致で検査し、旧説明で失敗することを確認した。
- 設定のINFとRESを完全一致で検査し、旧符号付きラベルで失敗することを確認した。
- ACTIONの暗幕を合成した文字と背景の相対輝度比を独立に計算し、旧0.82では必要な情報が読めないことを検出した。
- 操作パネル自体の文字のコントラストと、他の4画面が個別の暗幕を保つことを検査した。
- 既存のTab、Shift+Tab、無効なボタンの除外、フォーカス復帰の検査も成功した。

失敗ログはhelp-terms-red.txtとaction-context-red.txtにある。
修正後のnpm run checkは成功し、モデル536、UI接続12、既存回帰52、拡縮61、新UI135 checksで失敗0だった。
全戦闘と対抗プレイの再生、OpenSpecの正式仕様4件の厳密検査、トレース検査も成功した。

## 実画面

macOS、Godot 4.7.2、Retina倍率2.0、埋め込み1438x809で確認した。

- 修正後のHELPの3行を読め、CLOSEに重ならなかった。
- 実際に2歩移動してACTIONを開き、右のHP100/100、スキル、下のINF79.0%、RES103.4%、4波形を同時に読めた。
- 操作パネルの境界とWAIT、DAMAGE、無効なHEALを区別できた。
- TabとShift+Tabで有効なACTIONボタンだけを循環し、背後のHP付近をクリックしても状態は変わらなかった。
- WAITを実行してRESTARTを押し、BUILDへ戻ったことを確認して操作を終了した。

独立検証用に起動したGodotは今回のログ引数でPIDを特定して終了した。
レビュー側のエディターは終了していない。
既存セーブのSAVE/LOAD、push、公開は行っていない。
