# 設定色と所有紋章の統一

## 結果

基準は881b2ebであり、開始時の作業ツリーは空であった。
残HPバーと残HP円弧、アセンブリ紋章と所有紋章を同じ不透明の設定RGBへ統一した。
明度と彩度を変えるHP専用の処理と、その調整値を削除した。
バーの背景と減少部分、回復増分の一時反応と攻撃回復の演出は維持した。
既定のPEARLとRED、7色の選択と保存、ユニット紋章とアセンブリ紋章の生成規則を変更していない。

自軍だけの同心円マークを、既存の描画部品が生成する実際のアセンブリ紋章へ置き換えた。
所有判定と中心のオフセット(-38,38)は維持し、半径は形を読めるように4から6へ調整した。
専用の透明度と内円、線幅の調整値を削除し、所属紋章と同じ色とアンチエイリアスを使う。
敵には表示せず、将来の視点反転でも陣営と不変IDで判定する。

左上の数値は共通の右端360へ寄せ、最も長い文字幅と16pxの余白を確保した同幅のバーを使う。
紋章とバーの間隔12px、縦中心、文字とバー左端を維持する。
主画像のバー幅は従来の130pxから155pxへ拡大した。
桁が増える場合だけ数値の領域を増やし、共通右端とバー幅の一致を保つ。
HPの切り上げと内部HP、バーと円弧の比率、戦闘値と手番、保存値は変更していない。

ケース数を増やさず、既存の期待値を同じ設定RGBAと実際の紋章、共通右端へ置き換えた。

全色の取得規約は部品に集約し、画面ではその接続を代表例で確認する。
既存の図形と所有、保存、切り上げの基本規則は変更しないため最初から成功した。
新しいバランス固定値と検査コマンドは追加していない。

## Godot描画

Godot 4.7.2、Compatibility、Apple M4、本番main.tscnを使い、OS入力なしで隔離した状態を描画した。
最終スクリプトは168項目で失敗とSCRIPT ERRORがない。

| 確認範囲 | 観測 |
| --- | --- |
| サイズ | 1920x1080、1152x648 |
| バーの画素 | 内部の実画素がPEARL c9d2dcとRED ed8b8bに完全一致 |
| バーと数値 | 通常の幅155px、数値右端は両行360px、紋章とバーの間隔12px |
| 大きい桁 | 表示境界用の33178 / 33178と471 / 563で、バー幅114pxを共用し、最小でも重ならず盤面へはみ出さない |
| 所有 | 両視点と同色ミラーで自軍3体だけへ元の所属紋章を表示 |
| 隣接と盤端 | 角と隣接の描画用配置でも紋章が中央のリングとフォーカスを避け、盤外へ切れない |
| 右側 | CLASSとの縦中心差0pxと余白12px、選択した所属への追従を維持 |
| 比率 | 実数のHPと最大HPから得たバーと円弧の比率を維持 |

大きい桁と角の配置は描画境界のfixtureであり、自然な戦闘の場面として扱わない。
主画像は前回と同じseed 128、合法な6手を経たTURN 07で、6体が生存している。
PLAYERはAXISとPEARL、ENEMYはMONOLITHとREDであり、名前は隔離データだけへ設定した。
右詳細は味方のCLASS VIRSLである。
攻撃と回復、移動の新しい自然な一戦と物理入力、別のOSとGPUは今回未確認であり、関連する基本規則は全体の自動検査で確認した。
