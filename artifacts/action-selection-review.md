# 行動の最終選択と表示境界

## 変更

戦闘の最終CONFIRM画面だけを取り除いた。\
必要な対象がある行動は有効な対象の選択、WAITとGUARDのように対象の追加選択が不要な行動はその行動ボタンで一度だけ受け付ける。\
移動なしでは従来どおりWAITだけを選べ、予測の経路を実行せず待機する。\
対象をまだ選んでいない間のBACKとEsc、経路と位相の予測は維持する。

ACTIONのボタンは0.12秒の保護時間と、マウス左と確定キーの押下解除を経てから本来の可否へ戻す。\
背後のHUDのフォーカスも解除する。\
保護中の入力を後で再生せず、無効な対象と非活性の行動を確定しない。

最終選択では表示だけを閉じて実行待ちとし、ダイアログの消えた描画を確認した次の処理で原本の移動を一度確定する。\
その後は従来の距離と上限、雲フェード、各歩のリングとSE、着地後の攻撃の一拍、行動と結果へ進む。\
移動がないWAITはその表示境界の後で次手へ進む。\
実行待ちの重複入力を拒否し、補助画面とフォーカス喪失では止め、戻った時も消去後の新しい描画を待ち、再戦とBUILDでは破棄する。\
CPUの判断と表示、戦闘式、他の確認画面は変えていない。

## 検証

旧実装で新しい保護とCONFIRM廃止、表示境界の3検査が失敗することを確認した。\
補助画面の復帰と旧HUDフォーカスも旧状態で失敗することを確認した。\
修正後の行動UIは53項目、移動UIは32項目、SFXは76項目すべて成功した。\
既存のフォーカスとスキルの可否の期待値は維持し、ACTION保護の解除後へ検査の入口だけを接続した。\
npm run checkと差分の検査に成功し、新しい固定ダメージ、勝敗や終了手数の期待値は加えていない。

Godot 4.7.2、Compatibility、1920x1080と1152x648で32項目の実描画検証に成功した。\
Godotの入力イベントと盤面の検証入口を使い、連打、0.4秒のキーとマウスの長押し、キーリピート、取消と再表示、無効対象、移動ありとなしのWAIT、対象選択と自分を対象とする行動、再戦を確認した。\
対象を選んだ直後は原本と履歴を変更せず、ダイアログなしの描画フレーム680の後、681で最初の移動表示になった。\
最後は通常BUILDへ戻り、検証用Godotを終了した。

## 限界

独立した動画プレイヤーによるAVI再生と音の聴感は未確認で、全フレームの復号と実描画、メタデータの確認と区別する。\
録画専用ハーネスを画面を保持したまま終了した際にObjectDBと残存リソースの解放警告が出るが、既定の全体検査と通常のGUI検証には同じ警告はない。\
自然な一戦の完走と勝率、全入力装置の網羅は今回行っていない。\
既存の実機確認台帳30件は利用者の最終確認として未確認を保つ。\
実保存と設定、本人提供の音源と過去の成果物は変更せず、公開とpushは行っていない。
