# 右情報の並びと装備枠の検証

## 変更

右情報をCLASS、リング状態、GEAR、ARMS、MOVE、スキルの順へ並べた。\
CLASSとリングの位置は維持し、装備をリングの直下へまとめ、MOVEとスキルを下へ移した。\
GEARとARMSは各々背景なしの控えめな細線で囲い、完全な識別名と突然変異を1行で表示する。

装備枠は閉じた線の描画だけであり、ControlやButton、ホバー状態、フォーカスとクリック処理を追加していない。\
既存のボタンの背景、文字とフォーカス表現と区別する。\
値はgame/tuning.gdに集約し、小さい倍率でも輪郭が消えないよう最小物理線幅を保つ。\
右情報以外の配置、盤面とメニュー、細いHP、灰色の時間軸接続、選択と経路予測、色設定と戦闘式は維持した。

## 自動検査

- 承認された並びへ表示集合の期待値を先に変更し、装備枠と余白の検査を追加した。旧実装は9項目で失敗し、構文エラーはなかった。
- 変更後のside_informationは84項目で成功した。STANDARDとREVERSE、全スターター、長い突然変異識別名、0と1と3スキルを含む。
- 名前を枠内へ収めること、リング、装備、MOVEとスキルの上下関係、文字と枠、盤面とメニューの非交差を確認した。
- GPU463項目が成功した。1152x648、1920x1080、2560x1440と縦長1200x1600で、四辺の細い輪郭と塗りのない内部、選択と経路保持、枠のクリックとホバーの非操作性を確認した。
- Tabで移動するのは既存の4つのシステムボタンだけで、装備枠が新しい移動先にならないことを実入力で確認した。
- GPUの輪郭検査は最初の実行から成功した。実装済みのGodotのアンチエイリアス付き線描画がそのまま拡縮に対応したためであり、輪郭なしと背景塗りの誤実装も別途作って検出を確認した。
- 順序の逆転、枠を狭くする変更、MOVEを元の位置へ戻す変更、輪郭なし、背景塗りの5変異は全て検査が失敗した。失敗数は7、2、3、64、48であり、構文エラーによる失敗ではない。
- npm run checkはheadless2447項目、既存の戦闘再生、4仕様とトレース検査に成功した。検査コマンドの構成は変更していない。

## 実描画と操作

Apple M4、Godot 4.7.2、Compatibilityの実GPUで確認した。\
両陣営の10行動をGUIで進めたTURN11で味方2を選択し、前回と同じ場面を撮影した。\
移動、攻撃と回復を含み、HPは80、59、60、38である。\
この場面のユニットの位置、HPと位相は撮影用に直接変更していない。\
最長名、REVERSEと3スキルの別画像は、その後に設定した表示fixtureであり、実進行場面と区別する。

比較画像では指定した右領域の16948画素だけが変わり、対象外差分は0だった。\
CLASSとリング、盤面、時間軸、予測とシステムメニューは同じ描画を維持した。

通常の1438x809埋め込みでも両クラス、2種類の装備識別名、選択、未確定経路を保持した枠内のクリック、ACTION、攻撃と手番更新、HELPの開閉を確認した。\
攻撃でAのHPが100から90へ減り、手番2への更新で装備名が141E0F140Fへ切り替わることを観測した。\
最後にRESTARTでBUILDへ戻し、画面操作を終了した。\
クラス確認はメモリ上の変更だけであり、保存していない。

## 限界

最小サイズでは既存と同じ文字サイズが縮小されるため、長い識別名の最終的な読みやすさはユーザーの表示倍率でも確認する必要がある。\
全カスタム配色と独立全画面の手動比較、自然な一戦の完走は今回再実施していない。\
今回の表示変更に関する不具合は検出していない。
