# 攻撃と回復の光の弧の検証

## 変更

赤系の攻撃と緑系の回復を、リング外縁を結ぶ短い曲線の光で示す。
光の到達時に既存のactを一度だけ実行し、HPと符号付き数値、撃破へつなぐ。
攻撃は締まった3本の切れ目、回復は外へほどける2つの開いた円弧で区別する。
色は既存のINFとRES設定を使い、設定と保存形式を変更しない。
強いINFは線幅と局所反応を最大25%だけ強める。

飛行は基準0.18秒、距離に応じて最大0.24秒とする。
反応は攻撃0.16秒、回復0.24秒とする。
主線は1.8論理px、最小1.25物理px、広い弱い縁取りだけを重ねる。
近接でも読めるように曲線を膨らませ、盤面と全生存ユニットのリング外形で切り取る。
大きな爆発、画面全体の閃光、太いレーザーは追加しない。

確定前の予定、移動と一拍、白い経路線の非表示、雲の透過と再表示、盤上と左右のリング更新を維持する。
WAIT、GUARD、SWAPとPUSHへ光の待ち時間を追加しない。
退出と再戦は光と以前の効果数値を破棄する。
自己回復と通常の0歩攻撃は現行の操作では許可されず、新たに許可しない。
CHOICEにある合法な発動は移動表示がなくても同じ表示部品へ接続する。

## 開発側の実描画

Godot 4.7.2、Compatibility、Apple M4の実GPUで確認した。
1920x1080と1440x810で、盤端の距離2攻撃、斜め攻撃、盤端の回復、変更色の回復の8条件を描画し、到達と数値、リングと識別の維持、BUILDでの消失を確認した。
画像はartifacts/runtime/action-feedback/qa-clean-以下、記録はgpu-qa-clean.jsonにある。
最大のCPU側描画処理時間は18.516msだった。
これはライブ描画のFPS保証ではない。
初回の検証スクリプトではウィンドウのフォーカス取得を待たず表示時間が停止したため、実フォーカスを確認してから再実行し、8条件すべて成功した。

通常のインポートでは既存のGodot設定が外部エディターを復元しようとして起動に失敗した。
追加アプリは使用していない。
以降の全体検査はプロジェクト内の開いたスクリプトの復元だけを一時停止し、検査後にキャッシュの元のバイトと更新時刻を復元した。
最終の全体検査とコミットフックは同じGodot 4.7.2の一時コピーを自己完結モードで使い、エディター設定もテンポラリへ分離した。
実ユーザー設定は保存していない。

## 確認動画

全解放の隔離データ、異なる6構成、シード128の3対3を使った。
最初の7手を合法に再現し、TURN08とTURN09を実Godot入力と描画で連続収録した。
動画は横1920x1080、30fps、H.264、yuv420p、faststart、無音、13.233秒、3,071,012バイトである。
計画から移動、着地、飛行、結果まではカットや速度加工を加えない。

| 時刻 | 場面 |
| --- | --- |
| 4.60秒 | ユニット1が確定し、雲の透過から2マス移動する |
| 5.27秒 | 着地し、既存の短い一拍を示す |
| 5.47から5.67秒 | INF200%の赤い弧がAへ届き、HP118から0、-132とDEFEATEDへつながる |
| 10.67秒 | 続くユニット2が1マス移動する |
| 10.93から11.13秒 | 緑の弧がユニット1へ届き、HP129から135、+6と柔らかい円弧を示す |

両手の最終HPと履歴は表示を通さない同じ合法操作と完全一致する。
397フレームを全復号し、時刻間隔、画角、色形式と先頭メタデータを確認した。
代表フレームの実ピクセルと前後の変化を確認し、デスクトップと個人情報は含めない。
通常BUILDへ戻し、Godotの操作を終了した。

## 最終確認と限界

動画は合法な再現操作であり、人が通して対CPUの一戦を行ったものではない。
CPUの発動接続は自動検査で確認し、動画は両陣営手動の進行を使う。
実機のiPhoneとX側の再圧縮、別GPU、全カスタム色の主観的な見やすさは未確認である。
小さく短い演出なので、スマートフォンでさらに弱く感じる場合は表示の寸法と時間だけで調整できる。
最終利用者の確認はmanual-checks.mdのREQ-021-S03を未確認のまま残す。
威力、対象、手番、CPU判断と保存形式は変更していない。
実セーブのバイトと更新時刻、設定の不存在、以前の動画17本の不変を確認した。
push、公開とX投稿は行わない。
