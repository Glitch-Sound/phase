# アセンブリの紋章と所属色の検証

## 結果と範囲

基準は6bea3f3であり、開始時の作業ツリーは空であった。
今回の独立した差分で、アセンブリ名と紋章、所属色、視点に基づく所有マークを追加した。
戦闘の計算と不変ID、移動、パネルとオーラ、赤い攻撃収束と緑の回復拡散を変更していない。
game/unit_identity.gdの差分はなく、既存ユニットの504形と生成方式を維持した。

BUILDのASSEMBLYから名前と6色の候補を編集し、即時プレビュー、APPLY、CANCELまたはEscを使う。
既存で編集できるPLAYERの3枠に属する設定であり、新しい敵編集モードは追加しない。
CPUのアセンブリはVECTORとAMBER、自分の既定はORBITとJADEとした。
名前は既存の版1規則で空白と制御文字を処理し、最大32コードポイントとする。
空欄は陣営の既定名へ解決し、大文字小文字とUnicode合成を変えない。
入力中の候補は原本と分離し、Enterは入力を整え、APPLYで初めて設定を反映する。
保存は明示SAVEとLOADだけであり、通常保存版を3とした。
旧保存移行は依頼の対象外であり、旧ファイルを削除、変換、自動保存しない。

別接頭辞のUTF-8とSHA-256、整数の幾何規則をdocs/assembly-v1.mdへ記載した。
名前と版で紋章を構成し、色と陣営、視点、衝突によって形を変更しない。
6つの安定キーはPEARL、JADE、ICE、AMBER、LILAC、ROSEである。
所属ユニットの紋章は色だけを別レイヤーで適用し、HPは同じ色相で白に近い高明度へ寄せた。
6色とも設定した輝度とコントラスト基準を満たすことを部品で検査した。
ステータス用の配色設定とは分離し、攻撃と回復、位相とフォーカスの色を変更しない。

戦闘左上の両行は紋章、HPバー、数値を共通の列と垂直中心へ揃える。
右側の上部には所属アセンブリ紋章、リングの芯にはユニット紋章を置く。
クラス以降の情報順と位置を保つ。
盤面の所有マークは白灰色の小さい同心円で、自分の視点の陣営と不変IDが整合するユニットだけへ描く。
最終の位置は既存フォーカスの四隅とリングを避け、視点を反転しても同じ規則で判定する。
自動生成のP1とE1形式とユニット名は盤面、右側、タイムライン、目的文、通知、ダイアログとツールチップから除いた。
行動の発動者と対象、目標の対象は同じユニット紋章で示し、待ち量とHP、装備とスキルは維持した。
利用者が入力したP1という名前も入力と保存、紋章生成、非表示のアクセシビリティ用名称へそのまま保持する。

## Godotでの確認

Godot 4.7.2、Apple M4、gl_compatibilityで独立した検証用プロセスを使った。
通常セーブと設定のパスをartifacts/runtime/assembly-identity内へ差し替え、明示的な保存だけを使った。
Godotの実ウィンドウにフォーカスがあることを確かめた上で、エンジンの入力イベントを送った。
人間による物理マウスとキーボードのプレイとは区別する。

| 段階 | 確認した範囲 |
| --- | --- |
| 初回起動 | 17項目成功。名前の長さとUnicode、EnterとTab、Esc、色とAPPLY、隔離SAVE |
| 別プロセス再起動 | 352項目成功。自動ロードなし、明示LOAD、両サイズ、6色の候補と取消、長い名前、通常状態の復元 |
| 進行した戦闘 | 合法な6手を再現したTURN 07で6体を表示。続く2手はUI入力から移動と攻撃、撃破まで確認 |
| 移動の不変条件 | 実行中の白線なし、右詳細が移動者を保ち、所属紋章と更新されるリングが一致 |
| 同じ設定 | 全6体を同名Echo、両陣営を同じ紋章とICEにした検証。両視点で自軍の3体だけに所有マーク |
| CPU | 固定既定アセンブリの敵が実際に表示された1手を完了 |
| 最終描画 | 本番main.tscnと同じアンカーを使い、入力を送らないGPU描画の84項目成功。標準1920x1080と最小1152x648、右詳細、両視点、隣接と盤端、行動と確定の両者の紋章、OPERATION内の対象紋章を確認 |

初期の入力用検証はルートControlを直接作り、製品main.tscnの全画面アンカーを持っていなかった。
ダイアログの暗幕を正しく比較するため、最終描画では本番シーンをインスタンス化した。
製品のアンカーを直す変更はしていない。
実画面で所有マークが選択枠の角に近い問題を発見し、先行失敗を作って内側へ移した。
所属紋章の中心は上部の既存行に揃えた。
最新の追加指示で戦闘中の名前を取り除いたため、その後の最終描画には文字列を戻していない。

## OpenSpecのverify

対象変更はassembly-identityである。
別変更を対象にする場合はopenspec-verify-changeへ変更名を指定する。

| 観点 | 結果 |
| --- | --- |
| 完全性 | 8タスクを完了。差分の42シナリオを既存テスト、新規の部品とUI、実機確認の台帳へ対応づけた |
| 正確性 | REQ-050からREQ-052の規約、保存、所有を部品と接続で確認。変更したHP、所属、名前の既存シナリオも確認 |
| 整合性 | design.mdのD-01からD-06に沿い、表示設定と内部識別、一時データ、位相色を分離 |
| テストの識別力 | 色キーと所有者の完全な集合、2つのハッシュ、座標と幾何の数を確認。空の幾何と旧マーク位置を見逃さないことを確認 |
| 未確認 | 下記の物理操作と利用者の最終的な視認性判断は未確認として維持 |

実施した検査にCRITICALとWARNINGの指摘はない。
未確認範囲を含む完全な実機検証済みとはしない。
手動台帳を成功へ置き換えず、今回の開発側の観測を本書へ分けて記録した。
アーカイブは実装と有効仕様の一致を意味し、利用者による最終確認の代わりではない。

## 制限と終了状態

検証途中でMacが再びロックされ、本番シーンを使った最終状態でのOS入力確認は中止した。
最終のマーク位置と記号だけの識別はGPU描画で確認したが、修正後の物理入力を確認したことにはしない。
日本語IMEの変換操作、他のOSとGPU、通信は未検証であり、ネット機能は追加していない。
今回の戦闘検証は進行した2手とCPUの1手であり、新規の自然な一戦を最初から最後までプレイした評価ではない。
通常と最小の全景を確認したが、紋章の細かい意匠とHPの最終的な読みやすさは利用者の実機で確認する。
検証用のGodotは通常BUILDへ戻して終了し、画面操作を終えた。
実セーブと設定、既存成果物は保護し、pushと公開は行っていない。

## 検証画像の出力に関する記録

追加指示後の描画で出力名が最初の確認PNGと重なったため、最新の全画像をsymbols接頭辞の別名へ分離した。
最初のBUILDと設定PNGはLibraryの同じ版から元のローカル内容へ復元した。
旧戦闘PNGの同名への復元は、最新画像を失う可能性を理由に自動承認レビューで拒否された。
別名の最新戦闘PNGが同一バイトで存在することを確認し、ユーザーの最新指示を読み直して1回だけ再試行したが、拒否が続いたため、その操作を停止した。
Libraryの旧戦闘画像は元の版のままであり、最新の成果物はsymbols-battle-turn07-1920.pngとして保全した。
今回以前の44ファイルと実データは変更していない。
