# 接続線の色と右情報の評価

## 原因と変更

前回の画像ではユニット2を詳細表示のために選択していた。\
ui/main.gdの接続線は選択またはホバーに一致するとCYAN、不透明度0.95へ切り替わり、他の通常線はMUTED、不透明度0.40だった。\
陣営、HP、行動可能性による違いではない。

接続線の色を定義する1か所を調整し、選択とホバーでもMUTED、不透明度0.40に揃えた。\
再登場の接続は従来のMUTED、不透明度0.18を保つ。\
選択状態のHP文字色、盤面の強調、右の詳細、未来の節点の時刻を保持する選択と経路予測の独立は変更していない。\
線の幅、経路、各要素の位置、右情報、ゲームルールと配色設定は変更していない。

REQ-019-S07の状態選択と盤面対応は維持され、シナリオの追加、変更と削除を要しない見た目の色調整としてAGENTS.mdの直接変更手順を使った。\
OpenSpecのchangeは作成せず、正式仕様は変更していない。

## 検証

- 先にGPU検査を作り、旧実装では選択とホバーの画素比較28件が失敗した。同一場面が変更されることを求める比較も旧実装では変更0画素として失敗した。
- 修正後のGPU検査は379項目、0失敗だった。4ユニット、各再登場、節点のクリックとホバー、1152x648、1920x1080、2560x1440と縦長1200x1600で、選択前後の接続線の実画素が同じであることを確認した。
- 両陣営10行動を実GUIで進めたTURN11を再現した。攻撃と回復を含み、HPは80、59、60、38である。ユニット2を選択し、前回と同じ進行場面で比較した。
- 変化は接続線内の144画素だけであり、対象外差分は0だった。右情報、リング、盤面、メニューと他の描画が一致する。
- 通常のGodot 4.7.2の1438x809埋め込みでも、味方2と敵Aの選択、右詳細と盤面の連動、未確定経路の保持、移動の確定、攻撃と次の手番を操作した。敵AのHPは100から90へ減った。
- npm run checkはheadless2438項目、既存再生、4仕様とトレース検査に成功した。既存テストと検査コマンドの構成は変更していない。

通常のGodotはRESTARTでBUILDへ戻し、画面操作を終了した。\
独立全画面と全カスタム配色の手動比較、自然な一戦の完走は今回再実施していない。\
今回の調整に関する不具合は検出していない。

## 右情報の案の評価(未実装)

提案の順はCLASS、リング状態、GEARとARMS、MOVE、スキルである。\
現在はCLASS、リング状態、MOVE、GEARとARMS、スキルである。\
今回は右情報の描画を変更していない。

| 観点 | 評価 |
| --- | --- |
| 順番 | 賛成である。リングに関わる装備をリングの直下へまとめ、構成を確認してから移動と行動へ目を移せる |
| 装備を個別の枠にする | 装備を独立した物として識別しやすく、クラスやスキルの文字列と区別できる |
| 見た目の懸念 | 2つの強い枠や背景は情報を増やし、黒い余白を使う現画面から浮く。システムメニューと同じ外観にすると押せるボタンに見える |
| 文字量と配置 | 右領域には余裕がある。枠の内側余白を設けても長い突然変異名と全3スキル、右下メニューの非交差を保つ必要がある |
| 制約 | 現行REQ-019-S04は右情報の囲いを省く。この案を実装する場合はユーザーの承認後、GEARとARMSだけを例外とする仕様変更が必要である |

並び順は提案どおりを推奨する。\
枠を採用するならGEARとARMSだけの控えめな細い輪郭とし、背景は黒いまま、影や発光、ボタンに似たホバー演出を加えない案を推奨する。\
装備名は枠内の1行を基本とし、突然変異を含む最長名と最小画面で欠けないか再検証する。\
以前削除した説明や見出しは戻さない。\
右情報の順番と枠の追加は本報告では提案だけである。
