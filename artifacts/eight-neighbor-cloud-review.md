# 周囲8マスと漂う雲の検証

## 変更

周囲パッシブの作用を上下左右4マスから斜めを含む8マスへ広げた。
本人と同じセル、距離2以上、盤外と撃破済みの発生源を除く。
本人除外、両陣営、着地ごとのGEARとARMS、SLOWの0.5倍とSTOPの0倍、FASTの1.5倍を維持する。
同種は重複せず、STOPを優先し、STOPがないSLOWとFASTは通常1倍へ相殺する。
CORE、能力値、手番速度、攻撃と回復、位置操作の対象範囲は変更していない。

8方向の定義を共通のカタログへ置き、倍率と範囲列挙、既存の進入とCPUが同じ規則を使う。
通常移動の各歩、全到着位置を先に決める交換と押し出し、取消と確定を維持する。
表示はSURROUNDINGへ変更したが、旧保存のADJACENTを含む内部IDと版1は維持する。
新品の自動開放、敵の初期装備と利用者の構成は変更していない。

## 見た目の判断

セルごとの十字形の雲を取り除き、生存する装備ユニットの周囲へ柔らかい雲を連続して漂わせる。
初回の多角形の雲片は葉のように見えたため、Godot標準のメモリ内の放射グラデーションで縁をぼかした。
画像ファイルと素材は追加していない。
薄い雲片をずらして重ね、形と位置だけを表示時間でゆっくり動かす。
動きを抑える設定では同じ形で止まり、戦闘値と乱数、正確な範囲は動かない。

雲は中心の3x3セルと盤面の交差へ収め、距離2以上のセルと盤外へ広げない。
全セル背景の後、パネルとユニットの前に描くことで、次行の背景に消されず、リングと効果記号を隠さない。
移動後の発生源は予測位置へ移し、薄い面と短い破線の軌跡で現在と区別する。
雲は発生源を示す柔らかい表現であり、濃さと重なりを倍率として扱わない。
正確な8マスの作用、倍率と発生源はホバーとHELPで確認できる。

GUARDの八角形は設定アクセント色へ変え、輪郭の濃さを0.55から0.95へ上げた。
線幅と位置、薄い面、白いHP円弧と各リング、四隅フォーカスを維持する。
文字と四辺の対象枠、発光は追加していない。
同じ描画部品を盤面、手番一覧、詳細と予測で使う。

## 検査

利用者の範囲変更に合わせ、既存の検査を実装より先に更新した。
周囲の34項目中7件、CPUの10項目中2件、画面の10項目中2件、共通図形の153項目中1件で現行の不足を検出した。
修正後は34、10、11、153項目がすべて成功した。
経路と押し出し、CPUは斜めで作用する例へ更新し、範囲の境界は角の3セル、同位置と距離2を集合と具体的な角度で検証した。
既存の倍率と重複、HP上限と手番、保存の基本規則を弱めず、勝敗と決着手数の固定期待値は増やしていない。

次の誤実装を一時的に入れ、既存検査が失敗することを確認して復元した。

- 作用を上下左右だけへ戻す。
- 雲の盤面による切り取りをなくす。
- 雲の表示時間を0へ固定する。
- GUARDの輪郭を元の白系へ戻す。

新しい形の検査は、PackedVector2Arrayを配列として読む検査側の修正と、既存の監査にあるdraw_timesとの重複名の修正を行った。
初期化エラーで待機した検証用headlessプロセスだけを終了し、通常のGodot画面は終了していない。
旧4マスの予測で変わるセルを使っていたGPU検査は、8マスで新しく入るセルへ更新した。
これらの途中の失敗と最終の成功を区別し、ログをartifacts/runtime/eight-fields-*.txtへ残した。

`npm run check`でプロダクト全体と正式仕様5件が成功した。
既存の証明書取得の環境警告を除き、最終のGDScriptエラーと検査失敗はない。
プロダクト検査のコマンドとスイートの数は変更せず、既存検査を更新した。

## 実Godotの観測

Godot 4.7.2、Compatibility、Apple M4、OpenGL 4.1 Metalで確認した。
1152x648、1920x1080、2560x1440と1200x1600で、雲とGUARD、HPとリング、盤面端、予測と取消、HELPと変換後のクリックを検証した。
交換と押し出しは実入力で対象を選び、実際の位置と各角度、HPが事前の予測に一致することを確認した。
最終のGPU検査は137項目すべて成功した。

同じ配置を約3.07秒表示し、0秒、約1.5秒、約3秒の画像で雲の位置と形の変化を比較した。
時間が進んでもユニットの全データは変わらず、動きを抑える設定では表示時計も停止した。
4発生源の基準サイズで、盤面描画をCPU側から組み立てる85回の時間は中央値約1.24ms、上位95%の目安は約1.53msだった。
これはGPUの全フレーム時間と別の測定であり、他の機種の性能を保証しない。

入力イベントでPLAYERを操作し、ENEMYは通常速度のCPU演出で1戦を進めた。
シード1、PLAYERはDAMAGEとGUARDにSLOWまたはFAST、ENEMYはDAMAGEとHEALにSTOPまたはSLOWを装備した検証用構成である。
GUARDを見せる序盤と撮影時以外は公開状態の方策を使い、両陣営の移動と攻撃、GUARDの消費、撃破と範囲の除外を観測した。
17手でVICTORY、実時間約13.4秒、PLAYER側の判断は約14から97msだった。
この勝敗と手数はバランスの合否ではなく、今回の明示構成による観測である。

## 限界と保存

実GPUへの入力を伴う自動操作であり、今回の新たな人手の自然な対戦とは区別する。
全ステージの手動対戦、周囲構成の対人バランスと全品の自然取得は未確認である。
異なるRetina機とフルスクリーン切替、全カスタム配色の実画面は網羅していない。
既存の配色と設定、選択、保存の自動検査は成功した。
雲の柔らかさとGUARDの見え方の最終判断は利用者に委ね、manual-checks.mdの16件の未確認を維持する。

実セーブの内容と更新時刻、設定ファイルの不存在は作業前後で一致した。
検証用GodotをBUILDへ戻して終了し、通常の埋め込み画面は今回操作していない。
pushと公開は行っていない。
