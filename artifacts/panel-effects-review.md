# 効果パネルの検証

## 変更範囲

旧配置は中央付近の固定10枚と、BREACHとANCHORの6枚の上書きだった。\
本番ではこれを開始時のシードによる配置へ置き換え、効果の文字略号をLucideへ置き換えた。\
1000px角の盤面、周囲の配置、戦闘式、回転式、移動条件、勝敗の優先順位と収集を変更していない。

| 効果 | 盤面の形 | 維持した意味 |
| --- | --- | --- |
| SHIFT | fast-forwardの2つの三角形 | ARMSの回転量を2倍にする |
| LOCK | lockの錠前 | GEARを回転させない |
| REVERSE | rotate-ccwの反時計回りの矢印 | ARMSを逆回転させる |

盤面のS+、L=、R-は削除した。\
効果セルのホバーに対象リングまで含む説明を出し、HELPに3アイコンと短い凡例を置いた。\
色は既存の役割色を参照し、カスタム色を保存し直さない。\
既存のLucideの同梱方式を使い、公式コミット55782beff3a0133df79c417eb68f96e8f19e2404のfast-forwardとlockを追加した。\
rotate-ccwを再利用し、出典をassets/lucide/NOTICE.mdへ追記した。\
同梱LICENSEのISCとFeather由来部分のMITを保持した。

## 数量と配置

| 判断 | 実装 |
| --- | --- |
| 母数 | 除外前の10x10の全100セル |
| 率と端数 | PANEL_EFFECT_RATE=0.20、floor(100x率+0.5)で四捨五入し20枚 |
| 除外 | 4体の初期位置、PLAYER目標、ENEMY目標の有効セルの集合 |
| 候補不足 | 目標数を候補数へ制限し、候補0なら空辞書を返す |
| 分散 | 4つの5x5区画へ候補数に比例する最大剰余配分を行い、同じ剰余はシード乱数で決める |
| 区画内 | Fisher-Yatesで重複なく抽選し、隣接と小さな集まりを許可する |
| 効果種類 | 3種類の枚数差を最大1にした袋を混ぜる。20枚では6、7、7枚であり、余分な種類も抽選する |
| 再現 | 同じステージとシードと生成方式とGodot版なら、座標と効果が一致する |

すべての特殊パネルは従来どおり通行可能である。\
新しい障害物や配置を理由にした通行禁止を追加していない。\
通常のSTARTは前回と異なる32bitシードを選び、HELPから現在のシードを読める。\
BUILDの編集と描画はシードを消費せず、ドロップ用乱数と独立する。\
戦闘中は再抽選しない。\
シードの入力欄や配置のセーブ形式は追加していない。\
再現用モデル入口はBattle.start(stage,builds,seed)、開発用UI入口はpanel_seed_overrideである。

512シードの全滅戦配置では、512種類の配置が生成され、96候補セルすべてが75～135回選ばれた。\
隣接の観測数は2984であり、隣接を禁止した整列配置にはしていない。\
現行4ステージの候補数では各区画5枚になる。\
これは全シードの統計的無偏りや同難易度の証明ではない。

## 自動検査と誤実装の検出

npm run checkが成功し、headless2356項目、既存と新規の戦闘再生、4仕様の厳密検査とトレース検査を通過した。\
差分仕様のopenspec validateとstrict change traceも成功した。\
GodotのGPU139項目は別途実行した。

- tests/panel_generation.gdの539項目で、4ステージの数量、除外、端数、種類、入力不変、シード再現、他乱数との独立、512シードの分散、候補不足と戦闘接続を確認した。
- tests/panel_interface.gdの99項目で、全セルと効果の集合、重複とNORMALの不在、実SVG、設定色、意味、HELP、シードと入力を確認した。
- UI接続は1152x648、1920x1080、2560x1440、1200x1600で実際のGUI座標変換を通した。
- tests/panel_play.gdで本番モデルのシード0、1、7を再生し、全4ステージの初手合法経路570本を確定しても即時勝利や報酬が発生しないことを確認した。
- 旧配置を前提とする位相とUIの検査はtests/fixture_battle.gdとfixture_main.gdへ分離した。本番へ検査専用固定モードは追加せず、従来の数値と操作期待値を維持した。
- scripts/check.shへ3つの新規スイートを接続した。npm testがプロダクト検査、npm run checkがそれにOpenSpec検査を加えた全体検査である。

生成器が存在しない状態で新規検査が1件、旧UIで略号と説明の検査が2件失敗した。\
最終検証では、枚数を1減らす、除外を無視する、全シードを0にする、SHIFTを錠前へ変える、説明のARMSをGEARへ変える、S+を復活させる、盤面入力を転送しない変異を一つずつ加えた。\
7種類すべてを対応する検査が検出し、元のコードへ復元した。\
セルと効果の集合比較と役割色の追加検査は、既存の全セル描画と設定色参照で最初から成功した。\
期待値を描画関数から生成していない。

GUIホバー用Controlの初期実装は盤面クリックを遮り、4サイズの入力検査で失敗した。\
局所座標を親の論理座標へ戻し、既存入力へ一度だけ渡して処理済みにすることで修正した。\
GPU検査では一度の対象クリックでダメージ、次の手番、選択未指定が揃い、二重転送による対象の再選択がないことを確認した。

## プレイの評価と限界

本番モデルの両陣営を経路と攻撃と回復の評価で操作した全滅戦は、シード0、1、7で23、28、30手のVICTORYに到達し、WAITは両陣営とも0回だった。\
両陣営の回復を含むのは0と7であり、1では敵の回復は0回だった。\
シード0の再生履歴は完全一致した。\
操作と結果はartifacts/panel-play.jsonに残した。

到達戦では、敵Bを単純に追跡する既存方策は3シードともBREACHとANCHORで12手のDEFEATになった。\
取得可能なMOVEを両味方の空き枠へ付け、ステータスは変えず初動を迎撃へ変えると、シード0と1は両ステージとも19手でVICTORYとなった。\
同じ迎撃方策でもシード7は両ステージとも12手でDEFEATだった。\
不利な結果を除外せず、配置を勝ちやすいシードへ選別せず、戦闘式を変更しなかった。\
目標へ通れること、相手を無視すると敗北すること、一部の対抗勝利は確認したが、全シードの最適攻略、初期装備での同等難易度と勝利可能性の網羅は未確認である。

自然な一戦の最後までの人間による手動プレイ、全ステージの実機操作、全配色の新アイコン比較、縦長の手動操作、独立全画面と長時間の性能計測は今回の範囲に含まない。\
9件の実機確認台帳はユーザーの最終確認対象として維持する。
