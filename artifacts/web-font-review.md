# Webの日本語フォント修正

## 原因と対応

既存UIはSystemFontに依存し、macOSの日本語フォントを参照していた。
Webにはその字形がなく、説明と日本語の選択肢が代替文字になった。
Google Fonts公式のNoto Sans JP原本とOFLを同梱し、説明用のフォントだけへフォールバックを追加した。
通常のシステムフォントとエンジンの既定を先に保ち、数値用の等幅フォントは変更しない。
英語の原文、翻訳、戦闘と保存処理は変更していない。
既存のREQ-053-S04に対する直接バグ修正であり、シナリオは変更しない。

## 取得元と権利

取得元のコミットは295d98a7a0c17c68f1341eaeea354e7960ea70d3である。
assets/fonts/NOTICE.mdとOFL.txtに出典と原文を保持した。
フォント原本は9589900バイト、SHA256はc2f3b4d463500a2ddcd3849cded1fceeb9fd6d1c32e6cbecd568453ba50fc68fである。
原本を加工せず、リソースの描画設定でRegularを指定する。
Webプリセットには権利表示を含めるフィルターを加えた。
PCK内のフォントとライセンスの実在も確認した。\
HTMLシェルにも実行されないプレーンテキストとしてライセンス全文を保持し、生成HTMLのソースから読めるようにした。

## 自動検査

- language.gdのフォント欠落検査が変更前に失敗した。
- バックエンドへウェイトが渡らない設定も検査で失敗させ、最終設定で成功した。
- 最終language検査48件が成功し、日本語説明に必要な字形をOSフォールバックなしで検査した。
- side_informationの位置合わせ検査92件は期待値を変更せず成功した。
- Web Demoのrelease再出力が成功し、実PCKの7項目が成功した。
- フォントなしの条件を再現して、追加したフォールバックの有無で日本語の字形の可否が変わることを確認した。
- PCKのdemoタグ、メモリ保存、OFLと出典の同梱を確認した。
- npm run checkが成功した。既存の検査コマンドは変更していない。

## 実ブラウザ

本人MacのBraveでlocalhostのWeb Demoを再読込した。
初回の解放通知、BUILDの説明と名前欄の補助、日本語のLanguage選択肢、HELPの3項目が代替文字なく表示されることを確認した。
JAからEN、ENからJAの往復でもBUILDとHELPを開閉でき、英語の名称と操作を維持した。
前回の試験用の名前dと明示英語の状態から、再読込後にKestrelと日本語の既定へ戻り、初回解放通知も再び表示された。
抽選結果の違いだけではなく、識別可能な名前と設定でリセットを確認した。

その後、回帰検査で判明した等幅フォントの行高変化を取り除き、Regularウェイトを確実に適用する整数タグへ設定を修正して最終版を再出力した。
この最終版をブラウザで再読込する直前にMacが再ロックされ、その再確認は未実施である。
フォント修正を含む版で日本語を実際に読めたことと、最後の微調整後の実ブラウザ確認を区別する。
最終PCKの字形、適用ウェイト、demoタグとライセンスは再検査済みである。
他ブラウザ、最小ウィンドウでの最終版の実ブラウザ確認、配布ホスト上の確認も未実施である。

## 試し方と保護

同じMacでhttp://127.0.0.1:8060/を開き、ブラウザの再読み込みボタンを使う。
キー操作がゲームに捕捉される場合もあるため、ツールバーのボタンで再読込する。
サーバー停止後はREADMEのPythonコマンドで出力フォルダーだけをlocalhostへ配信する。
新しいHTML一式はartifacts/runtime/web、更新前の出力はartifacts/runtime/web-font/before-exportに保持した。
実セーブと設定の内容と更新時刻を維持した。
公開、pushとアップロードは行わず、端末へフォントをインストールしていない。
