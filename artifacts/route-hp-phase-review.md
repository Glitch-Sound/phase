# 経路、HPと位相予測の判読性

## 変更の範囲

経路線は出発点と到着点にユニットがいる場合、実際のリング、HP、目盛りの外周で切り詰める。
色リングとHPの物理最小線幅、経路線の半幅、両側のAAに必要な物理2.5pxの余白を含める。
描画順を変えるだけでは空洞を線が横切るため、端を外へ切る方法を選んだ。
長さ0や両端の余白が区間を使い切る場合は線だけを省き、入力と戦闘状態を変更しない。
合法な経路は生存ユニットを通れないため、通常は起点の分離が該当する。
ユニットのある終点は描画部品のfixtureで検査し、移動の合法性は緩めていない。

HP円弧だけを純白へ変え、半径、細さ、HP比率、色リングと文字色を維持した。
通常と拡大で区別できたため、発光は追加しなかった。
円形予測は3装備の最低不透明度を0.72、結果の最低不透明度を0.45へ上げた。
最大値、実際の色、境界の補間、位相の形、戦闘式と設定色は維持する。

線幅2と番号円半径14は既存の値を調整定数へ集約した。
1000px角の盤面、右情報、2列2段メニュー、削除済み表示、内部ID、保存形式は変更していない。

## 実描画と実操作

Godot 4.7.2、Compatibility、Apple M4でGPU検査69件が成功した。
1152x648、1920x1080、2560x1440、1200x1600で経路確定と手番更新、HELPのクリックを検査した。
上下左右の線、HP0、1、50、100、4ユニットと境界、隣接、一致、不一致、AMBER、対象状態、TURN2の15画像を取得した。
縦長の画像はレターボックスを除いたviewportテクスチャであり、画素の検査座標とウィンドウの入力座標を区別する。

変更前と同じTURN2で、HP、経路と予測を含む領域以外の全画素は一致した。
円形予測の外周だけのRGB合計は3670.106から4371.028へ増え、約19.1%明るくなった。
内側HPを除いた比較であり、グラデーションのRGBと実位相は既存の部品検査で確認した。

通常のGodot埋め込み1438x809で上下左右への経路追加と取消、確定、ACTION、BACK、DAMAGE、11ダメージと次の手番の経路を実操作した。
リングと上端の目盛りに線が重ならず、HPと色リングを区別できた。
Retinaの全画面4608x2592、内部表示4442x2499で経路2歩を追加し、隙間、純白HP、一致した予測と経路でずれた予測を確認した。
通常サイズへ戻した後も経路表示を維持し、RESTARTでBUILDへ戻して画面操作を終了した。

## 検証の境界

今回の通常実操作は攻撃1回と次の経路までであり、一戦を自然な勝敗まで完走していない。
回復と閉塞WAIT、QUIT終了は今回の通常起動では再実施していない。
4ユニットのHP0と1を含む境界はGPUの明示的fixtureであり、自然な戦闘での達成とは扱わない。
最小と縦長の入力はGPUで検査し、OSの縦長ウィンドウの手動操作は再実施していない。
情報の最終的な見やすさはユーザーの確認対象である。
HP色を変えたREQ-030-S03も未確認へ戻し、台帳は9件の最終確認を残す。

実セーブのSHA256は25167e282e85b12fd9f059ae72d9cb16e4d6fb55310b1d3f57295dd02a6573e2で、更新日時2026-11-15T01:12:39.637Zを維持した。
実ui-settings.jsonは存在せず、保存、色適用、pushと公開は行っていない。

## 最終確認

npm run checkで1718件のheadless検査、両陣営の戦闘再生、4つの正式仕様の検査が成功した。

1718件には新規の経路127件を含み、既存の戦闘再生も成功した。
OpenSpecの3要件10シナリオについて実装、検査または実機確認台帳の対応と設計との一致を確認し、重大な指摘と警告はない。
