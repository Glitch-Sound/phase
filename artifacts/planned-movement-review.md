# 予定から移動と技を連続再生する改修

## 変更と操作

人は経路の終点をダブルクリックして行動を選び、必要な対象を選んでからCONFIRMする。\
選択中は着地点から合法な行動と効果を予測し、盤上の実ユニット、位置と角度、HP、手番と履歴は変更しない。\
WAITとGUARDは対象クリックを必要とせず、移動だけで終局する場合はMOVE / FINISHを確認する。

BACKとEscは対象、行動、経路編集の順に予定だけを戻す。\
CONFIRM後は移動と技を一度だけ実行し、移動後のメニューと追加入力を挟まない。\
CPUも同じ移動表示を通し、選択済みの行動と対象を既存表示で示して、到着後は対象選択の待ちを加えず結果へ進む。

移動表示は1セル0.20秒、上限0.65秒とした。\
旧0.10秒より各歩の変化を読み取れる時間があり、長経路でも待ちすぎない構成である。\
各歩は既存のenter_cellから得た独立した状態を使い、GEARとARMSの方向と周囲倍率を維持して角度だけを補間する。\
COREのRESETは開始角への短い方向で表示し、通過効果を原本へ追加適用しない。\
盤面と左右は同じ描画用ユニットを使い、CLASSと装備名を維持する。

## 自動検査

- 予定部品12項目、移動部品23項目、画面接続22項目が成功した。
- 予定部品の未実装、移動中の状態API欠落、画面の旧選択順、古い予定行動の残留とCPU意図表示を、失敗する検査で確認してから実装した。
- 予定中に原本を仮移動させる変異実装は5項目で失敗した。製品コードを変更せず、検証専用の複製で試した。
- STOP範囲と逆方向COREの途中表示は、既存の共有計算を使っていたため追加確認時から成功した。
- 既存UI検査は実モデルのCHOICEから独立した予定のCHOICEへ参照を変更し、攻撃の確認点をCONFIRMと到着後へ移した。
- 表示寸法、既存の効果量、保存、対象パターンなどの期待値は弱めていない。勝敗、終了手数と固定戦術の新しいバランス期待値は追加していない。
- 製品検査scripts/check.shにturn_planと各移動検査の完了出力確認を加えた。
- npm run checkで製品検査、静的解析、6仕様の検証と追跡検査が成功した。最終コミットのフックでも同じ全体検査を行う。

## 実描画

macOS、Apple M4、Godot 4.7.2のCompatibility描画で、1152x648と1920x1080を検証した。\
実main画面へ拡縮後の座標からマウスイベントを送り、予定の原本不変、BACK、CONFIRM、曲がる移動、左右の変化と経路の余白、CPUとHELP、移動中のRESTART、移動による終局を222項目で確認し、失敗は0だった。\
最小と標準の原寸画像、およびCPU移動中の選択済みの行動表示も確認した。

移動位置と角度をフレームごとに記録し、左右と盤面が同じ状態であることを確認した。\
参考として描画関数内の処理時間は最初のGPU検証206フレームで中央値3.662ms、95パーセンタイル10.129ms、最大21.409msだった。\
これはGPU全体のフレーム時間や他端末での性能保証ではない。

## 収録中に見つけた描画境界

連続角度で0度をまたぐ際、Vector2へ丸めた領域の微小な隙間から所属が欠け、PREVIEWの輪郭生成が失敗した。\
REQ-033-S02の再現検査を追加し、旧実装で描画エラーと失敗を確認した。\
開始境界の循環順で描画上の所属を決めるよう修正し、4輪郭が欠けず有限な座標になることを含むPREVIEW167項目が成功した。\
戦闘計算と領域の値は変更していない。\
不具合を含む試作フレームは配布せず、修正後にエラーのない全フレームを新しい出力先へ再収録した。

## 限界と保護

今回は実描画と合成入力による検証であり、人による物理マウスの再プレイ、別の高DPI画面と端末側のMP4プレイヤーでの再生は未確認である。\
最終確認はmanual-checks.mdへ未確認として残す。\
SWAPとPUSHの強制移動の新しいアニメーションは加えていない。\
通常BUILDと元の一時状態を復元して検証プロセスを終了した。\
実セーブと設定、過去の動画を維持し、push、公開とXへの投稿は行っていない。
