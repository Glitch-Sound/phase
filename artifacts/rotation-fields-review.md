# 周囲回転と自分対象の検証

## 変更と判断

GUARDの自分対象から四辺の対象枠と対象面を取り除いた。
既存の四隅フォーカス、八角形、スキル名と操作は維持した。

| パッシブ | 上下左右1マスの他者のGEARとARMS |
| --- | --- |
| SLOW FIELD | 各歩の回転量を0.5倍にする |
| STOP FIELD | 各歩の回転量を0倍にする |
| FAST FIELD | 各歩の回転量を1.5倍にする |

生存発生源の本人を除く両陣営へ作用する。
各歩の着地で判定し、範囲外へ持続せず、立っているだけでは回転しない。
同種は個数によらず1回とし、STOPを最優先、STOPがないSLOWとFASTは通常1倍へ相殺する。
CORE、能力値、手番時刻と基礎ダメージは変更しない。
COREパネルは従来どおり作用し、PANEL IGNOREは周囲効果を無視しない。

交換と押し出しは全到着位置を先に決めてから、動いた本人ごとに通常の1歩として扱う。
これにより交換相手が発生源でも処理順に依存しない。
予測、確定、CPUと雲は同じ現在位置の判定部品を使う。
CPUの反撃予測は候補後の発生源位置と生存を含め、1回の判断内だけ同じ世界の計算を再利用する。

雲は有効な盤内セルごとに、ユニットと効果記号より下へ静かに重ねる。
予測で変わる範囲は破線とし、ホバーにAFTER MOVE、倍率と発生源、相殺と優先を示す。
HELPのSKILLSからFIELDSへ進むと全規則を確認できる。
素材と追加アプリは導入していない。

新品は初期未開放とし、既存の戦利品、共有装備と3枠、版1保存を利用する。
旧13品までの保存を自動開放や自動装備せず読み込む。
敵の初期装備は変えず、検証用だけで新しい周囲効果を装備させた。

## 自動検証

- 最初の周囲検査は12項目中8失敗で、ID不足と回転未適用、取得未対応を検出した。
- CPUの代表接続は9項目中1失敗、画面は5項目中4失敗で、旧進入と四辺の対象枠、雲と説明の欠落を検出した。
- 範囲外の倍率を既存の境界検査へ加え、34項目中1失敗から修正した。
- 完成後は周囲の基本規則34項目、画面接続11項目、ユーティリティCPU10項目がすべて成功した。
- 誤実装を一時的に4種類入れ、停止優先の削除、異種の乗算、古い発生源位置のキャッシュ、GUARDの四辺復活をすべて検出し、原本へ復元した。
- `npm run check`はプロダクト全体と正式仕様5件に成功した。
  プロダクトの検査コマンドへ新しい下層と画面接続の2スイートを接続した。
  戦闘の勝敗と決着手数を固定期待値に追加していない。

CPUのキャッシュ接続は実装済みの位置キーで最初から成功し、そのキーを取り除く誤実装で失敗することを確かめた。
画面の代表ホバーは部分文字列でなく、倍率と作用元の全文一致へ強めた。
検査を作る途中の死亡済み発生源と実行後のfixtureは、期待角度を緩めず検査前の生存と未実行状態へ修正した。
ログはartifacts/runtime/rotation-fields-*.txtとrotation-fields-mutations.jsonへ置いた。
既存の環境由来の証明書取得の警告は残るが、GDScriptの実行エラーと検査失敗はない。

## 実GPUの表示と入力

Godot 4.7.2、Compatibility、Apple M4、OpenGL 4.1 Metalで検証した。
1152x648、1920x1080、2560x1440と1200x1600で、GUARD対象の四隅、発動、雲の範囲、移動予測の破線、取消、HELPの文字領域と実座標クリックを確認した。
合計119項目が成功した。
新しいポリゴンはセル内部に収まり、リングとパネル記号の描画を遮らず、盤面端からはみ出さない。
現在の雲と破線は控えめなため、細かな倍率の区別はホバーとHELPで確認する。

入力イベントによる1戦ではPLAYERを検証用方策、ENEMYを通常速度のCPU演出で進めた。
シード1、初期HP、PLAYERはDAMAGEとGUARDにSLOWまたはFAST、ENEMYはDAMAGEとHEALにSTOPまたはSLOWという明示編成である。
GUARDの確認を優先して序盤と撮影時に使用し、それ以外は公開状態の方策を使った。
20手でDEFEAT、ENEMY BのHP11で終局し、両陣営の移動と攻撃、GUARDの消費、撃破と範囲の除外、CPUの経路と対象表示を観測した。
検証の実時間は約18.9秒、PLAYER側の経路と行動の判断は約17から97msだった。
この1戦の勝敗と手数は観測であり、合否やバランスの保証ではない。

これは実GPUへの入力を伴う自動操作であり、新たな人手による自然な対戦とは区別する。
今回の通常の埋め込みGodotへは操作を送っていない。
検証用のGodotは対戦後にBUILDへ戻し、ウィンドウを終了した。
フルスクリーン切替と異なるRetina機での再測定、全ステージの人手プレイ、全品の自然取得、周囲構成の対人バランスは未確認である。
強制移動の新しい倍率は下層の予測と確定で検証し、今回のGPU対戦ではSWAPとPUSHを手動入力していない。
既存の配色検査は成功したが、今回の全カスタム配色の実画面を網羅してはいない。
