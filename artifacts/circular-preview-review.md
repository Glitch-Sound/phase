# 円形プレビューの確認

## 変更範囲

基準は17862aaである。\
PHASE PREVIEWの中央の3リングと半径48、HP、名前を維持し、その周囲へCORE、GEAR、ARMSと重なり結果の4輪郭を配置した。\
GとAの角度数値、横長波形と角度軸、下端のROUTEからEFFECTへの記載を除去し、INFとRESの最終同期率を1行へ集約した。\
特異点が有効なら同じ行に×5を出し、PATHとDESTINATIONは保持した。

マップを700角から760角へ拡大した。\
幅は約8.6%、面積は約17.9%増え、左右パネルとの間隔は10である。\
左右パネルを移動せずに正方形を確保するため、この幅にした。\
セル、記号、経路、効果量とクリック判定は共通のセル寸法へ接続した。\
BACKと閉塞時WAITは盤面の直下へ移した。

左右の情報、BUILD、SETTINGS、RESULT、ユニットの意匠、戦闘式、収集と保存、基本配色は変更していない。\
HELPは新しい表示の意味へ更新し、既存のINFとRESの正しい説明も維持した。\
追加説明が隣列へはみ出す問題を実画面で発見し、長さの検査を失敗させてから短く修正した。

## 参考画像と形の根拠

指定されたIMG_0606.jpeg、91,654 bytesを正規のLibrary転送手順でMacへ取得し、実画像の画素を確認した。\
黒地に細い色付きの閉曲線が重なる形を参考にし、画像をゲーム素材にはしていない。\
転送は承認されたPython 3を使用した。

各輪郭の角度領域は実際の配分、突然変異、回転から求める。\
領域中央を山、境界を谷とし、CORE、GEAR、ARMSの3本の細線を内から順に置く。\
4本目は同じステータスの三重一致とペア一致を0.7、0.2、0.1の重みで合成し、一致が多いほど不透明度を上げる。\
この局所的な生領域の表示は、LUK補助とベルカーブを含む最終補正率そのものではない。\
下の数値は従来の最終計算をそのまま使い、HELPにも違いを記した。

円形の線は旧波形と同じ基本5色を使う。\
プリセットの3リングだけを鮮やかにする既存処理と、カスタムRGBの保持は変更していない。\
時間と乱数で形を揺らさず、経路と配色が変わったときに更新する。\
4本の閉じ目の位置と色は一致する。

## 実行した検査

- 新しい部品と接続の検査は、未実装の状態で6件の失敗を確認してから実装した。
- 解析的な山と谷、透明度、RGBの検査は実装後に補強したため最初から成功した。誤った出力への感度は下の変異検査で確認した。
- tests/phase_preview.gdの57件は成功した。局所一致、部分一致、不一致、最小配分、突然変異、閉じ目、純粋性、キャッシュと配色、説明の幅、拡縮した入力を含む。
- 角度を無視する実装は6件、常に鮮明にする実装は3件、閉じ目を除く実装は8件の失敗となり、すべて終了コード1、構文エラーなしだった。変異は管理対象外のコピーだけに加えた。
- npm run checkは成功した。headless検査1,223件、両陣営を含む戦闘再生、4仕様の検証とトレースを含む。
- プロダクト検査scripts/check.shへphase_previewを追加した。既存の寸法依存テストは今回変更したマップと予測の座標だけを見直した。
- OpenSpecのchange検証とトレースの厳密検査が成功した。
- 同じTURN2の前回画像と比べて571,585画素が変わり、マップと予測領域の外は0画素だった。パネル上端の1px線も許可領域に含めた。

## Godotでの観測

Apple M4、Godot 4.7.2、Compatibility、Retinaの倍率2.0で実行した。\
Godotの実GPU描画を保存し、画像を実際に見て確認した。\
表示は1920x1080、1440x810、1152x648、縦長1200x1600、横長2560x1080、実全画面4608x2592と復帰を試した。\
縦長と横長では16:9の内容の画素を保存し、OSのデスクトップや個人情報は含めていない。

一致、ペア一致、不一致、DEFAULT、AMBER、ICE、カスタムの表示を生成した。\
一致と不一致、既定とカスタム、最小、HELP、対象と全画面の実画像を確認し、3リング、白いHP、輪郭の色と同期率を判別した。\
全画面では実ウィンドウ座標から敵Aを選択し、戻った後もTURN2の経路を維持した。\
両陣営について、配置とHPを明示したfixtureで拡大マップの入力から(5,6)から(5,5)への移動を確定し、GEAR330度とARMS60度を確認した。\
その後、実際のスキルボタンと対象クリックを通して攻撃と回復が成功した。\
画像確認は通常の一戦を最後まで遊んだことを意味せず、手動のユーザー最終確認を代替しない。

## 性能

PNG保存と全画素比較の処理は計測区間から除いた。\
経路角度を変えた30回の輪郭生成と、待機中の180描画フレームを測った。

| 表示 | 輪郭生成の中央値 / p95 | 待機中描画CPUの中央値 / p95 | 描画フレーム間隔の中央値 / p95 |
| --- | --- | --- | --- |
| 1920x1080 | 2.408 / 2.483 ms | 2.086 / 2.358 ms | 8.336 / 12.403 ms |
| 1152x648 | 2.421 / 2.532 ms | 1.845 / 2.063 ms | 8.239 / 11.079 ms |

待機中は輪郭を再生成しなかった。\
この実行環境では既存の30Hz更新の予算内だった。\
表は単独計測したpreview-capture-final.txtの値であり、追加入力確認と全体検査を並行した回の値とは分けた。\
全機種の性能や長時間の安定性を保証する測定ではない。
