# 円形予測の周期的な動き

## 変更

RESETを塗りのない元のひし形へ戻した。
直前のセル境界の強調、盤面、左右の配置、経路、メニューと戦闘式は維持した。

CORE、GEAR、ARMSの輪郭は実SPDの平方根に応じた速度で揺れる。
装備ごとの係数と初期位相を分け、近い速度が生じる場合だけ最小差を確保する。
等SPD20の周期は約5.00秒、4.27秒、3.65秒となる。
表示時間は半径の変形だけに使い、実際の角度と数値を回転させない。

輪郭は塗りのない円に近い形を保ち、小さな膨らみが移る。
実領域の山と一致度を振幅の包絡に使い、装備の最大振幅を6px、結果を10pxとした。
結果は3波の重み付き合成であり、異なる周期によるうなりと一時的な打ち消しがある。
瞬間の半径だけから一致度を判断せず、複数周期の振幅と維持した明るさ、線幅、色を併せて読む。
グラデーションとステータスの色分類を維持した。
既存の動きを抑える設定では現在の形で停止し、解除すると同じ表示時間から再開する。

## 参考の確認

提示された[Vecteezyの参考動画](https://www.vecteezy.com/video/81298395-warm-orange-gradient-orb-morphs-and-pulses-through-turbulence-displacement-capturing-a-glowing-neon-sunset-atmosphere)の公開プレビューを検証専用に取得した。
0、0.5、1、1.5、2、3、4、5秒の8つの実フレームを復号し、実画素を確認した。
連続再生のプレイヤーではなく、時刻の異なる実フレームによる観測である。
円に近い形と移る膨らみを参考にし、塗りと発光は使わず、素材はゲームへ組み込んでいない。

ローカル動画はartifacts/runtime/motion-reference-20261117/reference-preview.mp4である。
確認画像は同じディレクトリのframe-0.0.pngからframe-5.0.pngである。
許可済みのNodeとPythonを使い、PythonからOS標準の復号機能を呼び出した。
追加アプリは導入していない。

| 全体検査 | npm run check成功 |

テストを先に追加して、旧実装で線の記号と時間変化、HELP、停止の失敗を確認した。
各装備の1周期後の一致、等SPDとSPD1、20、96、低中高の複数周期の振幅、3波の独立した計算による合成、閉曲線と内側の余白を確かめた。
誤実装は構文エラーなしで全て失敗し、検査が振る舞いの違いを検出した。

GPUでは1152x648、1920x1080、2560x1440と1200x1600で入力を確認した。
縦長は1200x675の内容領域と上下の余白へ拡縮する。
低中高、等SPD1と96、AMBERと停止は明示した表示fixtureであり、添付する実戦の状態とは区別する。
比較可能な前回画像に対し、記号と円形予測の変更領域外の画素差は0だった。
キャッシュを維持した描画処理の観測はp95が8.269ms、最大15.606msだった。
CPU側の描画処理時間であり、全環境のGPU性能の保証ではない。

通常のGodotでは4442x2499の埋め込み表示で動き、経路追加、別ユニットの選択と経路保持、HELP、動きを抑える設定の切替を操作した。
設定を元の無効へ戻し、RESTARTでBUILDへ戻ったことを確認して画面操作を終了した。
時間を置いて輪郭だけが変わり、盤面とHPは維持されることを観測した。
停止中の完全画素一致は通常ウィンドウ全体のキャプチャでは確定せず、モデルとGPUの座標検査で確認した。
