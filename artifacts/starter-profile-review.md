# 初回装備と非永続セッションの検証

## 実装

新規プロフィールは固定のARMSとGEAR各4種と編成を保ち、各5種を追加してそれぞれ9種となる。\
VIT、INF、RES、SPD、LUKが単独で最大となる未所持のカタログ群から各1種を選び、候補不足では残りから補い、重複と数値変更を行わない。\
初回専用の乱数を使い、既存の盤面シードと戦利品を消費しない。

game/profile.gdが起動時に既存の有効な保存を復元し、未作成だけ抽選して保存する。\
既存保存へ追加品を足さず、ロードだけで書き戻さない。\
破損保存はエラーを示して保護し、初回書込の失敗でも同じセッションでは再抽選しない。

初回のBUILDでは今回の追加品だけをARMSとGEARの2列へ示す。\
型番と5値は実際に解放した配分から描き、CLOSEとEscで通常BUILDへ戻る。\
同じページのBUILD再訪、再戦とシーン再作成、既存プロフィールの起動では再表示しない。\
RESULTの実装は変更していない。

game/storage.gdへゲームと配色、言語、SE、表示モードの入出力を集約した。\
通常は既存パスへの原子的置換と退避、Webは静的メモリだけを使う。\
編成と報酬の通常保存は従来のSAVEを維持し、WebのSAVEはページを越えない。\
Web Sessionの出力は専用シェルでpersistentPathsとserviceWorkerを空にし、PWAを無効にする。\
Godotの既定の永続パスは[公式Engine設定のソース](https://github.com/godotengine/godot/blob/master/platform/web/js/engine/config.js)で確認した。

| 別プロセス | 隔離した実アプリのシーン起動で9品と初回通知、別のGodotプロセスで9品と通知なしを確認した |

既存の自動テストを変更せず、新たな固定勝敗、手数とダメージの期待値は追加していない。\
プロダクト検査scripts/check.shへstarter_profileとWebシェルの検査を追加した。\
JSON往復は整数がfloatへ復元される既存仕様に従い、期待値と結果を同じJSON値へ正規化して全体比較し、個別の値の変更を見逃さない。

## 未確認と保護

verifyでは7タスクの完了と追加2要件を照合した。\
REQ-061の4シナリオはプロフィールと通知、REQ-062-S01とS02は共通の保存境界とWebシェルへ対応する。\
REQ-062-S03の実描画はMacで開発側の確認を行ったが、実Webと利用者の最終確認は未確認である。\
設計D-01からD-04と実装の責務、先行テストと最終テストの期待値を確認し、CRITICALとWARNINGの指摘はない。\
未確認の実Web検査を成功やアーカイブの証拠には数えていない。

実Web出力を試行したが、4.7.2.stableのweb_nothreads_debug.zipとweb_nothreads_release.zipが未導入のため生成できなかった。\
実ブラウザの起動、IndexedDBの実監視とページ再読み込みは未確認であり、NodeとGodotのメモリ境界検査で代用済みとは扱わない。\
新規ページの確認は抽選結果の相違に依存せず、明示した編成と設定が消えることを根拠とした。\
外部配布先向けのパッケージとアップロードは行っていない。

実ユーザーのセーブと設定、原音など既存20ファイルの内容と更新時刻を比較し、不変を確認した。\
検証用GodotはBUILDへ戻して終了し、既存のユーザー側Godot画面は操作していない。\
OSの物理キー操作、実ブラウザと自然な一戦の完走は今回の範囲外である。\
実機台帳は新規の確認行を未確認として追加し、最終確認を開発側の観測だけで完了扱いにしていない。
