# 黒を基調としたUIの検証

## 結果

黒い面と余白を基調に、位相リング、4波形、HPと同期の棒、装備5値の小さな棒を情報の中心にした。
走査線、波形の時間揺れ、発光線、ランダムな線、反復する説明を除いた。
BUILD、BATTLE、行動選択、RESULT、HELP、SETTINGS、色選択を共通の書体と面へ統一した。
機能の未実装はないが、後述の実機確認の残りを成功扱いにはしていない。

戦闘式、ステージ、収集確率、初期ビルド、ゲームの保存形式、1920x1080と70pxセルを変更していない。
game/、project.godot、main.tscnに差分がないことを確認した。
入力要求書のSHA256はebd39aaf10e80b0c5e188be3acd9f4e397cf6f111103e3ff5b422064b7501bf6のままである。
旧美術方針と画像禁止だけは最新の利用者指示を優先した。

## 配色と操作

- DEFAULT、AMBER、ICEとアクセントおよび5ステータスの個別調整を備える。
- 最も明るい操作面との相対輝度比4.5以上、不透明、標準RGB範囲、ステータス同士のRGB距離0.12以上を適用条件とする。
- 低コントラストと重複色は理由を表示し、現在の配色と経路を保持する。
- 配色は明示的な適用時に独立したUI設定へ保存し、以前の設定を退避する。
- 色に加え、INF/RES等の名称、負数と正数、輪郭、選択の下線、フォーカス枠、勝敗文字とチェックまたはXを使う。
- TabとShift+Tabは最前面モーダルの有効な部品で循環する。
- 補助画面を閉じた後のフォーカスと、ウィンドウへ復帰した後のモーダル操作を復元する。
- 配色変更で未確定経路、CHOICE、TARGET、結果、報酬の抽選状態を変えない。

## 体験の評価と限界

経路変更によるリングと波形の変化を追いやすくなった。
静的な波形にしたため、経路で変わった形と装飾の動きを混同しない。
5値の棒だけでは正確な比較が難しいため、型番、数値、差分を残した。
色だけでは攻撃と回復や勝敗を判断させない構成にした。
これらは短い実操作での開発側の判断であり、初見の利用者による評価ではない。

今回の新UIでは一戦全体の自然な勝敗までの実プレイを完了していない。
以前に実画面で確認した28手の両陣営プレイはreview-verification.mdにあり、同じ操作履歴の自動再生は今回も成功した。
回復優先を極端にすると160コマンドでも決着しない課題は残る。
固定式やゲーム条件を変える依頼ではないため変更していない。

実機確認表には、新UIの取消とBACKを含む通しの経路操作、自然な勝敗までの一巡、RESTARTを含むシステム操作の通し確認を未確認で残した。
通常の操作と自動テストは成功しているが、これらの通し観測を成功として数えていない。
他OS、他GPU、色覚差の当事者評価、読み上げ対応は検証していない。
色間のRGB距離は、すべての色覚差に対する識別を保証するものではない。

ユーザーの最終確認では、好みの配色、普段のウィンドウ寸法での文字の読みやすさ、情報量、経路選択のしやすさ、新UIでの一戦を確認する。
既存のビルドセーブに対するSAVE/LOADは行わず、配色の実機検証にはラボ専用ファイルを使った。
追加アプリ、push、公開は行っていない。
