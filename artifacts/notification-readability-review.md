# 予測と通知の可読性

## 問題と修正

4033990では、戦闘通知の基線1028と予測の同期率の基線1026が重なっていた。\
独立レビューの指摘後、通常の埋め込み表示でも開始案内がINFとRESを覆うことを再現した。\
以前の比較キャプチャでは通知を消しており、この表示状態を見逃していた。

通知だけを予測パネルの右側の空き領域へ移し、リング、同期率、マップ、操作部品の位置は維持した。\
通知の文字の大きさ、色、表示時間は変更していない。\
位置はgame/tuning.gdのBATTLE_MESSAGE_POSITIONへ集約した。

REQ-033-S03の可読性を損なう既存シナリオの不具合として直接修正した。\
正式仕様の振る舞いは変更していない。

## 輪郭の調整

通常の縮小表示で結果線を追いやすくするため、game/tuning.gdの表示値だけを調整した。

| 値 | 前 | 後 |
| --- | --- | --- |
| 結果線の幅 | 1.4 | 2.0 |
| 3輪郭の最低不透明度 | 0.42 | 0.55 |
| 結果輪郭の最低不透明度 | 0.12 | 0.25 |

一致時の不透明度、色相と基本RGB、半径、振幅、頂点数、位相と重なりの計算は維持した。\
暗さを残しながら、不一致時も4輪郭の所在が分かり、一致時は明確なステータス色になるようにした。\
3リング、白いHP、他UI、保存と戦闘式も変更していない。

## 自動検査

通知を消さず、実際の開始、無効移動、無効対象の経路から表示する検査を追加した。\
通知の文字列を完全一致で確かめ、実フォントの上昇部と下降部から表示領域を求め、INFとRES、予測全体、盤面、操作ボタンとの非重複を確認した。\
1152x648、1440x810、縦長1200x1600、基準1920x1080への拡縮と通知の消滅も確認した。

修正前は74件中10件が失敗し、修正後は74件すべて成功した。\
管理対象外のコピーで旧通知位置を戻す変異でも同じ10件が失敗し、終了コード1となった。\
輪郭の調整では既存の期待値を変更せず成功した。\
プロダクト検査の入口は維持し、その中のphase_previewを17件増やした。\
npm run checkは1,240件、戦闘再生、4仕様とトレースを含め成功した。

## 実画面の観測

レビュー側の操作終了を待ってからGodotを操作した。\
1920x1080、1440x810、1152x648の各通知状態をGPUで描画して保存し、開始、無効移動、無効対象と同期率の非重複を確認した。\
1440の一致と不一致の調整前後の実画像も見て確認した。

通常の埋め込み表示1438x809でも、開始案内、無効移動、経路追加、終点確定、攻撃対象選択、無効対象をマウスで操作した。\
開始時のINF200.0%とRES200.0%、移動後のINF79.0%とRES103.4%を通知と同時に読めた。\
BACKも盤面の下へ独立して表示され、通知と重ならなかった。\
最後にRESTARTでBUILDへ戻し、実画面操作を終了した。\
設定やビルドの保存は行っていない。

## 限界

今回の実操作は上記の短い入力経路であり、自然な勝敗までの通しプレイは再実施していない。\
輪郭の視認性は開発側の観測であり、ユーザーの最終的な意匠判断を代替しない。\
既存の実機未確認7項目は未確認のままとする。\
追加の性能測定は行っていない。\
公開とpushは行っていない。
