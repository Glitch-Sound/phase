# 合成輪郭の滑らかな呼吸の検証

## 変更と観察

基準は131a5b5である。
旧MP4を全480フレーム復号し、旧版に当たる後半8秒の実画像とコードを確認した。
強一致の端に細かなひだが現れ、膨らみが二重に折れて見えた。
複数速度の加算、二重のtanh圧縮、狭い角度の強調が原因と判断した。

合成結果の強一致だけ、3装備の速度の平均から導く一つの余弦周期へ変更した。
角度の肩は対称な循環平均で丸くし、安全な空間包絡を事前に求める。
時間方向の圧縮と切断を外し、丸く膨らんで滑らかに戻す。
個別3輪郭と色、透明度、戦闘式、保存、他のUIは変更しない。
強一致がない場面は旧版と全座標が一致する。
強一致の端に隣接する肩の形は緩やかにつながるが、色と一致する角度は時間で動かさない。

## 実際の振幅と動き

TURN 08、同一の2歩の未確定経路、INF 200%の状態を使った。
以下は同じ位相を30秒、毎秒30フレームで評価した値であり、戦闘バランスの合否条件ではない。

| 指標 | 旧版 | 新版 |
| --- | --- | --- |
| 合成の最大ピーク間変位 | 32.596px | 31.495px |
| 前回の最大角度220度のピーク間変位 | 32.596px | 23.372px |
| 合成の最小から最大の半径 | 既存の内外包絡 | 74.800から106.307px |
| 最大の時間方向2階差分 | 0.611px/frame² | 0.133px/frame² |
| 最大の角度方向2階差分 | 3.425px/sample² | 0.223px/sample² |

最大の径方向の動きは約97%残した。
220度の鋭い端の変位は小さくなり、膨らむ範囲へ分散する。
単に全体の変位を小さくした変更ではない。
この場面の合成の周期は約2.278秒である。
旧版の各角度のピーク時刻は維持せず、一つの滑らかな呼吸へ置き換えた。
最小画面の最大ピーク間変位は約18.9物理pxとなる。

主観的な所見は、旧版の細かく折れるひだが消え、通常の全景でも下側が丸く膨らんで戻ると読み取れることである。
利用者が好む動きかどうかは最終確認を待つ。

## 検査

- 変更した周期と肩の検査は、基準版に接続した状態で170件中2件が失敗し、新版で170件すべて成功した。
- npm run checkは100組、8216件の表明と7仕様書の検証が成功した。
  検査コマンドの変更とバランス依存の固定期待値の追加はない。
- Godot 4.7.2、Apple M4のCompatibility実描画で、合法な7行動の再生後の同一試合を使用した。
  新規の実描画検査2370件は失敗なしであった。
- 1920x1080と1152x648で弱一致と強一致、最大、最小付近を確認した。
  1時間と24時間相当の表示時計でも実描画し、見切れと形のねじれがないことを確認した。
- 個別3輪郭のキャッシュは旧版と完全一致し、色と透明度の計算は変更していない。
  弱一致の30秒の座標と振幅も旧版と一致した。
- 600回の座標評価の参考計測では、旧版0.385ms、新版0.323ms/回であった。
  位相変更時だけのキャッシュ生成は旧版6.022ms、新版6.439ms/回であった。
  専用の性能試験ではなく、このMac上の参考値である。
- 保護対象16585項目のSHA-256と更新時刻は変化なしであった。
  実セーブと設定、既存画像と動画は保持した。
- 隔離UNLOCK ALLを終了し、通常BUILDと元のコレクションへ戻して検証アプリを終了した。
