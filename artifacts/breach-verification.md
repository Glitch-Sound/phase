# BREACHの閉塞修正

## 原因と修正

01の到達だけが勝利条件だったが、01撃破が敗北条件に含まれていなかった。
02だけが生存して敵を全滅させると達成可能な勝敗条件がなくなる。
BREACHへPLAYER01のTARGET敗北を追加し、撃破時点で直ちにDEFEATとする。
画面の条件文とヒント、READMEに01を守る条件を反映した。
要求で設定可能なTARGET敗北を使い、固定式、配置、報酬、保存形式、共通の判定処理は変えていない。

## 失敗から成功への確認

修正前は追加した検査のうち5件が失敗した。
01撃破後の決着、手番更新の停止、以降の操作拒否、他者生存と敵残存の両境界を拒否できなかった。
証拠はbreach-red.txtに残した。
条件追加後はレビュー回帰52チェック、既存モデル536チェック、UI接続12チェックが失敗0である。
全体検査はnpm run checkから実行し、従来の25手の目標達成、12手の対抗目標敗北、28手の両陣営の攻撃と回復を含む再生も成功した。

| 境界 | 期待結果 | 確認方法 |
| --- | --- | --- |
| 敵が移動してHP1の01を攻撃、02とA/Bは生存 | 即時DEFEAT、RESULT、手番と時刻は進まない | 合法移動、スキル選択、実際のダメージ処理 |
| 01撃破、02生存、敵生存 | DEFEAT | 戦闘状態でDEATH判定 |
| 01撃破、02生存、敵全滅 | DEFEAT | 報告された閉塞状態でDEATH判定 |
| 01生存、02撃破 | 継続 | DEATH判定 |
| 01生存、02撃破、敵全滅 | 到達まで継続、その後VICTORY | DEATH判定と目標への合法移動確定 |
| 両陣営全滅、またはSEVERANCEの両TARGET撃破 | DEFEAT | 同じDEATHの判定 |
| 同じREACHを勝敗双方へ設定 | DEFEAT | 条件fixtureと合法移動確定 |
| ANCHORの勝敗目標を双方が占有 | DEFEAT | 合法移動とWAITによるEND判定 |
| 結果確定後に勝利だけの状態へ変更して再判定 | DEFEATのまま | 既存の結果の不変性 |

敗北優先と01生存時の到達は元から正しく、最初から追加テストに成功した。
優先順位の検査が誤りを見逃さないよう、無視対象のruntime内へbattle.gdの複製を作り、その複製だけを勝利優先へ変えた。
この複製に対して新しい優先順位検査は5件失敗し、誤りを検出した。
証拠はbreach-priority-mutation.txtに残した。
製品側のbattle.gdは変更していない。

## 検査の範囲

今回の再現は実際のモデルの移動、攻撃、撃破、結果処理を実行する自動検査である。
ネイティブ画面でこの撃破操作を再実行したとは主張しない。
新しい描画部品はなく、RESULTからBUILDへの接続は既存UI検査と前回の実画面検証を維持する。
既存の未確認項目と回復優先による長期化は引き続きmanual-checks.mdとreview-verification.mdに残る。
既存のユーザーセーブと入力要求は変更せず、追加アプリや公開は必要なかった。
