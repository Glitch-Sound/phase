# 戦闘画面上端の表示削除

## 変更範囲

基準はc9e327cである。\
製品コードはui/main.gdの2行の削除だけであり、左上のPHASE / TACTICAL STUDYと右上のBOTH SIDES / HUMANを除去した。\
両者はdraw_stringによる文字描画であり、Control、入力領域、フォーカス、コールバックを持たない。\
前回の7表示の非表示、手番一覧、経路、円形予測、同期率、詳細、通知の分離と他の配置を維持した。\
セーブと配色設定への書き込み、push、公開は行っていない。

## 自動検査

tests/battle_labels.gdを88件から106件へ拡張した。\
既存の維持対象から2表示を外したのは、今回の明示的な削除指示による振る舞いの変更である。\
非表示対象へ2表示を加え、4ステージと行動選択、攻撃対象、回復対象、結果の背後を検査した。\
変更前は16件が失敗し、変更後は106件すべてが成功した。\
元の2表示位置のクリックが選択、経路、ユニットとオーバーレイを変えない検査は変更前から成功した。\
この検査は、対象が元から静的な文字だったことを確認するものである。

文字の一部だけが残る誤実装として、TACTICAL STUDYとHUMANだけを管理対象外のコピーへ描画した。\
106件中16件が失敗し、終了コード1となった。\
期待値は文字の接頭辞だけでなく元の表示領域全体を検査するため、残存文字を見逃さない。\
既存のプロダクト検査の入口は維持し、同じ検査群を拡張した。\
npm run checkは1,346件のheadless検査、戦闘再生、4仕様とトレースを含め成功した。

制限されたheadless実行ではmacOSの証明書取得に関する既知のエンジン警告が出た。\
既存の検査規則が識別する警告だけであり、スクリプト、描画と検査の失敗はなかった。\
検査を弱める変更は行っていない。

## 実描画と比較

Godot 4.7.2、Compatibility、Apple M4でTURN2を描画した。\
手番2、経路(4,6)から(5,6)、敵AのHP89、INF130.6%、RES94.5%を前回と揃えた。\
1920x1080の比較では、左上804画素、右上739画素の合計1,543画素だけが変化し、2領域外の差は0だった。\
実画像を目視し、指定2表示の不在、手番一覧と盤面、円形予測と同期率、詳細と操作部品の保持を確認した。\
基準、1440x810、最小1152x648で開始、無効移動、無効対象の通知を描画した。\
通知と同期率の分離を維持した。

## 通常のGodotでの操作

1438x809の通常の埋め込み表示で変更後のゲームを起動した。

1. 開始時に2表示と前回の7表示がなく、手番6件、詳細、予測、通知を表示することを確認した。
2. (4,4)の経路と一覧から選択したAの詳細を表示し、元の上端2表示位置をクリックしても経路と選択を維持することを確認した。
3. (5,4)へ経路を延ばし、終点のダブルクリックからACTION、攻撃、対象Aへ進んだ。
4. -11、敵HP合計189、TURN002、手番2を確認した。
5. (4,6)から(5,6)へ経路を選び、一覧からAを選択した。HP89/100の詳細と手番2のINF130.6%、RES94.5%を同時に確認した。
6. 元の上端位置を再びクリックし、選択と経路を維持することを確認した。
7. RESTARTでBUILDへ戻し、Godotの実画面操作を終了した。
