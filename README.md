# PHASE

移動経路で装備リングを回転させ、位相の干渉を予測して戦うGodot製の戦術ゲームである。
両陣営手動と敵CPUを選べる開発用のプレイ可能版であり、レベルはない。

## セットアップ

### 必要なもの

- Godot 4.7系(検証版4.7.2、Mac arm64)。
- 開発検査にはNode.js 22.12以上とnpm、Git。
- 追加のGodotアドオンや外部サービスは不要。
LucideのSVGアイコンとライセンスは同梱済みである。\
Webの日本語表示用にNoto Sans JPとSIL Open Font License 1.1も同梱し、端末へのフォント追加は不要である。

### 手順

1. Godotでproject.godotをインポートする。
2. プロジェクトを実行する(Macの既定ショートカットはCommand+B)。
3. ターミナルからは次のコマンドでも起動できる。

~~~sh
godot --path /Users/glitch/Developer/phase
~~~

## 使い方

起動直後のBUILDでPLAYER 01、02、03の構成とステージを選び、STARTを押す。
角枠で示した手番ユニットから、空いた上下左右のセルを順にクリックする。
PREVIEWで移動後のリングと位相の一致を比較し、経路の終点をダブルクリックして行動選択を開く。\
WAITと対象選択が不要な行動はそのボタン、ほかのACTIVEは有効な対象の選択で確定する。\
最後のCONFIRM画面はなく、画面を閉じてから移動と行動へ続く。
ENEMY CPUがOFFなら敵の手番も同じように操作する。
ONなら経路、行動と対象の予測を表示して自動操作する。

- 経路上のセルをクリックすると、それ以降を取り消す。
- 開始セルまたはEscで未確定経路を消す。
- 対象選択のBACKは予定した経路を保持して行動選択へ戻る。
- 行動選択のBACKまたはEscは予定だけを取り消し、経路を選び直す。
- 生存ユニットの通過、斜め移動、経路の再進入はできない。
- 移動なしのWAITは、人が操作する現在手番のユニットをダブルクリックしてACTIONから選ぶ。\
  戦闘画面本体に独立したWAITボタンはなく、それ以外の能動行動には1マス以上の移動が必要になる。\
  WAITを選ぶまで手番は進まず、BACKまたはEscで戻れる。\
  両陣営手動では現在手番の側を操作でき、非手番とCPUのユニットでは開かない。
- 別ユニットまたは手番一覧をクリックすると右側の詳細を調べられる。
- RESTARTは現在戦闘を破棄してBUILDへ戻る。

### 初期配置

通常のSTARTごとに新しいシードを選び、各陣営を2列3行の範囲へまとめる。\
両陣営は3マス以上の距離を保ち、全員に空いた上下左右の移動先を残す。\
両ステージで各陣営を左右対称に配置する。\
開始位置に特殊パネルは置かず、陣営間の距離を保つ。\
同じシードと構成なら初期位置とパネルは再現でき、戦闘中に生成し直さない。\
OPERATIONの小図は開始可能領域を表し、個別の出発点を固定しない。

### ステージ

| ステージ | 勝利条件 | 役割 |
| --- | --- | --- |
| INTERFERENCE | ENEMY全滅 | 基本戦闘と経路比較 |
| SEVERANCE | 敵Aを撃破 | 01を守り、02で敵Bを遮る |

いずれもPLAYER全滅で敗北する。
SEVERANCEは01の撃破でも直ちに敗北し、ENEMY全滅でも勝利する。
勝利と敗北が同じ判定時機に成立した場合は敗北を優先し、一度確定した結果は変わらない。
初期01はSPD30のランナー、02はCOREと装備のINF30を持つ迎撃役、03はRES30を持つ支援役である。\
標準戦の敵A、B、Cも同じ初期3構成で、配置は左右対称となる。
両陣営手動では指定対象を優先するか他の敵を攻撃するかもプレイヤーが選ぶ。

### パネルと位相

| 表示 | 効果 |
| --- | --- |
| 無印 / NORMAL | COREは維持 |
| ◇ / RESET | COREを本人の戦闘開始角へ戻す |
| ↷ / CLOCKWISE | COREを時計回りへSPD × 1.5度回転 |
| ↶ / COUNTERCLOCKWISE | COREを反時計回りへSPD × 1.5度回転 |

どのセルでもGEARは反時計回り、ARMSは時計回りへ、それぞれのSPD × 1.5度回転する。
特殊効果は経路の進入順にCOREだけへ作用する。
PANEL IGNOREを装備した本人は特殊CORE効果を無視し、GEARとARMSの通常回転は維持する。
赤はINF、緑はRES、青はSPD、黄はLUK、灰はVITを示す。
表示するINF/RES SYNCはベルカーブ適用後の効果補正であり、最大200%である。
生の重なり率、LUK補助後の中間値とは異なる。
SINGULARITYは生INFセクターが完全一致し、CORE:INFが10以下のときだけ成立する。

### ビルドと保存

COREを変更すると他の値を再配分し、全値1以上、合計100を維持する。
STANDARDとREVERSEはCOREの配置順を変える。
装備と開放した変異は全PLAYERで共有し、同じものを複数人へ装備できる。
新規のARMSとGEARは5値が各10以上の10刻みで合計100、各126種類である。
変異は配分と別の共通解放である。
スキルは最大3個、未設定も許可する。
DAMAGEとHEALは、それぞれ上下左右1、斜め1、上下左右2、斜め2マス先の対象1体へ作用する。
上下左右1の旧2種だけを初期開放し、追加6種とMOVE+1、下記の補助スキルは戦利品で取得する。
2マス先は正確な距離であり、途中の1マス先は含まない。
DAMAGEは敵、HEALは自分以外の負傷味方だけを対象とし、範囲が違っても威力と回復の計算は同じである。
取得後は両PLAYERで共有できる。
既存セーブの開放済みスキルはそのまま使え、追加品は自動解放や自動装備しない。
SWAP、PUSHとGUARDは移動後に攻撃や回復の代わりに選ぶ1行動である。
PANEL IGNOREと3種類のFIELDは装備中に作用する受動効果である。

| スキル | 対象と効果 |
| --- | --- |
| SWAP / ADJACENT | 上下左右の隣接味方1体と位置交換 |
| PUSH / ADJACENT | 上下左右の隣接敵1体を外側の空きセルへ1マス押す。無傷で盤外と連鎖押しは不可 |
| GUARD / SELF | 自分の次の攻撃被害を1回50%軽減。重複不可、0ダメージでも消費 |
| PANEL IGNORE / SELF | 装備した本人の特殊COREパネル効果を無視する受動効果 |
| SLOW FIELD / SURROUNDING | 周囲8マスの本人以外の装備回転を0.5倍にする |
| STOP FIELD / SURROUNDING | 周囲8マスの本人以外の装備回転を0倍にする |
| FAST FIELD / SURROUNDING | 周囲8マスの本人以外の装備回転を1.5倍にする |

SWAPの両者とPUSHの対象にも、到着先への通常1歩の回転と本人の受動を適用する。
押された相手の待ち時刻と移動数、HPは変えず、交換を全て確定してから両者の通常の進入ルールを適用する。
有効対象のホバーで到着先と変化後のリングを予測し、右の短いPREVIEW表示で現在状態と区別する。
GUARDの予測では消費せず、実際の次のDAMAGEだけで解除する。
移動や回復、手番の境界では残り、新しい戦闘で解除する。
防御中はHPとCOREの間に重ねた薄い八角形で確認できる。
盤面、手番一覧と予測へ同じ図形を使い、状態文と発動文字は加えない。
軽減率はgame/tuning.gdの調整値であり、BUILDと戦闘の説明にも反映する。

FIELDは生存発生源の斜めを含む周囲8マスで、自分を除く味方と敵の両方へ作用する。
各歩の着地位置でGEARとARMSの通常回転量だけに倍率を掛け、CORE、能力値と手番速度は変えない。
範囲外へ持続せず、発生源が移動しても立っている別ユニットの角度を変えない。
同種は何個あっても1回、STOPを優先し、STOPがなくSLOWとFASTが両方あれば通常x1へ相殺する。
SWAPとPUSHは全到着位置を先に決めてから同じ規則で1歩を適用する。
柔らかい雲が装備ユニットの周囲をゆっくり漂い、薄い破線の雲は移動後の予測を示す。
正確な作用は周囲8マスであり、セルのホバーで作用元と倍率を確認できる。
雲の動きで範囲や戦闘値は変わらない。
スキルの短い説明はBUILDと戦闘の情報欄で確認できる。
GUARDの自分対象では四辺の対象枠を重ねず、従来の四隅フォーカスと設定アクセント色の明瞭な八角形を使う。


装備の型番の下には5ステータスを十進表示する。\
選択を開くと現在と候補の実リングと数値を比較でき、APPLYで確定、CANCELとEscで取り消す。\
装備は能力値の下限で絞り込め、上下キー、HomeとEnd、スクロールで候補を移動する。\
未解放の装備と変異、スキルも非活性で確認できる。\
CLASS、変異、スキルとOPERATIONも同じ操作で選ぶ。

SAVEはビルド、開放一覧、ステージを作業先のartifacts/runtime/phase-save.jsonへ保存する。
再保存時は元のファイルを別名の.backup.jsonとして残す。
起動時に既存プロフィールを復元し、LOADでも明示的に読み直せる。\
破損や未知の版は拒否し、読込元へ新規状態を上書きしない。\
戦闘途中のセーブはなく、初回作成以外の自動保存は行わない。

#### 初回プロフィールとWeb

新規プロフィールは固定初期装備を維持し、ARMSとGEARを追加で各5種開放する。\
各能力が単独最大の候補から1種ずつ選び、似た配分だけへ偏らないようにする。\
初めてのBUILDでは、今回の追加品だけをカテゴリ別に表示し、CLOSEまたはEscで通常BUILDへ戻る。\
既存の有効な保存があれば起動時に復元し、追加抽選と自動上書きを行わない。\
初回以外の編集と報酬の保存はSAVE、復元はLOADを使う。

Web Demoは同じ初期化、構成、収集と戦闘を使い、ゲームと設定をタブ内のメモリだけで保持する。\
SAVEとLOADは表示したまま非活性となり、内部からの保存と読込も拒否する。\
同じページ内の再戦と画面切替では構成、解放と設定を保ち、再読み込みと終了では失われる。\
通常版はdemoタグを付けず、これまでのファイル保存と読込を使う。\
コードを書き換える必要はない。

#### HTMLの書き出し

1. `/Users/glitch/Developer/phase/project.godot`をGodotで開く。
2. `エディター > エクスポートテンプレートの管理...`を開き、Godot 4.7.2の`Web Single-Threaded`がInstalled Templatesにあることを確認する。\
   このMacでは導入済みである。\
   未導入のMacだけ、Official Releases mirrorから同じ版のWeb Single-Threadedを導入する。
3. `プロジェクト > エクスポート...`で左の`Web Demo`を選ぶ。\
   一覧が空なら、いったん閉じて`プロジェクト > 現在のプロジェクトを再読み込み`を選んでから開き直す。\
   `機能`タブのカスタムは`demo`、`オプション`のThread SupportとExtensions Support、PWAはOFF、Custom HTML Shellは`res://web/session.html`のままにする。
4. `プロジェクトのエクスポート...`を選び、Export With DebugをOFFにして`artifacts/runtime/web/index.html`へ書き出す。\
   デバッグOFFではUNLOCK ALLは表示されない。\
   `PCK/Zipのエクスポート...`はHTML一式を作るボタンではない。
5. 同じフォルダに出たHTML、JS、WASM、PCK等をまとめて保つ。HTMLだけを移動したり、生成後に一部だけ改名したりしない。

このMacでは同じプリセットを使った次のコマンドからHTML一式の出力を確認した。\
画面の`プロジェクトのエクスポート...`が押せない場合も、このコマンドを使える。

~~~sh
cd /Users/glitch/Developer/phase
mkdir -p artifacts/runtime/web
/Applications/Godot.app/Contents/MacOS/Godot --headless --path . --export-release "Web Demo" artifacts/runtime/web/index.html
~~~

#### ローカルブラウザでの確認

HTMLをダブルクリックするfile://ではなく、localhostのHTTP経由で開く。\
以下はPython 3が使えるターミナルで実行し、そのまま起動しておく。

~~~sh
cd /Users/glitch/Developer/phase
python3 -m http.server 8060 --bind 127.0.0.1 --directory artifacts/runtime/web
~~~

サーバーのターミナルは開いたまま、ブラウザのアドレス欄へ`http://127.0.0.1:8060/`を入力する。\
WebAssemblyとWebGL 2.0が必要で、音は最初のクリック後に確認する。\
確認後はターミナルでCtrl+Cを押してローカルサーバーを終了する。\
日本語の字形は同梱フォントで補い、英語とmacOSの既存フォントの優先順は維持する。\
更新前のページを開いたままの場合は、再読み込みして新しいPCKを取得する。

- 初回の装備解放一覧を閉じ、SAVEとLOADが見えるが押せないことを確認する。
- 名前と装備を1つずつ変更し、SETTINGSの言語かSEも変更する。
- 戦闘からBUILDへ戻り、変更が残っていて初回一覧が繰り返されないことを確認する。
- ページを再読み込みし、変更した構成と設定が初期状態に戻り、初回一覧が再表示されることを確認する。抽選結果が違うことだけを初期化の根拠にしない。

#### 配布先へ渡すファイル

[itch.ioの公式案内](https://itch.io/docs/creators/html5)では、index.htmlを直下に含む出力一式のZIPを使う。\
[unityroomの公式案内](https://help.unityroom.com/Godot-Engine-381dc3ed5de980b2a573ccfe415feb52)では、Web出力のPCKを選ぶ。\
どちらも同じWeb Demo設定とdemoタグを使うが、unityroomではホスト側のHTMLとエンジンを使うため、こちらのカスタムHTMLシェルは適用されない。\
ゲームと設定の非永続処理、保存拒否はPCK内の共通コードでも有効となる。\
各ホストでの実動作はアップロードせずには確認できないため、公開前の確認対象とする。\
この手順はローカル書き出しと確認までとし、登録、アップロードと公開は行わない。

### デバッグの全解放

Godotエディターからの実行、またはデバッグ書き出しでは、BUILD上段のUNLOCK ALLトグルをONにして一時的な全解放へ入れる。\
ARMSとGEAR各126配分、NORMALを含む120変異、全16スキルを新規の検証用データで試せる。\
通常の3スキル枠と装備の共有規則は同じであり、装備と変異の長い選択肢はスクロールまたは上下キーで選ぶ。

全画面のDEBUG / NOT SAVEDが目印となる。\
SAVEとLOADは無効となり、戦闘結果の戦利品は発生せず、色設定の適用もメモリ内だけである。\
RESTARTは全解放を続け、BUILDのUNLOCK ALLをOFFにして元の所持品、構成、ステージと表示設定へ戻る。\
再びUNLOCK ALLを選ぶと新規の検証用構成となる。\
リリース書き出しでは入口を表示せず、直接呼び出しても開始できない。

ニューゲーム前提の変更であり、既存ファイルの変換と削除は行わない。\
検証時は保存先をartifacts/runtimeの検証専用ファイルへ差し替え、実ユーザーのセーブと設定を保護する。

### 表示設定

HELPはステータスの表、移動前後の位相比較、戦闘後のランダム解放だけを英日で説明する。
SETTINGSでウィンドウとフルスクリーンを切り替え、現在のモードを確認できる。\
SE ONとSE OFFは全効果音へ即時に反映し、次回起動でも維持する。\
未指定はONで、音だけの設定をartifacts/runtime/ui-settings.json.audio.jsonへ保存する。\
全解放中は保存せず、終了すると元の選択へ戻る。
1920x1080の内容全体を16:9のまま画面へ合わせ、異なる縦横比では上下または左右に余白を置く。
RetinaでもOSの倍率を重ねず、文字と盤面とリングとオーバーレイを同じ比率で拡縮する。

Godotから実行して全画面でも小さい場合は、ゲームビューの右上のメニューでFixed SizeからKeep Aspect Ratioへ変更する。
この作業先はプロジェクト別の生成メタデータで変更済みだが、.godotを作り直した場合や新規インポート時は選び直す。
ゲームバーの表示寸法がウィンドウの拡大に応じて増えることを確認する。
今回の実画面では固定の1440x810から4442x2499へ増えた。

埋め込み中は外側のゲームビューを拡大する。
ゲーム内SETTINGSのFULLSCREENを使う場合は、Embed Game on Next Playを無効にして再実行するか、上記のgodot --pathコマンドで独立実行する。
これは[Godotの埋め込み表示の制約](https://docs.godotengine.org/en/stable/tutorials/editor/game_embedding.html)である。
表示と入力の検証結果は[表示追従の記録](artifacts/display-verification.md)を参照する。

ゲームの保存はそのディレクトリを使用しない。
スクリプトエラーやテスト失敗は検査を失敗させ、既知のホスト権限警告とは区別する。

## 配色とUI

minimal dark intelligenceを方針とし、黒い面、位相リング、4波形、HPと同期の棒で情報を伝える。
装備の5値と型番、現在と候補の比較、効果量と符号を確認できる。
SETTINGSでDEFAULT、AMBER、ICEを選ぶか、6個の色見本でアクセントと5ステータス色を編集する。
APPLY COLORSで適用し、CLOSEまたはEscでは未適用の配色を取り消す。
暗すぎる色や区別しづらいステータス色は理由を表示して拒否する。
UI設定はartifacts/runtime/ui-settings.jsonへ保存し、既存設定はbackup付きで退避する。
ビルド保存とは独立しており、SAVEとLOADの操作は従来どおりである。
TabとShift+Tabは最前面の操作部品を移動し、Enterで実行する。
Lucideの出典とISCおよびFeather由来MITの権利表示は[NOTICE](assets/lucide/NOTICE.md)と[LICENSE](assets/lucide/LICENSE)にある。

UIだけを再現する検証ラボは次で起動する。
戦闘難易度を検証するモードではなく、本体の起動シーンにも組み込まれない。

~~~sh
godot --path . --script tests/visual_lab.gd --resolution 1440x810
~~~

F2は勝利と0件、F3は敗北と2件の表示fixture、F4は回復対象、F5は攻撃対象、F6は行動選択、F10はartifacts/runtimeへの画面保存である。
表示確認ではラボ専用の配色設定を使い、通常のビルドセーブには触れない。
