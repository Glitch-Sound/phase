# battle-interface Specification

## Purpose

一画面の予測情報と明確な入力案内によって移動と位相の関係を理解できるようにし、ビルドから結果までの操作を完結させる。

## Requirements

### Requirement: REQ-017 - オーバーレイ循環

ゲームは起動時に戦闘画面へBUILDを重ね、BATTLE、RESULT、BUILDを反復し、結果へ勝敗と新開放一覧を表示しなければならない(SHALL)。

#### Scenario: REQ-017-S01 - 一巡

- **GIVEN** ゲーム起動直後
- **WHEN** ビルドから戦闘を開始し勝敗を決めて戻る
- **THEN** BUILD、戦闘、結果、BUILDの順に表示される

### Requirement: REQ-018 - 経路入力表示

画面は経路番号、ユニットのリングと重ならないノード間の線、設定したアクセント色の終点、対象範囲、有効対象、選択、ホバーを表示し、パネル効果は文字の略号でなく意味の異なるアイコンで示し、ホバーとHELPで意味を確認でき、HELPで最終セルのダブルクリックを知らせなければならない(SHALL)。

#### Scenario: REQ-018-S01 - 経路操作

- **GIVEN** 移動状態の戦闘画面
- **WHEN** 経路追加、取消、ダブルクリック、対象選択を操作する
- **THEN** 番号と終点が追随し、行動選択とBACKが動作する

#### Scenario: REQ-018-S02 - 経路とリングの分離

- **GIVEN** ユニットから上下左右へ進む経路と、最小、標準、拡大された表示領域
- **WHEN** 経路を表示する
- **THEN** 線の端は起点や終点にあるユニットの記号の外側にあり、線幅を含めて色リングとHP円弧や目盛りに重ならず、経路番号と終点は維持される
- **AND** 線を引ける余白がない区間や長さ0の区間では線を描かず、経路や戦闘状態は変更しない

#### Scenario: REQ-018-S03 - パネルのアイコンと確認

- **GIVEN** SHIFT、LOCK、REVERSEとNORMALのパネル
- **WHEN** 盤面を表示して効果を調べる
- **THEN** 特殊パネルには順に早送り、錠前、反時計回りのアイコンを表示し、S+、L=、R-の略号は残さず、NORMALには効果アイコンを表示しない
- **AND** ホバーとHELPでARMSの回転2倍、GEAR固定、ARMS逆回転の対応が分かり、HELPで現在の配置シードを読める
- **AND** 最小と拡大でアイコンを区別でき、ホバーの確認は経路、対象とクリックを妨げない

### Requirement: REQ-019 - 情報と位相予測

画面はHP陣営合計、行動順ごとに等間隔の独立した点と相対進捗の白い円弧を持つ縦の時間軸と左右の現在状態、選択ユニットの必要な識別情報と全スキル、経路後リングと周囲の円形の揺らぎ、特異点を表示し、陣営ごとのHP数値とバーを同じ段へ収め、情報を囲う装飾を省きながら操作状態を区別できなければならない(SHALL)。

#### Scenario: REQ-019-S01 - 情報の比較

- **GIVEN** 異なる位相になる2経路
- **WHEN** 経路を切り替えて別ユニットを調べる
- **THEN** 予測は手番ユニットを維持し、右詳細は選択ユニットへ切り替わり、円形の揺らぎが配分と位相を反映し、GとAの角度数値、横長波形と角度軸、下端のROUTEからEFFECTへの記載は表示しない

#### Scenario: REQ-019-S03 - 指定文字の非表示

- **GIVEN** 戦闘画面の移動、行動選択、攻撃対象、回復対象、結果の背後のいずれか
- **WHEN** 画面を表示する
- **THEN** 次の文字を表示せず、時間軸、経路の描画と移動、円形予測と特異点、詳細情報と通知の機能を維持し、配置は盤面優先の寸法要件に従う

| 除去する表示 | 範囲 |
| --- | --- |
| PHASE PREVIEW | 見出し |
| PATH X / DESTINATION | 経路長と目的地座標を含む表示全体 |
| ROUTE / PHASE / EFFECT | 左上の補助見出し |
| TURN ORDER | 見出し |
| T / 現在時刻 | 数値を含む表示全体 |
| INSPECT | 見出し |
| INNER / MIDDLE / OUTER | 補助見出し |
| PHASE / TACTICAL STUDY | 左上の説明文字 |
| BOTH SIDES / HUMAN | 右上の説明文字 |
| TURN / 現在ターン番号 | 数値を含む表示全体 |
| 行動順の待ち量とACTING、QUEUED | 選択とホバーを含む状態文全体。FINISHEDとDEFEATEDも同領域には表示しない |
| INFとRESの最終同期率 | 予測下の2つの数値表示。代替表示を追加しない |

#### Scenario: REQ-019-S04 - 情報の囲い装飾を省く

- **GIVEN** 戦闘画面の情報と予測が表示されている
- **WHEN** 移動、行動選択、対象選択、結果の背後を表示する
- **THEN** 左右の情報と円形予測、時間軸の全状態、スキル行を囲う外枠と薄い背景を表示せず、情報の内容、同時刻の処理順、既存の文字色とリング、陣営HPの棒を維持し、新しい囲いや装飾を加えない
- **AND** 中央バトルマップ、システムメニューと操作ボタンの通常、選択、ホバー、フォーカスの表現と機能は変わらない

#### Scenario: REQ-019-S05 - HPの1段表示

- **GIVEN** PLAYERとENEMYのHP合計
- **WHEN** 戦闘情報を表示する
- **THEN** 各陣営の名前、現在と最大のHP数値、比率のバーが同じ横の段に収まり、欠けずに読める

#### Scenario: REQ-019-S06 - 待ち量と処理順

- **GIVEN** 行動中ユニットの時刻が現在で、同時刻、近接時刻、同ユニットの再登場がある
- **WHEN** 行動順を表示する
- **THEN** 上から行動順に等間隔で1行動1点を置き、同時刻も個別の点に分かれ、各点は1体だけへ接続し、中央にユニット名を表示しない
- **AND** 同時刻は1、2、A、Bの処理順で並び、同ユニットの再登場も別の点を持ち、白い円弧は1から表示中の最大待ち量に対する残り待ち量の比を引いた相対進捗、残る灰は待ち量を表し、待ちが減るほど白が増える
- **AND** 最大待ち量が0なら全点を白一周とし、最大待ち量が変わると同じ基準で再計算し、個別周期の経過率や実時間と誤認させない
- **AND** 待ち0の白一周でも先頭の中心点で現在手番を識別し、同時刻の後続点は順番待ちとして扱い、状態文や待ち量数値の代替を追加しない

#### Scenario: REQ-019-S07 - 現在状態との対応と独立した選択

- **GIVEN** 未確定経路と左右の状態、未来の節点がある
- **WHEN** 状態か節点をホバーして選択する
- **THEN** 左の味方1と2、右の敵AとBの現在のリング、HPと補正率を該当節点へ接続し、対応状態と盤面ユニットを強調して詳細を切り替える
- **AND** 手番、経路、予測は変えず、未来のHPや位相を現在状態として捏造しない

#### Scenario: REQ-019-S08 - 予定の更新と終了

- **GIVEN** 撃破、行動後の再投入、戦闘終了のいずれかが発生する
- **WHEN** 行動順を再表示する
- **THEN** 撃破したユニットの節点を除き、行動後は新しい現在と待ち量に更新し、終了後は未来の予定を表示しない

#### Scenario: REQ-019-S09 - 右情報の整理

- **GIVEN** 通常または突然変異を持つ選択ユニット
- **WHEN** 右の情報を表示する
- **THEN** 現在のリングと中央名、CLASS、移動上限、全スキル、NORMAL以外のGEARとARMSの突然変異を表示する
- **AND** 陣営名、重複するHP数値、移動済み数、15個の配分数値と棒、型番、NORMALとACTIVE、PASSIVEの反復を表示せず、右情報と盤面の間に余白がある

### Requirement: REQ-020 - システム操作

画面はHELP、SETTINGS、RESTART、QUITを備え、HELPで操作を説明し、設定でウィンドウとフルスクリーンを切り替え、戦闘中は4つをこの順の2列2段で盤面右下へ置き下端を盤面と揃え、RESTARTでBUILDへ戻らなければならない(SHALL)。

#### Scenario: REQ-020-S01 - システムメニュー

- **GIVEN** 起動したゲーム
- **WHEN** 各メニューを操作する
- **THEN** HELPが開閉し、表示モードが変わり、RESTARTでBUILDに戻り、QUITで終了する
- **AND** 戦闘ではHELPとSETTINGS、RESTARTとQUITの2列2段で盤面右下へ並び、下端が盤面と揃い、BACKとWAITに重ならない

### Requirement: REQ-021 - 効果フィードバック

WHEN 効果が実行されるとき、画面はダメージをINF色の負数、回復をRES色の正数(既定は赤と緑)、撃破をDEFEATEDとして対象付近から上昇しフェードする表示にしなければならない(SHALL)。

#### Scenario: REQ-021-S01 - 効果表示

- **GIVEN** 負傷と撃破と回復が起こる戦闘
- **WHEN** それぞれのスキルを使用する
- **THEN** HP変化と対応する符号、色、DEFEATEDを表示する

### Requirement: NREQ-001 - 画面寸法

Godot 4.7系の1920x1080基準画面はアイコン以外の画像を使わず左右の情報と円形予測とシステムメニューを保って中央マップを可能な限り大きくし、周囲の情報と盤面に適切な余白を設け、10x10マップの70x70論理セルを同じ倍率で正方形に拡大して全ユニットをセル内に収め、ウィンドウとフルスクリーンの表示領域へ16:9を維持して中央で最大限拡縮し、高DPIでも文字とリングとオーバーレイを同じ比率で鮮明に表示しなければならない(SHALL)。

#### Scenario: NREQ-001-S01 - 基準レイアウト

- **GIVEN** 1920x1080と1440x810ウィンドウ
- **WHEN** 各画面を表示する
- **THEN** マップ全体、右情報、下部予測、システムメニューが重ならず操作できる

#### Scenario: NREQ-001-S02 - 表示領域への追従

- **GIVEN** Godot 4.7系で16:9の縮小と拡大、4:3、横長、縦長の表示領域
- **WHEN** 表示領域の寸法を変更して元へ戻す
- **THEN** 1920x1080の内容全体が歪まず中央へ収まり、拡大したセルは正方形を保ち、余白は左右または上下に1物理ピクセル以内の差で等分され、元の寸法と倍率へ戻る

#### Scenario: NREQ-001-S03 - 全画面と高DPIの実表示

- **GIVEN** macOSの高DPI環境で起動したゲーム
- **WHEN** ウィンドウ、全画面、異なる縦横比を実際に表示する
- **THEN** 盤面と文字とリングとオーバーレイが表示領域へ追従し、周囲の余白とクリック対象が見た目に一致する

#### Scenario: NREQ-001-S04 - 盤面優先の配置

- **GIVEN** 最小、標準、拡大された表示領域
- **WHEN** 戦闘を表示して盤面と情報とメニューを操作する
- **THEN** 正方形の盤面が右下のメニューに縮小を強いられず、右情報との余白を持ち、左右の情報、円形予測、通知と操作部品が盤面に重ならず画面内へ収まり、表示とクリック位置が一致する

### Requirement: REQ-025 - 対象効果量の視認性

WHILE 対象選択の間、マップは攻撃と回復の効果量を対象セル内に完全に収め、他セルの背景より後に描き、最下行以外も符号と数字を読めるようにしなければならない(SHALL)。

#### Scenario: REQ-025-S01 - 通常行と最下行

- **GIVEN** 通常行と最下行に有効な攻撃または回復対象がいる画面
- **WHEN** 対象選択を表示する
- **THEN** 効果量の表示領域はセル内にあり、後続セルによって隠れない

#### Scenario: REQ-025-S02 - 実画面の数字

- **GIVEN** 最下行以外の攻撃対象と回復対象
- **WHEN** 対象選択を実画面で行う
- **THEN** 負のダメージと正の回復量の符号と全桁を読める

### Requirement: REQ-027 - 拡縮時の入力

WHEN 拡縮された画面で操作するとき、ゲームはマウスイベントを描画と同じ座標系で判定し、余白で盤面を操作せず、フォーカス喪失中は盤面入力を無視し、復帰後も経路とGUIを操作可能にしなければならない(SHALL)。

#### Scenario: REQ-027-S01 - クリックとGUI

- **GIVEN** 縮小、拡大、余白付きの戦闘とBUILD
- **WHEN** セル、終点ダブルクリック、GUIボタン、余白をクリックする
- **THEN** 見た目どおりのセルとGUIだけが反応し、余白では経路と選択が変わらない

#### Scenario: REQ-027-S02 - フォーカス復帰

- **GIVEN** 経路選択中のゲーム
- **WHEN** フォーカスを失って戻す
- **THEN** 喪失時のホバーを消し、非アクティブ中の盤面入力では状態が変わらず、復帰後に経路とGUIを続けて操作できる

### Requirement: REQ-028 - 配色設定

WHEN 利用者が設定で配色を適用するとき、ゲームはアクセントと5ステータス色を全画面へ反映し、文字と背景のコントラストが基準に満たない色と区別できないステータス色を拒否し、取消時は現在の配色と未確定経路を維持しなければならない(SHALL)。

#### Scenario: REQ-028-S01 - 有効な配色

- **GIVEN** 移動経路を選択中のゲーム
- **WHEN** プリセットまたは6色の個別調整を適用する
- **THEN** アクセントと5色がリング、円形の揺らぎ、数値、操作部品へ反映され、経路と戦闘状態は変わらない

#### Scenario: REQ-028-S02 - 判読できない配色

- **GIVEN** 現在の配色でゲームを表示中
- **WHEN** コントラスト不足または同色のステータスを含む配色を適用する
- **THEN** 理由を表示し、現在の配色を変更しない

#### Scenario: REQ-028-S03 - 配色の取消

- **GIVEN** 設定の配色を編集中
- **WHEN** 閉じるまたはEscで取消する
- **THEN** 編集前の配色、経路、対象選択を維持する

### Requirement: NREQ-002 - 静かな情報階層

BUILD、BATTLE、行動選択、RESULT、HELP、SETTINGSはGodot 4.7系の1920x1080基準と1440x810表示で深い黒の一貫したUIを表示し、走査線とランダムな装飾を用いず、操作用のLucideアイコンに意味の分かるラベルを添え、パネル効果は盤面の略号を省いてホバーとHELPで説明し、選択とフォーカスと勝敗を形または文字でも区別し、モーダル内でキーボードフォーカスを循環させ、閉じたら元の操作へ戻し、既存の戦略情報を保持しなければならない(SHALL)。

#### Scenario: NREQ-002-S01 - 全画面の実表示

- **GIVEN** 既定色と変更した配色のゲーム
- **WHEN** BUILD、BATTLE、行動選択、RESULT、HELP、SETTINGSを表示する
- **THEN** 黒基調の共通表現となり、アイコンの操作ラベル、選択枠、フォーカス枠、勝敗文字、HP、装備5値、位相予測を読める

#### Scenario: NREQ-002-S02 - アイコン同梱

- **GIVEN** プロジェクトをオフラインで起動できる環境
- **WHEN** 操作部品を生成する
- **THEN** 同梱したLucideアイコンとラベルを表示し、出典とISCおよび該当するMITの権利表示を配布物に含める

#### Scenario: NREQ-002-S03 - モーダルのフォーカス

- **GIVEN** BUILD、HELP、SETTINGS、行動選択、RESULTのいずれか(フォーカス復帰後を含む)
- **WHEN** TabとShift+Tabで操作部品を移動する
- **THEN** 表示中モーダルの有効な部品だけにフォーカスが移り、補助画面を閉じると元の操作部品へ戻る

### Requirement: REQ-029 - 中央マップ周辺の文字

WHILE 戦闘盤面が表示される間、画面は中央マップ周辺の操作説明、ステージ名、ゲームモード名、座標数字、勝利条件文を表示してはならない(SHALL NOT)。

#### Scenario: REQ-029-S01 - 状態とステージの切替

- **GIVEN** 戦闘盤面が表示されるゲーム
- **WHEN** 以下の表示へ切り替える
- **THEN** 中央マップ周辺に指定した5種の文字を表示しない

| ステージ | 表示状態 |
| --- | --- |
| INTERFERENCE | 移動 |
| SEVERANCE | 移動 |
| BREACH | 移動 |
| ANCHOR | 移動 |
| INTERFERENCE | 行動選択 |
| INTERFERENCE | 攻撃対象選択 |
| INTERFERENCE | 回復対象選択 |
| INTERFERENCE | 閉塞してWAIT可能 |
| INTERFERENCE | RESULTの背後 |

### Requirement: REQ-030 - ユニットの円弧表示

画面はユニットを外枠のない細いCORE、GEAR、ARMSの3リング、領域間の隙間、内側の純白のHP円弧、中央の名前で表示し、HP比率、位相、設定色、選択状態を判別可能にし、盤面の記号をセル中央に収めなければならない(SHALL)。

#### Scenario: REQ-030-S01 - 共通の構造

- **GIVEN** 盤面、予定手番、詳細、予測、BUILDのユニット
- **WHEN** ユニットを表示する
- **THEN** CORE、GEAR、ARMSの順で内から外へ細い色付き円弧を表示し、各領域の境目に隙間があり、外周を囲む枠線がなく、名前が中央にある

#### Scenario: REQ-030-S02 - HPの増減と境界

- **GIVEN** 最大HPが100のユニット
- **WHEN** HPを表示する
- **THEN** 3リングの内側の純白の円弧が配色に依存せず次の比率を表し、名前と他の線の色は変わらない

| HP | 円弧の比率 |
| --- | --- |
| 0 | 0% |
| 50 | 50% |
| 89 | 89% |
| 100 | 100% |

#### Scenario: REQ-030-S03 - 実表示での判別

- **GIVEN** 味方と敵、選択と非選択、既定色と変更色、最小ウィンドウと基準画面
- **WHEN** Godotでユニットを表示する
- **THEN** 3リングの境目、白いHP円弧、中央の名前、選択状態を区別でき、ユニット記号はセル内に収まる

#### Scenario: REQ-030-S04 - セル中央への配置

- **GIVEN** 境界セルと隣接セルにいるユニット
- **WHEN** 盤面のユニットを表示する
- **THEN** 各記号の中心はセルの幾何学的な中央に一致し、色リング、HP、名前、目盛りはそのセル内に収まり、隣接セルへ重ならない

### Requirement: REQ-031 - 味方の表示名

画面は内部ID01、02の味方の表示名を1、2とし、敵のA、B、ステージ番号、内部ID、保存内容、目標の判定を変更しないようにしなければならない(SHALL)。

#### Scenario: REQ-031-S01 - 表示と識別子の分離

- **GIVEN** 内部ID01、02、A、Bを持つユニット
- **WHEN** 名前を表示する
- **THEN** 表示名はそれぞれ1、2、A、Bとなり、内部IDは元のままである

#### Scenario: REQ-031-S02 - 関連画面の名前

- **GIVEN** BUILD、BATTLE、ACTION、HELPのユニット名と目標の説明
- **WHEN** 画面を切り替える
- **THEN** 味方への参照は1、2で統一され、ステージ番号01と02は維持される

### Requirement: REQ-032 - リング配色の強調

画面は有効な配色を表示するとき、組み込みプリセットと6色すべてが一致する配色の3リングだけを同じ色相と明度で高彩度にし、それ以外のカスタム配色は指定RGBのまま使い、他UIの色、HPの白色、形状と保存内容を変更せず、色設定でこの違いを知らせなければならない(SHALL)。

#### Scenario: REQ-032-S01 - 組み込み配色

- **GIVEN** DEFAULT、AMBER、ICEのいずれかと6色が完全に一致する配色
- **WHEN** リングを表示する
- **THEN** VIT、INF、RES、SPD、LUKの色相と明度を維持して彩度を高め、CORE、GEAR、ARMSの色分類を同じに保ち、配色の判読性と区別の基準を満たす

#### Scenario: REQ-032-S02 - カスタムの保持

- **GIVEN** アクセントだけが異なる場合を含め、組み込み配色と6色が完全一致しない有効な保存済み配色
- **WHEN** 配色を読み込んで表示する
- **THEN** リングは指定した5色のRGBと完全一致し、入力配色と保存ファイルの全内容は変わらない

#### Scenario: REQ-032-S03 - 設定との接続

- **GIVEN** 未確定経路を持つゲームと色設定
- **WHEN** 組み込み配色とカスタム配色を明示的に適用する
- **THEN** リングだけが配色の種類に応じた表示になり、他UIは指定した基本色、経路と戦闘状態は元のままで、設定画面にプリセット強調とカスタム色保持の説明がある

#### Scenario: REQ-032-S04 - 黒い背景での実表示

- **GIVEN** 既定と変更したプリセット、カスタム配色のゲーム
- **WHEN** 盤面、TURN ORDER、詳細、プレビュー、BUILDを表示する
- **THEN** 異なる背景と大小の記号でも3リングの色分類と白いHPを区別でき、形状、線幅、配置を維持する

### Requirement: REQ-033 - 円形の位相予測

WHILE 経路後の位相を予測する間、画面は3リングを維持して周囲へCORE、GEAR、ARMSと最終重なりの4輪郭を共通の半径付近で重ねて表示し、実際の領域境界の色をグラデーションで接続し、実際の配分と回転に沿う色分類と形、同じステータスの一致が多いほど鮮明な色で局所的な重なりを表し、時間や乱数で変形させず、戦闘式と保存内容を変更せずに経路と配色へ追随しなければならない(SHALL)。

#### Scenario: REQ-033-S01 - 局所的な一致

- **GIVEN** 各ステータスが20ずつの3リング
- **WHEN** VIT領域の中央に相当する同じ角度を表示する
- **THEN** 位相の組み合わせに応じて次の重なりとなり、一致が多いほど結果の色が鮮明になり、不一致の輪郭も黒背景から区別できる

| COREの位相 | GEARの位相 | ARMSの位相 | 重なり |
| --- | --- | --- | --- |
| 0 | 0 | 0 | 3つのVITが一致 |
| 0 | 0 | 72 | COREとGEARのVITだけが一致 |
| 0 | 72 | 144 | 同じステータスの一致がない |

#### Scenario: REQ-033-S02 - 決定的な更新

- **GIVEN** 有効な配分と突然変異、回転角、カスタム色を持つ予測
- **WHEN** 予測を表示する
- **THEN** 全周の色分類と形が実際の領域を反映して閉じ、同じ入力では同じ4輪郭になり、経路と配色の変更時に更新され、入力の状態と保存は変化しない

#### Scenario: REQ-033-S03 - 実表示の比較

- **GIVEN** 一致する位相とずれた位相、既定と変更した配色、基準と最小の画面
- **WHEN** Godotで予測を比較する
- **THEN** 内側の3リングとHP、周囲の4輪郭を区別でき、リング下のINFとRESの最終同期率は表示せず、拡大マップと左右の情報が重ならず、経路の選択と対象への操作を続けられる

#### Scenario: REQ-033-S04 - 重なる輪郭と境界の連続色

- **GIVEN** 同じステータス配分で一致または不一致となる位相と有効な配色
- **WHEN** 円形予測を表示する
- **THEN** 4輪郭が近い半径で重なり、各色領域の中央では指定色を保ち、境界では隣接する実際の色へ連続的につながり、完全一致の輪郭は不一致より鮮明で、同期率と戦闘状態を変えない
