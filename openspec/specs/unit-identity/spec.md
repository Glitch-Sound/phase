# unit-identity Specification

## Purpose

編集する名前と戦闘の不変識別子を分離し、同じ文字列から端末と起動をまたいで再構成できる小さな円形紋章を提供する。
入力と保存、表示の契約を一貫させ、同名でも戦術操作を保つ。

## Requirements

### Requirement: REQ-047 - 名前の入力規約

WHEN 名前を入力するとき、版1の規約はUnicodeを受け付け、定義済みの空白をASCII空白へまとめて前後を除き、制御と方向制御の文字を除去し、先頭32コードポイント以内へ制限して末尾空白を除き、大文字小文字とUnicode合成を変えず、空欄は枠の既定名として解決し、名前を装飾構文として解釈してはならない(SHALL NOT)。

#### Scenario: REQ-047-S01 - 正規化と境界

- **GIVEN** 日本語と結合文字、前後と連続空白、改行と制御、空欄、32文字を超える名前と装飾記号
- **WHEN** 名前を正規化して表示と保存へ渡す
- **THEN** 固定規約の同じ文字列が得られ、先頭32コードポイントを超えず、空欄は対応枠の既定名となり、装飾記号はプレーンテキストとして残る

### Requirement: REQ-048 - 版付きの円形紋章

WHEN ユニットの紋章を表示するとき、解決した名前を版1の固定接頭辞とUTF-8でSHA-256へ渡し、固定の幾何生成規約から円内の少数の対称な形を得て、端末、時刻、乱数とフォントに依存せず再構成可能にし、紋章を識別子または唯一性の保証として使ってはならない(SHALL NOT)。

#### Scenario: REQ-048-S01 - 固定ベクトルと幾何

- **GIVEN** 英語と日本語の固定名と同じ名、同じ版
- **WHEN** ハッシュと紋章を再構成する
- **THEN** 固定ベクトルと同じハッシュと幾何パラメーターとなり、全点が円内に収まり、入力と戦闘を変更せず、別起動と異なる保存経路でも同じ結果となる

#### Scenario: REQ-048-S02 - 小さい紋章の実描画

- **GIVEN** 味方と敵、最小と基準画面、異なるHPと位相、GUARDと攻撃回復
- **WHEN** BUILDと盤面、タイムラインと詳細、予測を実描画する
- **THEN** 名前に対応する同じ紋章を識別でき、円内の余白を保ち、陣営と枠、明るいHPと位相、手番と既存演出を覆わず、長い名前を盤面へ展開しない

### Requirement: REQ-049 - 名前の編集プレビュー

WHEN BUILDで編集可能なPLAYER枠を選ぶとき、コンパクトな名前欄と即時の紋章プレビューを使え、通常の明示SAVEとLOADで枠ごとの名前と方式の版を保存し、同名と一時全解放の編集を独立させ、未編集の敵には固定名を与えなければならない(SHALL)。

#### Scenario: REQ-049-S01 - 編集と取消と保存境界

- **GIVEN** 3つの編集枠、同名と長い入力、一時全解放と通常データ
- **WHEN** 入力し、EnterとTabで確定、Escで現在の編集を戻し、隔離先へ保存と別起動の読込を行う
- **THEN** 編集中は同じ枠のプレビューだけが即時に変わり、Escは編集開始時の値へ戻し、確定値だけを現行形式で復元し、通常と一時の名前を混ぜず、キー入力を盤面と別モーダルへ漏らさない

#### Scenario: REQ-049-S02 - 名前欄と長い表示の実描画

- **GIVEN** 初期名と架空の日本語、長い名前、標準と最小サイズ
- **WHEN** BUILDで入力し、戦闘とHELPへ遷移して選択する
- **THEN** 名前と紋章の対応、入力とキーボードフォーカス、取消と紋章だけの戦闘識別を確認でき、通常の編集と戦闘のクリック領域を塞がない

### Requirement: REQ-050 - アセンブリの表示規約

WHEN アセンブリの表示設定を使うとき、ゲームはユニット名と同じ固定のUnicode処理と空欄の既定名を使い、別の固定接頭辞とUTF-8、SHA-256、版付きの幾何規約からユニットとは異なる太めの紋章を安定に生成し、設定色を読みやすいパレットの安定キーで表し、既存キーと選択済みの色を維持して新規とCPUには陣営別の既定を使い、同色と同紋章を許して衝突回避のために選択した形と色を変更せず、識別と戦闘に設定を使ってはならない(SHALL NOT)。

#### Scenario: REQ-050-S01 - 安定した規約と独立性

- **GIVEN** 同じUnicode名と版、異なる保存先と色、同名の両陣営
- **WHEN** アセンブリとユニットの紋章を構成する
- **THEN** 固定ベクトルと同じアセンブリ図形が得られ、色によって形を変えず、既存ユニット紋章の版1の504形は不変であり、陣営と手番、CPUの判断へ影響しない

#### Scenario: REQ-050-S02 - パレットと明るいHP

- **GIVEN** パレットの全色と暗い盤面、異なるHP、新規とCPU、明示保存した設定
- **WHEN** 紋章とHPを表示する
- **THEN** アセンブリと所属ユニットの紋章は設定色、残HPバーと残HP円弧、所属紋章は同じ不透明の設定RGBをそのまま使い、明度と彩度、透明度による別トーンを作らず、新規とCPUは設定した陣営別の既定を使い、明示保存した色は保持し、HP比率と位相色、攻撃と回復の色は変わらない

### Requirement: REQ-051 - アセンブリの編集と保存境界

WHEN BUILDで編集可能なアセンブリの設定を開くとき、画面はコンパクトな入口と紋章、名前と色の即時プレビュー、明示確定と取消を提供し、未知の色キーと版、不正な名前を拒否し、通常の明示保存と読込で設定を復元し、未編集の敵へ既定の紋章と色を与え、一時全解放と通常データを混ぜず、長い名前とキー入力で他の操作を妨げてはならない(SHALL NOT)。

#### Scenario: REQ-051-S01 - 候補と確定と取消

- **GIVEN** 通常BUILDのアセンブリと名前、色の候補
- **WHEN** 名前と色を編集し、取消または確定を選ぶ
- **THEN** プレビューは候補だけを反映し、取消とEscは原本を保持し、確定だけが全所属表示へ反映され、入口へフォーカスを戻し、ユニット名と装備を変更しない

#### Scenario: REQ-051-S02 - 保存と一時状態

- **GIVEN** 通常と一時全解放、空欄と長いUnicode、未知の色キーと版、不正な名前
- **WHEN** 隔離先へ保存と別起動の読込、一時状態の入退場を行う
- **THEN** 有効な名前、色キーと版を復元し、空欄は既定名で表示し、無効な設定を原本不変で拒否し、一時中は保存せず、終了時に通常の設定へ戻る

#### Scenario: REQ-051-S03 - 実描画の対応

- **GIVEN** 初期と編集した設定、同色と同紋章、6体の戦闘、最小と基準画面
- **WHEN** BUILDと戦闘で名前と色、紋章とHPを表示し、入力と既存操作を行う
- **THEN** 紋章、HPバーと数値の列と中心を両行でそろえ、長い入力でレイアウトを壊さず、右詳細には小さい所属紋章とCLASSを同じ段と垂直中心で表示し、確認対象の切替に所属と色が追従してユニットの芯の紋章と区別でき、HPと位相、手番、攻撃と回復、移動と雲を区別できる

### Requirement: REQ-052 - 視点に基づく所有マーク

WHEN 盤面のユニットを表示するとき、画面はマス左下のP1とE1などの文字に代えて、視点の陣営と不変IDが一致する自軍にだけ小さい所属アセンブリの実際の紋章を描き、敵と不正な視点へは描かず、中央のユニット紋章と手番枠へ重ねず、設定色を透過させず、点滅を加えてはならない(SHALL NOT)。

#### Scenario: REQ-052-S01 - 所有の判断

- **GIVEN** 同じ名前と紋章、色の両陣営と異なるまたは不正な視点
- **WHEN** 所有マークを判定する
- **THEN** PLAYER視点では正しいPLAYER枠だけ、ENEMY視点では正しいENEMY枠だけに表示し、不正な視点と陣営不整合のIDには表示せず、名前と色で判断しない

#### Scenario: REQ-052-S02 - 同色時の実表示

- **GIVEN** 同色と同紋章の両陣営、手番とホバー、最小と基準の画面
- **WHEN** 両方の視点から静止と移動を表示する
- **THEN** 自軍だけに同じ設定色の小さい所属アセンブリ紋章が出て、位相と紋章、HP、フォーカスを覆わず、移動者に追随して隣接セルと盤端にも収まる
