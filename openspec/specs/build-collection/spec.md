# build-collection Specification

## Purpose

性能総量を増やさず構成の選択肢を収集するゲームの反復を実現し、ビルドと共有開放一覧を安全に保存して再利用できるようにする。

## Requirements

### Requirement: REQ-014 - 共有ビルド

WHEN 戦闘外で編集するとき、3体のPLAYERはCLASS、合計100のCORE、開放済み装備と変異、重複しない最大3スキルを共有一覧から設定できなければならない(SHALL)。

#### Scenario: REQ-014-S01 - 構成検証

- **GIVEN** 共有装備とNORMAL、REVERSE、未設定スキル
- **WHEN** ビルドを検証する
- **THEN** 空スキルと同一装備の複数人利用を許可し、未開放装備、重複スキル、不正変異は拒否する

#### Scenario: REQ-014-S02 - BUILDの情報階層

- **GIVEN** 3体のユニットと開放済み装備、変異、スキル、4ステージ
- **WHEN** BUILDで構成を編集して出撃条件を選ぶ
- **THEN** ユニット切替、CLASS、COREの5値と総量と再配分規則、ARMSとGEARの型番と5値、現在と候補の比較、変異、3スキル枠、HPと移動と待ち量とINF補正、ステージと勝利条件と案内、共有一覧の数量を確認できる
- **AND** 主要な編集、構成の結果、装備の比較と出撃を余白と強弱で区別し、SAVE、LOAD、HELP、SETTINGS、QUIT、STARTの操作を維持し、情報を恒久的に隠したり削除したりしない

### Requirement: REQ-015 - 収集

WHEN 通常モードの戦闘が終了するとき、各戦闘で一度だけ0から2件の未開放ARMS、GEAR、SKILLをランダム取得し、新規装備の5値を各10以上の10刻みで合計100の各126通りから選び、MUTANT取得で本体と非NORMAL変異を開放し、既開放候補を再抽選しなければならない(SHALL)。

#### Scenario: REQ-015-S01 - ドロップ境界

- **GIVEN** 固定シードの乱数と初期所持品
- **WHEN** 繰り返し戦利品を生成する
- **THEN** 各回0から2件、新規配分は10以上の10刻みで合計100、各種類の候補集合は重複のない126通り、変異は通常以外で本体と共に開放される

#### Scenario: REQ-015-S02 - 重複と変異

- **GIVEN** 本体開放済み、変異未開放の候補
- **WHEN** 候補を取得する
- **THEN** 新変異だけを開放し、両方既開放の再取得を拒否する

#### Scenario: REQ-015-S03 - 同じ結果の再表示

- **GIVEN** 戦利品を受け取った戦闘結果
- **WHEN** 同じRESULTを再表示する
- **THEN** 開放一覧、戦利品表示、乱数の状態が変わらず、戦闘以外では戦利品を取得しない

### Requirement: REQ-016 - 保存と読込

WHEN SAVEまたはLOADを選ぶとき、ビルドと共有開放一覧とステージを検証して保存または復元し、破損、不正、未知版、欠落は現在データを変えず報告し、有効な旧保存からは廃止したSTOP FIELDの解放と装備だけを外して他の内容を維持し、読込元を自動で書き換えず、再保存では既存保存をバックアップしなければならない(SHALL)。

#### Scenario: REQ-016-S01 - 保存往復

- **GIVEN** 編集したビルドと開放一覧
- **WHEN** 保存して別の状態へ読み込む
- **THEN** 全構成が復元され、再保存では以前の保存が別名で残る

#### Scenario: REQ-016-S02 - 不正入力

- **GIVEN** 欠落、破損JSON、未知版、不正な配分のファイル
- **WHEN** ロードする
- **THEN** エラーを返し、現在ビルドと開放一覧を変更しない

#### Scenario: REQ-016-S03 - 廃止した停止スキルの読込

- **GIVEN** 廃止したSTOP FIELDを解放と装備に含む有効な版1保存、または重複や未解放装備を含む不正な保存
- **WHEN** ロードする
- **THEN** 有効な保存はSTOP FIELDだけを解放一覧と各構成から外し、残る順序、FAST FIELDの旧ID、他の装備と収集、ステージを保持し、代替を自動取得や装備せず、読込元を書き換えない
- **AND** 不正な保存を廃止スキルの除去で有効化せず、エラーと現在状態の維持を保つ

### Requirement: REQ-024 - 装備の比較

WHEN BUILDで装備を選ぶとき、画面は型番を維持したまま5ステータスを十進数で表示し、候補と現在装備を横並びで比較可能にし、括弧内の増減値を表示してはならず、実リングを確認可能にしなければならない(SHALL)。

#### Scenario: REQ-024-S01 - 数値と差分

- **GIVEN** 現在装備が全値20で、候補がVIT25、INF15、RES20、SPD30、LUK10
- **WHEN** 候補を比較する
- **THEN** 型番とともに候補のVIT25、INF15、RES20、SPD30、LUK10と現在の各20を確認でき、括弧内の増減値を表示しない

### Requirement: REQ-026 - 初期スキルの収集余地

WHEN 新規ゲームを開始するとき、上下左右1マスのDAMAGEとHEALは使用可能、MOVE+1と斜め1、上下左右2、斜め2マスのDAMAGEとHEAL、SWAP、PUSH、GUARD、パネル無視、減速と加速の周囲効果は未開放とし、戦闘後に取得すると共有して装備可能にし、既存セーブの廃止スキル以外の開放済みスキルは維持しなければならない(SHALL)。

#### Scenario: REQ-026-S01 - 初期状態と取得

- **GIVEN** 新しいゲーム
- **WHEN** 初期構成を確認してMOVE+1を戦利品から取得する
- **THEN** 取得前は両PLAYERが移動+1を持たず、取得後は双方のビルドへ使用できる

#### Scenario: REQ-026-S02 - 既存開放状態

- **GIVEN** 3スキルを開放済みの版1のセーブ
- **WHEN** 読み込む
- **THEN** 3スキルが開放された状態を維持する

#### Scenario: REQ-026-S03 - 追加スキルの取得と互換性

- **GIVEN** 初期状態、追加6種を取得した状態、または既存3種を開放済みの版1保存
- **WHEN** 取得、構成と保存の往復を行う
- **THEN** 新規状態では旧2種だけを装備し、追加6種は未開放候補として入手でき、取得後は両PLAYERが重複しない最大3枠へ装備できる
- **AND** 新旧のIDと開放、構成を保持して版1で往復でき、旧保存の読込だけで追加品を解放や自動装備せず、未開放と重複を拒否する

#### Scenario: REQ-026-S04 - 位置操作と防御の取得

- **GIVEN** 新規状態、追加4品の取得後、旧3種または9種を開放済みの版1保存
- **WHEN** 取得と共有装備、保存と読込を行う
- **THEN** 追加4品は未開放候補から取得して両PLAYERの既存3枠へ装備でき、未開放と重複を拒否し、旧開放と構成を保持し、読込だけで追加品を解放しない
- **AND** 戦闘中の防御状態と一時予測をビルド保存へ含めない

#### Scenario: REQ-026-S05 - 周囲パッシブの収集

- **GIVEN** 新規状態、周囲の2品を取得した状態、旧13品までの版1保存
- **WHEN** 取得、共有装備と保存の往復を行う
- **THEN** SLOW FIELDとFAST FIELDの2品は初期未開放で戦利品から取得でき、両PLAYERの既存3枠へ共有でき、未開放と重複装備を拒否し、版1でIDと構成を保持し、STOP FIELDを通常、全解放と未解放候補、報酬へ含めない
- **AND** 旧保存は廃止したSTOP FIELDだけを除いて読め、自動開放と自動装備をせず、雲や範囲内の一時状態を保存しない

### Requirement: REQ-041 - 一時的な全解放

WHERE デバッグビルドである場合、利用者はBUILDからARMSとGEAR各126通り、全スキルと全変異を使用できる一時モードへ入り、通常データの保存、読込と戦利品、設定へ影響させず、DEBUG / NOT SAVEDを識別でき、終了時に元の通常状態へ戻れなければならない(SHALL)。

#### Scenario: REQ-041-S01 - デバッグだけの入口

- **GIVEN** デバッグまたはリリースの実行環境と通常のBUILD
- **WHEN** 全解放の入口と開始を確認する
- **THEN** デバッグではENEMY CPUと同じ形式のUNLOCK ALLトグルでONとOFFを識別して明示的に開始と終了ができ、リリースでは入口を表示せず直接の開始も拒否し、起動直後は通常状態のままである

#### Scenario: REQ-041-S02 - 新規の全カタログ

- **GIVEN** 通常の構成と所持品
- **WHEN** 一時モードへ入る
- **THEN** 新規の一時データでARMSとGEAR各126通り、NORMALを含む120変異と全16スキルを使用でき、元の通常データを変更せず、装備の共有と重複しない最大3スキルを維持する

#### Scenario: REQ-041-S03 - 保存と戦利品の分離

- **GIVEN** 全解放で編集した構成と戦闘結果、通常のセーブと設定
- **WHEN** 保存、読込、戦利品と色設定を操作する
- **THEN** 通常セーブへの保存と読込は操作と実処理で拒否し、戦利品は発生せず乱数も進めず、色の適用は一時的とし、通常データと保存先、設定ファイルを変更しない

#### Scenario: REQ-041-S04 - 終了と再開始

- **GIVEN** 一時モードで構成とステージ、配色を変更し、戦闘または再スタートを行った状態
- **WHEN** BUILDで一時モードを終了するかアプリを終了する
- **THEN** 元の通常の所持品と構成、ステージと表示設定へ戻り、一時取得品を持ち込まず、再スタートだけでは一時モードを維持し、再度入ると新しい一時データになる

#### Scenario: REQ-041-S05 - 表示と装備の試行

- **GIVEN** 全解放のBUILDと戦闘、最小から拡大の画面
- **WHEN** 装備と変異、スキルを選び、開始と戻る操作を行う
- **THEN** DEBUG / NOT SAVEDを識別でき、126種と120変異の先頭と末尾まで選べ、数値とプレビュー、対象と戦闘へ反映し、終了とメニュー、既存のフォーカスとクリックを妨げない

### Requirement: REQ-042 - 共通の構成選択

WHEN BUILDでCLASS、ARMS、GEAR、各MUTATION、スキルまたはOPERATIONを選ぶとき、共通ダイアログは現在と候補を区別して実際のリングや効果をプレビューし、確定まで構成を変更せず、取消とキーボード操作を許可し、未解放候補を非活性で見せ、装備を能力値で絞り込んでスクロール可能にし、変異を装備との全組合せへ平坦化しないようにしなければならない(SHALL)。

#### Scenario: REQ-042-S01 - 候補と確定と取消

- **GIVEN** 現在装備と異なる開放済みの候補
- **WHEN** 候補を選んで確定または取消する
- **THEN** 選択中は原本を変えず実リングと5値を比較でき、確定時だけ対象の値を変更し、取消とEscは選択前の構成を保つ

#### Scenario: REQ-042-S02 - 全候補と非活性と絞り込み

- **GIVEN** 一部または全解放の共有一覧
- **WHEN** 装備と変異、CLASS、スキルの候補を調べる
- **THEN** ARMSとGEAR各126、変異とCLASS各120、全16スキルの候補を別一覧で確認でき、未解放と他枠で装備済みのスキルは確定できず、装備の指定能力値の下限に合う候補だけへ絞り込め、一覧の先頭と末尾へ到達できる

#### Scenario: REQ-042-S03 - クラスと変異の違い

- **GIVEN** 同じ配置コードのCLASS、GEARまたはARMSの変異
- **WHEN** 各候補を比較する
- **THEN** CLASSはCOREだけ、変異は選んだ装備リングだけの順を示し、配分と他リングを変更しない

#### Scenario: REQ-042-S04 - スキルと作戦の内容

- **GIVEN** 3スキル枠と4作戦
- **WHEN** スキルまたは作戦を選ぶ
- **THEN** スキルは同系統のまとまりと簡潔な説明、対象位置を示し、NONEを許可し、作戦は内容と勝利目的、配置を示し、確定後だけ対象枠または作戦へ反映する

#### Scenario: REQ-042-S05 - モーダルの入力境界

- **GIVEN** BUILDから開いた候補一覧
- **WHEN** キーボードで候補を移動し、確定または取消して閉じる
- **THEN** 有効な候補と操作だけへフォーカスでき、背景の構成や戦闘を操作せず、現在装備と候補を識別でき、閉じた後は呼出元へフォーカスが戻る

### Requirement: REQ-045 - COREの配置選択

WHEN CLASSを選ぶとき、利用者はVIT、INF、RES、SPD、LUKを一度ずつ並べた120配置を確認でき、VIRSLとVLSRIは常時、それ以外は共有MUTATIONの解放に従って選べ、COREだけの基準配置へ反映しなければならない(SHALL)。

#### Scenario: REQ-045-S01 - 候補と解放の境界

- **GIVEN** 通常の新規一覧、共有変異LSRIVの解放、全解放の一覧
- **WHEN** CLASSを選んで確定する
- **THEN** 候補の全体は重複のない120配置であり、選択可能な集合は新規ではVIRSLとVLSRIだけ、LSRIV解放後はこの2つとLSRIVだけ、全解放では120配置すべてとなり、未解放と不正な配置は確定できない
- **AND** CLASSだけのVLSRI利用によって装備の変異を解放しない

#### Scenario: REQ-045-S02 - 配置と回転とリセット

- **GIVEN** CLASSをLSRIVにしたユニットとCORE回転パネル、RESETを含む経路
- **WHEN** 経路を予測して確定し、RESETを踏んで再戦する
- **THEN** COREの領域順はLUK、SPD、RES、INF、VITとなり、GEARとARMSの順と能力値は変わらず、予測と確定の領域が一致し、RESETと再戦ではLSRIVの戦闘開始時CORE配置へ戻る
- **AND** 通常移動のCORE保持、特殊パネルのCORE回転量とGEAR、ARMSの通常回転、CPUと強制移動の規則は変わらない

#### Scenario: REQ-045-S03 - 旧クラスと保存境界

- **GIVEN** STANDARDとREVERSE、および装備と収集を持つ従来の有効な通常セーブ
- **WHEN** 読み込み、その後に隔離先へ明示保存する
- **THEN** STANDARDはVIRSL、REVERSEはVLSRIの従来と同じCORE配置を再現し、元の装備と収集を維持し、読込元のバイト列を変えず、新しい開放済みCLASSも保存と読込で保持する
- **AND** 不正または未解放のCLASSを含む読込は現在の構成を変えず拒否する

#### Scenario: REQ-045-S04 - 配置コードと対象リングの表示

- **GIVEN** 標準と非標準のCLASS、GEARとARMSのMUTATION、最小と標準の対応画面
- **WHEN** BUILD、選択ダイアログ、戦闘の関連情報とHELPを確認する
- **THEN** 配置コードを主表示とし、初期配置VIRSLには括弧を使わず小さくSTANDARDを添え、CLASSがCORE、MUTATIONが選んだ装備に作用することと解放条件を英語で確認でき、コードと補足が重ならず選択と取消を操作できる
