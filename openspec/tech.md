# 技術方針

## 技術スタック

Godot 4.7系、GDScript、Compatibilityレンダラーを使う。
開発専用にNode.js 22.12以上、npm、OpenSpec 1.16.0、Gitを使う。
画像は同梱したLucideのSVGアイコンだけを使い、追加の実行時ライブラリは使わない。

## アーキテクチャ

画面からモデルへ一方向に依存する。

~~~mermaid
flowchart LR
  UI["画面と入力"] --> B["戦闘"]
  UI --> C["収集と保存"]
  B --> M["位相計算"]
  B --> D["カタログ"]
  B --> FIELD["周囲回転の判定"]
  B --> SPAWN["初期配置"]
  B --> PANEL["効果パネル"]
  FIELD --> D
  C --> D
  UI --> V["描画"]
  UI --> CPU["CPU判断"]
  UI --> PRESENT["CPU表示進行"]
  UI --> MV["確定移動の表示"]
  CPU --> B
  PRESENT --> B
  V --> M
  UI --> LANG["説明言語と独立設定"]
  UI --> SFX["確定表示の効果音"]
~~~

## 技術上の判断基準

- 効果音の有効値はui/sfx.gdで一元管理し、OFFへの変更時にボタンを含む全レーンと撃破予約を同期停止する。\
  歩と効果の消費済み識別を保持し、ONへ戻して過去の音を再生しない。\
  音専用の.audio.jsonへ明示選択だけを原子的に保存し、不明はON、書込失敗は元の値を維持する。\
  全解放中は保存せず終了時に元へ戻し、配色と言語、ゲーム保存とMasterを変更しない。
- ボタン用の短いサイン波をui/sfx.gdで一度だけPCMへ生成し、専用の単声レーンで再利用する。\
  画面配下のBaseButtonとPopupMenuへ動的に接続し、ボタン音は実GUI押下と同じ更新のbutton_downで一度だけ要求する。\
  操作のpressedとaction_modeは変えず、外へ離す取消では音だけが残る。\
  プルダウンの項目は有効な確定通知と入力を同じ更新で相互に照合し、発音の遅延呼出しを置かない。\
  項目を押した位置を推測せず、開く押下の離しとキーリピートでは重複発音しない。\
  ホバー、フォーカス、無効入力、盤面と内部更新から鳴らさず、画面遷移で短いUI音を切らない。\
  既存のSFX有効フラグとMasterへ従い、音量UIと素材ファイルを追加しない。
- 移動用の2音と攻撃、回復、撃破はui/sfx.gdで管理し、モデルと予測、CPU評価から再生しない。\
  確定移動で最初に位置が進む更新から半区間ごとの発音列を始め、回転量に依存せずring_rotate1とring_rotate2を交互に鳴らし、攻撃と回復は実HP変化へ接続する。\
  時計がゼロの確定直後と出発前フェードでは鳴らさず、固定秒数の前寄せ、原音の切り詰めと再生位置の補正を重ねない。\
  半区間と結果の重複を除き、停止と退出で戦闘音を止め、既存の表示と戦闘の時間を変えない。\
  ring_rotateとeffectの2レーンは各1声とし、撃破は独立した上限付きの声で既存のMasterへ送る。\
  撃破は実減少と0HPの確定結果だけに一度予約し、単一の遅延後に冒頭を保持して振幅を滑らかに消す。\
  次手とRESULTでは余韻を維持し、停止と明示的な戦闘退出で破棄する。\
  音源を変更せずgame/tuning.gdで音量と遅延、包絡と声数を調整する。\
  select.oggと旧ring_rotate.oggは原本を保持するだけとし、読込と再生対象から外す。
- 戦闘開始時のユニット配置とパネルだけを開始シードから生成し、配置後の戦闘計算には乱数を使わない。\
  ユニットは名前空間を分けた独立乱数で陣営ごとの範囲へ置き、実開始位置を確定してからパネルの除外へ渡す。\
  両ステージの全滅と指定対象の条件を保ち、同じ入力を再現し、他の乱数と保存を消費しない。
- 現行OPERATIONは01と02だけとし、ELIMINATEとTARGETを撃破時に敗北優先で判定する。\
  廃止した選択値の保存は一般の不正ステージ検証で拒否し、元ファイルと現在の構成を維持する。
- CPUは公開状態の複製を既存の戦闘操作で評価し、判断の履歴と同じ入力に対して同じ選択を返す。\
  表示進行の実時間をゲーム内の手番時刻へ加えず、中断時は表示時間も蓄積しない。\
  モード、速度と停止は実行中だけ保持し、既存セーブの形式を変えない。
- 配置のシード、ドロップ乱数と保存先は独立して注入可能にする。
- COREの現在角と戦闘開始角は戦闘中の状態だけに保持し、ビルドの保存形式へ加えない。
- 無移動WAITは未確定経路を適用せず、能動行動の入口は実移動数を検証する。\
  対象の幾何判定へ移動条件を混ぜず、移動前の脅威評価を維持する。
- 人の経路と行動の予定は独立した戦闘の複製で検証し、有効な対象または対象選択を要しない行動を選ぶまで実位置、リング、HP、履歴と手番を変更しない。\
  BACKとEscは予定だけを戻し、最終選択で実行待ちを一度だけ作り、ダイアログを消した描画の完了後に既存の移動計算へ渡す。\
  ACTIONは短い入力保護と押下解除を経て有効にし、入力を予約して後から再生しない。\
  移動した攻撃だけは着地の短い表示を経て予定した行動を一度実行し、保存へ予定を加えない。
- 確定移動の描画はモデルから分離し、既存の各歩の計算で作った表示専用の状態間を補間する。\
  各歩の位置とリングは同じ単調な進みを使い、セル中心で速度を落としてもゼロにせず、移動時計と着地後の一拍は延ばさない。\
  装備の方向と周囲倍率を保ち、RESETは開始角への短い方向で表示し、描画位置と角度を計算へ戻さない。\
  発生源の雲の出発前の透過と攻撃前の保持も同じ表示状態で所有し、中断中は表示時間を蓄積せず、所有戦闘または手番の変更と退出で古い表示と予定行動を無効にする。
- 通常と強制の進入はbattleの共通処理を通し、装備の受動を判定して同じ計算へ渡す。\
  強制移動は対象の確定済み時刻と移動数を変えず、全員の位置を確定後に通常の進入を適用する。
- 周囲回転の倍率と範囲は現在位置、生存と装備から共通部品で求め、各着地へ渡す。\
  強制移動は全到着位置をそろえてから計算し、予測と確定、CPUと雲は同じ規則を使う。\
  1回のCPU判断内の脅威再利用は位置、生存と反撃側の角度を区別し、異なる世界や次の判断へ持ち越さない。
- 防御は戦闘中だけの状態とし、計算と表示の予測では消費せず、攻撃の確定で一度だけ消費する。
- 全解放の開始はOS.is_debug_buildを必須条件とし、通常collectionの参照と表示設定を保持して新規の一時collectionへ切り替える。\
  一時collectionは保存、読込と戦利品を下層でも拒否し、配色の適用も保存せず、終了時に通常状態を復元する。\
  デバッグ中の状態を通常データへ転記しない。
- 構成選択は候補の複製を描き、明示確定時だけ可否を再検証して原本へ反映する。\
  取消とEscは原本を変更せず、閉じると呼出元へフォーカスを戻す。
- 新規保存は版3とし、3枠のunit_namesと紋章方式identicon_version、名前と色キーと版を持つassemblyを構成から独立して検証する。\
  旧保存は移行せず拒否し、名前や紋章を不変ID、陣営と枠、対象番号と照合しない。
- アプリの起動時はgame/profile.gdで既存の有効なプロフィールを読み、追加抽選と自動上書きを行わない。\
  未作成の場合だけ固定初期品へARMSとGEAR各5種を追加し、各能力が単独最大の未所持群から1種ずつ選び、通常の保存方式で一度保存する。\
  抽選乱数は盤面と戦利品から独立させ、同セッションは同じcollection参照を保持する。\
  保存の破損を新規扱いにせず、初回の書込失敗でも再抽選しない。
- ゲームと全設定はgame/storage.gdの共通境界へ接続し、通常は既存の保存パスへ原子的置換と退避、Webとdemoタグ付きのデモは静的メモリ辞書だけを使う。\
  ページ再読み込みでゲームと設定を破棄し、同ページのシーン再作成では保持する。\
  demoタグのときはSAVEとLOADを表示したまま無効にし、collectionでも明示保存と読込を拒否し、初期抽選のファイル保存を省く。\
  以後の編成と報酬の通常保存は従来の明示SAVEとし、自動で実セーブへ書き戻さない。
- 表示モードは所属する実ウィンドウで確認し、明示操作の安定後だけ.display.jsonへ保存する。\
  起動復元中の旧状態とエディター埋め込みでは保存せず、埋め込みの非対応操作は説明付きで無効にする。
- 説明言語は配色パスに.language.jsonを付けた独立設定へ保存し、既存の配色配列とゲーム保存を移行しない。\
  未設定と未知の値はsystem、明示値はenとjaとし、起動時にGodotがOSの優先言語から初期化したロケールを使う。\
  明示操作だけで書き込み、失敗時は元の選択を維持し、全解放中は一時選択として通常設定へ保存しない。
- COREのCLASSと装備のMUTATIONは配置コードで比較し、対象リングだけへ作用する。\
  旧CLASSのSTANDARDとREVERSEはVIRSLとVLSRIとして解釈し、読込元と保持した別名を自動で変換しない。
- OpenSpec設定とゲーム保存を作業先内に置く。
Godot自身の標準設定はmacOSのApplication Supportを使用するため、制限されたシェルでは初期化警告が出る場合がある。
- 調整定数はgame/tuning.gdに集約する。
- スキルの作用と対象位置、生存、陣営と負傷の条件はgame/catalog.gdへ集約する。\
  戦闘、表示とCPUは同じ条件を使い、装備と操作状態は入口で制限し、範囲の違いで別の威力式を作らない。
- 1920x1080の論理座標をcanvas_itemsとkeepで拡縮し、OSのDPI倍率やroot.scaleを追加で掛けない。
- 盤面はマウスイベントの論理座標を使い、GUIの座標変換はGodotへ任せる。
- フォーカス喪失でホバーとGUIフォーカスを解除し、未確定経路を保持して復帰後に続行する。
- 手番番号と行動者の組が変わった時だけ任意の確認と古いホバーを解除する。\
  PREVIEWは行動者の経路予測、詳細は明示的な選択を優先し、同じ手番の操作を自動追従で上書きしない。

## コードのコメント

先頭がアンダースコアでない関数を外部向けとする。
GDScriptの文書コメントに概要、引数、戻り値、副作用の意味を書く。
scripts/lint.mjsが存在と引数名と戻り値記述を検査し、Godotが構文と型を検査する。
テストとGodotコールバックはコメント検査から除く。

## テスト方針

- Godotのheadlessモードでモデルと保存境界を検証する。
- 無出力のDummyドライバーでは効果音の開始を省き、発音要求と接続を検査する。\
  Movie Makerでは音声出力を維持し、通常ドライバーの実ミックス信号は開発時に別途確認する。\
  信号確認を聴感の確認と同一視せず、好みと機器での聞こえ方は実機確認へ残す。
- テスト関数の先頭の文書コメントにシナリオIDを書く。
- 期待値を対象の関数から生成しない。
- 見た目、操作、面白さは実画面で確認し、自動テストと区別する。
- 英語の既存検査はGodotの--language enを明示し、OSに依存させない。\
  説明言語の自動判定と保存は、隔離設定とロケールを注入して別に確かめる。
- 比較用画像で通知を消す場合も、通知が出る代表状態の可読性を別に検査する。
- scripts/check.shにプロダクト検査をまとめ、npm run checkの先頭から呼ぶ。
- 旧配置を前提に位相とUIを確かめる検査はtests専用fixtureを使い、本番モデルの複数シード再生と区別する。
- 2対2の配置や対象添字を前提にした機械的な検査は、その構成数をfixtureへ明示する。\
  本番の6体の生成と陣営、保存とCPUは本番モデルで検証する。
- UI接続などの短い機能確認では条件をfixtureに明示し、実ステージの攻略難易度と分ける。
- 両ステージは撃破による目標条件、再生中の合法性、HP上限と手番進行を検査し、操作履歴を残す。
- 固定戦術の勝敗、決着手数、回復回数と反復回数はバランス観測とし、合否に固定しない。\
  平均10から15手はシミュレーションと実プレイの目安であり、数式と勝敗条件、HP上限、対象と手番、保存境界の検査とは分ける。\
  調整のたびに成功する戦術やシードのテストを追加しない。

## 表示原則

人が読む説明だけを英日で切り替え、タイトル、見出し、機械的なラベルと名称は英語を保つ。\
ui/language.gdとui/japanese.gdの対訳へ通す説明を明示し、汎用ラベルと入力名は翻訳しない。\
原文を持つ部品を即時更新し、言語変更で編成や戦闘、経路と選択を再作成しない。\
日本語は簡潔な常体とし、登録された翻訳テンプレートの句点を値の代入前に改行へ整える。\
入力名と動的値、原文には置換を広げず、既存のシステムフォントの組み合わせを使う。\
紋章を含む目標文もGodotの段落組版で折り返し、原文の固定参照と非表示の名前を保持する。\
BUILDの改名で既存の参照文を更新し、役割の不変IDをBUILDでは現在編成、戦闘では実ユニットへ解決する。

名前と円形紋章はdocs/identicon-v1.mdの版1規約を使い、紋章はHPより内側の単色の幾何とする。\
同名を許し、戦闘と入力欄以外では紋章と所有マーク、既存の対応強調だけで識別する。\
ユニット名と自動生成するP1とE1形式を戦闘画面とツールチップへ渡さず、名前は入力と保存、紋章生成、非表示のアクセシビリティ用名称へ保持する。
アセンブリはdocs/assembly-v1.mdの名前と安定した色キー、版を持ち、戦闘と独立した描画引数で所属色を渡す。\
紋章は名前で固定し、同色と同紋章の衝突で再生成せず、残HPバーと円弧、所属紋章と所有紋章は同じ不透明の設定RGBをそのまま使う。
視点は独立した陣営とし、整合する不変IDの自軍だけへ小さい実際の所属紋章を描く。
新規の陣営別既定とパレットの追加で明示保存した色を変更せず、HPを別トーンへ加工しない。


深い黒を基調とし、走査線、全面の発光、ランダムな装飾を使わない。\
攻撃は赤い収束だけとし、回復は最初の円の接触時だけ実HP増分の局所反応を許し、残HPと紋章を前面に保つ。\
円形予測は各装備の実SPDと役割差に基づく周期で半径だけを揺らし、表示時間で戦闘角度と値を変更しない。
色は役割を保ちつつ設定可能にし、文字の相対輝度比とステータス色の区別を配色部品で検証する。
組み込みプリセットと6色が完全一致するときはリングだけ彩度を強め、それ以外のカスタム配色は指定RGBをそのまま表示する。\
基本の6色と他UI、保存形式は維持し、表示用のリング色を保存へ書き戻さない。
符号、ステータス名、輪郭、操作ラベルを併用し、色だけに意味を依存しない。
配色は明示的な適用時に独立UI設定へ保存し、既存ファイルを退避する。
SETTINGSのDISPLAYはOSから読んだ実状態だけへ選択印を付け、ホバーとフォーカスから分離する。\
廃止した動きを抑える値を読み込まず、他の設定の保存形式を変更しない。
モーダルは最前面の有効な操作部品だけでTabを循環し、補助画面を閉じると以前のフォーカスへ戻る。
BUILD、行動選択、RESULTと補助画面は外枠を持たない黒い面とし、余白と文字で階層を示す。\
通常ボタンは囲わず、入力欄は下線、ホバーは灰色の面、フォーカスは白い下線で区別する。\
ユニット選択はアクセントの下線を使い、盤面のシステムメニューの既存表現は維持する。
ユニットの円弧は実描画倍率から最小物理線幅と弦誤差を求め、半径と角度を保ってアンチエイリアスを適用する。

円形の予測は実領域の局所的一致を表し、最終補正率とは区別する。\
領域、色と包絡は配分、突然変異、角度、SPDと配色が変わった場合だけ生成する。\
表示時間ではキャッシュから動く座標だけを生成し、通常の演出を常に使う。

周囲パッシブの雲は発生源中心の表示時間だけで漂い、戦闘値と乱数を変更しない。\
Godot標準のメモリ内の放射グラデーションを再利用して縁をぼかし、画像ファイルと素材は追加しない。\
全セル背景、盤内へ切り取った雲、パネルとユニットの順で描き、次行による遮蔽を防ぐ。
