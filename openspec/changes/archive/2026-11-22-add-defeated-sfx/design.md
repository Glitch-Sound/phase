# 設計

## 背景と制約

- 提案: [proposal.md](proposal.md)
- 前提: openspec/tech.md の 技術上の判断基準 と テスト方針
- 原音は約1.98秒で即時に立ち上がる一方、既存の攻撃原音は約132msで立ち上がる。
- 盤面の対象はHP0で即時に除外され、赤い収束は0.42秒続く。

## 設計判断

### D-01 - 実撃破の音を独立して進める

- 選択: 実効果の通知へ撃破の真偽を渡し、実減少が正のDAMAGEだけを予約する。\
  戦闘と履歴番号で重複を防ぎ、独立の再生プレイヤーと包絡を持つ。
- 理由: 元の攻撃、回復と移動のレーンを止めず、通常の手番更新とRESULTでも余韻を進められる。
- 代替案: ゲームを待たせる演出や原音の編集、単一の音声レーンの上書きは採用しない。
- 昇格: openspec/tech.md の 技術上の判断基準

### D-02 - 立ち上がりを残して余韻だけを滑らかに落とす

- 選択: game/tuning.gdの1か所に、撃破音の遅延0.24秒、ゲイン-18dB、保持0.20秒、フェード0.65秒、独立声数6を定義する。\
  再生要求の更新が遅れても、実際に開始した時点から保持時間を数える。\
  保持後は振幅をsmoothstepで0まで下げ、停止する。\
  出発前フェードと早送りの時計へ結合しない。
- 理由: 攻撃の立ち上がりから約0.1秒後に撃破音が続く。\
  元の冒頭を残して約0.85秒で終え、6体戦で近接した撃破も前の余韻を即断しない。
- 代替案: 原音の無音削除と追加の遅延を重ねず、一定音量の突然の停止を避ける。
- 昇格: openspec/tech.md の 技術上の判断基準

音声部品で音列、遅延、保持、フェードと境界を検査し、画面との接続は代表例だけで確かめる。\
固定ダメージなどバランスの期待値は増やさない。\
補足として隔離した通常Godotで非致死、人とCPUの撃破、最後のユニットの撃破を実行し、要求時刻、音声信号と音量を記録する。\
信号計測と聴感を区別し、実機確認の未実施を確認済みにしない。

## リスクと移行

音声機器の追加遅延と聴感は信号だけでは確定できない。\
停止と明示的なBUILD退出では保留と残響を破棄するが、通常の次手とRESULTでは破棄しない。\
原音の出典を確定できる文書はなく、公開しない。\
保存の変更と移行はない。
