# 差分仕様

## MODIFIED Requirements

### Requirement: REQ-030 - ユニットの円弧表示

画面はユニットを外枠のない細いCORE、GEAR、ARMSの3リング、領域間の隙間、内側の純白のHP円弧、中央の円形紋章で表示し、HP比率、位相、設定色、選択状態を判別可能にし、盤面の記号をセル中央に収めなければならない(SHALL)。

#### Scenario: REQ-030-S01 - 共通の構造

- **GIVEN** 盤面、予定手番、詳細、予測、BUILDのユニット
- **WHEN** ユニットを表示する
- **THEN** CORE、GEAR、ARMSの順で内から外へ細い色付き円弧を表示し、各領域の境目に隙間があり、外周を囲む枠線がなく、名前から決まる円形紋章が中央にある

#### Scenario: REQ-030-S02 - HPの増減と境界

- **GIVEN** 最大HPが100のユニット
- **WHEN** HPを表示する
- **THEN** 3リングの内側の純白の円弧が配色に依存せず次の比率を表し、紋章と他の線の色は変わらない

| HP | 円弧の比率 |
| --- | --- |
| 0 | 0% |
| 50 | 50% |
| 89 | 89% |
| 100 | 100% |

#### Scenario: REQ-030-S03 - 実表示での判別

- **GIVEN** 味方と敵、選択と非選択、既定色と変更色、最小ウィンドウと基準画面
- **WHEN** Godotでユニットを表示する
- **THEN** 3リングの境目、白いHP円弧、中央の円形紋章、選択状態を区別でき、ユニット記号はセル内に収まる

#### Scenario: REQ-030-S04 - セル中央への配置

- **GIVEN** 境界セルと隣接セルにいるユニット
- **WHEN** 盤面のユニットを表示する
- **THEN** 各記号の中心はセルの幾何学的な中央に一致し、色リング、HP、紋章、目盛りはそのセル内に収まり、隣接セルへ重ならない

### Requirement: REQ-031 - 味方の表示名

画面は内部IDと陣営、枠から独立した編集可能な名前と決定的な紋章を表示し、同名を許可しても対象と勝敗、手番の照合には不変IDまたは番号だけを使い、未編集の敵には固定の初期名を与え、長い名前は盤面へ展開せず詳細で全文を確認可能にし、必要な陣営と枠の手掛かりを保たなければならない(SHALL)。

#### Scenario: REQ-031-S01 - 表示と識別子の分離

- **GIVEN** 内部ID01、02、03、A、B、Cと同名のユニット
- **WHEN** 表示名を編集して戦闘とCPU、対象と目標を処理する
- **THEN** 同名では同じ紋章となるが、陣営と枠、対象番号、手番順と目標判定は互いに独立し、表示変更は戦闘結果へ影響しない

#### Scenario: REQ-031-S02 - 関連画面の名前

- **GIVEN** BUILD、BATTLE、ACTIONとHELPの識別表示と目標の説明
- **WHEN** 表示と操作を行う
- **THEN** 名前と紋章は対応する枠と陣営へ一貫し、盤面の芯は紋章、詳細は全文、タイムラインと操作は収まる短い参照で表示し、同名でも枠が分かり、ステージ番号は変えない

### Requirement: REQ-044 - 英語のユーザー向け表示

画面は利用者が入力した名前を翻訳せずプレーンテキストとし、それ以外のBUILD、候補選択、戦闘、行動と結果、HELPと設定、パネルと周囲効果の説明、保存の通知を簡潔で読みやすい英語に統一し、HELPで操作、クラスと変異、位相、スキル、保存と全解放の意味を説明し、STARTのラベルをボタン中央へ配置しなければならない(SHALL)。

#### Scenario: REQ-044-S01 - 全画面の英語と操作

- **GIVEN** 通常と全解放、3体の構成と戦闘、成功と不正操作
- **WHEN** 画面と各補助説明を確認する
- **THEN** 入力された名前を除くユーザー向け表示に日本語を含まず、HELPから必要な操作と効果を読め、STARTのラベルが中央にあり、戻ると既存の状態と操作を維持する
