## 設計判断

### D-01 - 常時表示と開示

- 選択: 盤面、短い手番順、予測リング1組、INF/RESだけを主表示にする。
詳細はI、波形はP、メニューはMでも開き、選択モデルと独立させる。
詳細を開いたときだけ全4ユニットの選択部品を示し、ACTIONと対象選択中も調べられるようにする。
- 理由: 前回は同じ値が反復し、装備表と説明が経路判断を圧迫した。
- 代替案: 色だけを落とす案は密度を解決しないため採用しない。
- 昇格: openspec/tech.md の 表示原則

| 対象 | 判断 | 理由 |
| --- | --- | --- |
| 左右の大面積パネル、標語、盤面座標軸、反復見出し | 削除 | 操作や判断を増やさない |
| 12組のリング | 予測1組に集約 | 盤上は陣営形状、ID、HPで十分である |
| 装備型番、15値、全スキル | 詳細へ | 相手の判断には必要だが毎手の常時表示は不要である |
| 4波形、正確な角度 | 位相詳細へ | 必要時の精密比較を保つ |
| 陣営集計、正確な時刻 | 手番詳細へ | 主表示は順序で足りる |
| 特異点オフ、装備NORMAL、技能タイプ | 削除 | 不成立や既定値を反復しない |
| 目標、パネル凡例、操作説明 | 目標とHELPへ | 初回に到達でき、戦闘を覆わない |
| ACTION中央配置 | 右へ | 盤面と予測を読みながら行動を選べる |

~~~mermaid

 B["戦闘の基本表示"] --> I["詳細 I"]

 B --> M["MENU M"]
~~~

### D-02 - 暗さと意味

- 選択: 背景#010203、面#030405、操作背景#0a0c0e、輪郭#15191d、本文#b5babc、補助#858b90とする。
配色とリング線幅はui/palette.gdとui/visuals.gdの定数を唯一の定義にする。
盤面寸法は既定の70、基準1920x1080を保つ。
- 理由: 広い色面と太いリングを減らし、必須文字の4.5:1以上を保って全体を暗くする。
- 代替案: 全要素に暗幕を掛ける案は選択中の比較を損なう。
- 昇格: openspec/tech.md の 表示原則
- 測定: 同一場面で描画文字とGUI文字を収集し、既定表示の文字数を前回の50%以下、リング組数を1以下とする。
Godotで前回画像と新画像を読み、全ピクセルのsRGB相対輝度の平均を測り前回の50%以下とする。
これは見た目の調整目標であり、数値はtests/essential_flow.gdの監査定数で定義する。

### D-03 - 目的別の小画面

- 選択: BUILDはCORE、EQUIP、SKILLS、HELPはPLAY、PHASE、BUILD、SETTINGSはDISPLAY、COLORに分割する。
RESULTは勝敗と取得品を示し、型番と全能力値は取得品を開いて調べる。
- 理由: 編集目的ごとの必要情報を保ち、一度に見る情報を減らす。
- 代替案: 全情報を小さくして詰める案は可読性を損なう。
- 昇格: openspec/structure.md の 配置原則

状態保存と開示の境界はUIの処理の流れで確かめる。
配色の異常は配色部品の既存検査で扱う。
幾何と入力の境界は既存の表示検査を継続する。
全画面はGodot実レンダーで記録し、ネイティブ操作で選択、フォーカス、両陣営の行動経路を確認する。
主観的な品位と面白さの最終判定は利用者に委ね、観測と限界を分けて報告する。

画像取得時に欠けに見えた領域は、保存PNGの画素では保たれていた。
旧面は遅延破棄前にツリーから外し、新しい面だけを入力と描画の対象にする。
追加の再描画は行わず、既存の30fpsの予測更新を保つ。
盤面線は拡縮しても1物理ピクセルとなる負幅をGRID_LINE_WIDTHに定義する。
GPU検査は最初から成功したため、ネイティブの再操作と実画素の比較を併用する。

COREの5入力は、2桁に必要な最小文字幅を明示して矢印の隣接重なりを防ぐ。
入力の実寸法を使う検査で、重なり4件の失敗から成功まで確認した。

## リスクと移行

隠しすぎによる発見性の低下は、短い表示ボタン、ツールチップ、F1のHELPで扱う。
ページの切替と色適用は未確定経路、対象、報酬乱数を維持する。
既存データの移行はなく、自動保存は加えない。
失敗時は今回のUI変更だけをGitで戻せる。
