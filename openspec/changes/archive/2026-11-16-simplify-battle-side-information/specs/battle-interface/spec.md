# 差分仕様

## MODIFIED Requirements

### Requirement: REQ-019 - 情報と位相予測

画面はHP陣営合計、行動順ごとに等間隔の独立した点と相対進捗の白い円弧を持つ縦の時間軸と左右の現在状態、選択ユニットの必要な識別情報と全スキル、経路後リングと周囲の円形の揺らぎ、特異点を表示し、陣営ごとのHP数値とバーを同じ段へ収め、情報を囲う装飾を省きながら操作状態を区別できなければならない(SHALL)。

#### Scenario: REQ-019-S01 - 情報の比較

- **GIVEN** 異なる位相になる2経路
- **WHEN** 経路を切り替えて別ユニットを調べる
- **THEN** 予測は手番ユニットを維持し、右詳細は選択ユニットへ切り替わり、円形の揺らぎが配分と位相を反映し、GとAの角度数値、横長波形と角度軸、下端のROUTEからEFFECTへの記載は表示しない

#### Scenario: REQ-019-S03 - 指定文字の非表示

- **GIVEN** 戦闘画面の移動、行動選択、攻撃対象、回復対象、結果の背後のいずれか
- **WHEN** 画面を表示する
- **THEN** 次の文字を表示せず、時間軸、経路の描画と移動、円形予測と特異点、詳細情報と通知の機能を維持し、配置は盤面優先の寸法要件に従う

| 除去する表示 | 範囲 |
| --- | --- |
| PHASE PREVIEW | 見出し |
| PATH X / DESTINATION | 経路長と目的地座標を含む表示全体 |
| ROUTE / PHASE / EFFECT | 左上の補助見出し |
| TURN ORDER | 見出し |
| T / 現在時刻 | 数値を含む表示全体 |
| INSPECT | 見出し |
| INNER / MIDDLE / OUTER | 補助見出し |
| PHASE / TACTICAL STUDY | 左上の説明文字 |
| BOTH SIDES / HUMAN | 右上の説明文字 |
| TURN / 現在ターン番号 | 数値を含む表示全体 |
| 行動順の待ち量とACTING、QUEUED | 選択とホバーを含む状態文全体。FINISHEDとDEFEATEDも同領域には表示しない |
| INFとRESの最終同期率 | 予測下の2つの数値表示。代替表示を追加しない |

#### Scenario: REQ-019-S04 - 情報の囲い装飾を省く

- **GIVEN** 戦闘画面の情報と予測が表示されている
- **WHEN** 移動、行動選択、対象選択、結果の背後を表示する
- **THEN** 左右の情報と円形予測、時間軸の全状態、スキル行を囲う外枠と薄い背景を表示せず、情報の内容、同時刻の処理順、既存の文字色とリング、陣営HPの棒を維持し、新しい囲いや装飾を加えない
- **AND** 中央バトルマップ、システムメニューと操作ボタンの通常、選択、ホバー、フォーカスの表現と機能は変わらない

#### Scenario: REQ-019-S05 - HPの1段表示

- **GIVEN** PLAYERとENEMYのHP合計
- **WHEN** 戦闘情報を表示する
- **THEN** 各陣営の名前、現在と最大のHP数値、比率のバーが同じ横の段に収まり、欠けずに読める

#### Scenario: REQ-019-S06 - 待ち量と処理順

- **GIVEN** 行動中ユニットの時刻が現在で、同時刻、近接時刻、同ユニットの再登場がある
- **WHEN** 行動順を表示する
- **THEN** 上から行動順に等間隔で1行動1点を置き、同時刻も個別の点に分かれ、各点は1体だけへ接続し、中央にユニット名を表示しない
- **AND** 同時刻は1、2、A、Bの処理順で並び、同ユニットの再登場も別の点を持ち、白い円弧は1から表示中の最大待ち量に対する残り待ち量の比を引いた相対進捗、残る灰は待ち量を表し、待ちが減るほど白が増える
- **AND** 最大待ち量が0なら全点を白一周とし、最大待ち量が変わると同じ基準で再計算し、個別周期の経過率や実時間と誤認させない
- **AND** 待ち0の白一周でも先頭の中心点で現在手番を識別し、同時刻の後続点は順番待ちとして扱い、状態文や待ち量数値の代替を追加しない

#### Scenario: REQ-019-S07 - 現在状態との対応と独立した選択

- **GIVEN** 未確定経路と左右の状態、未来の節点がある
- **WHEN** 状態か節点をホバーして選択する
- **THEN** 左の味方1と2、右の敵AとBの現在のリング、HPと補正率を該当節点へ接続し、対応状態と盤面ユニットを強調して詳細を切り替える
- **AND** 手番、経路、予測は変えず、未来のHPや位相を現在状態として捏造しない

#### Scenario: REQ-019-S08 - 予定の更新と終了

- **GIVEN** 撃破、行動後の再投入、戦闘終了のいずれかが発生する
- **WHEN** 行動順を再表示する
- **THEN** 撃破したユニットの節点を除き、行動後は新しい現在と待ち量に更新し、終了後は未来の予定を表示しない

#### Scenario: REQ-019-S09 - 右情報の整理

- **GIVEN** 通常または突然変異を持つ選択ユニット
- **WHEN** 右の情報を表示する
- **THEN** 現在のリングと中央名、CLASS、移動上限、全スキル、NORMAL以外のGEARとARMSの突然変異を表示する
- **AND** 陣営名、重複するHP数値、移動済み数、15個の配分数値と棒、型番、NORMALとACTIVE、PASSIVEの反復を表示せず、右情報と盤面の間に余白がある

### Requirement: REQ-020 - システム操作

画面はHELP、SETTINGS、RESTART、QUITを備え、HELPで操作を説明し、設定でウィンドウとフルスクリーンを切り替え、戦闘中は4つをこの順の2列2段で盤面右下へ置き下端を盤面と揃え、RESTARTでBUILDへ戻らなければならない(SHALL)。

#### Scenario: REQ-020-S01 - システムメニュー

- **GIVEN** 起動したゲーム
- **WHEN** 各メニューを操作する
- **THEN** HELPが開閉し、表示モードが変わり、RESTARTでBUILDに戻り、QUITで終了する
- **AND** 戦闘ではHELPとSETTINGS、RESTARTとQUITの2列2段で盤面右下へ並び、下端が盤面と揃い、BACKとWAITに重ならない

### Requirement: NREQ-001 - 画面寸法

Godot 4.7系の1920x1080基準画面はアイコン以外の画像を使わず左右の情報と円形予測とシステムメニューを保って中央マップを可能な限り大きくし、周囲の情報と盤面に適切な余白を設け、10x10マップの70x70論理セルを同じ倍率で正方形に拡大して全ユニットをセル内に収め、ウィンドウとフルスクリーンの表示領域へ16:9を維持して中央で最大限拡縮し、高DPIでも文字とリングとオーバーレイを同じ比率で鮮明に表示しなければならない(SHALL)。

#### Scenario: NREQ-001-S01 - 基準レイアウト

- **GIVEN** 1920x1080と1440x810ウィンドウ
- **WHEN** 各画面を表示する
- **THEN** マップ全体、右情報、下部予測、システムメニューが重ならず操作できる

#### Scenario: NREQ-001-S02 - 表示領域への追従

- **GIVEN** Godot 4.7系で16:9の縮小と拡大、4:3、横長、縦長の表示領域
- **WHEN** 表示領域の寸法を変更して元へ戻す
- **THEN** 1920x1080の内容全体が歪まず中央へ収まり、拡大したセルは正方形を保ち、余白は左右または上下に1物理ピクセル以内の差で等分され、元の寸法と倍率へ戻る

#### Scenario: NREQ-001-S03 - 全画面と高DPIの実表示

- **GIVEN** macOSの高DPI環境で起動したゲーム
- **WHEN** ウィンドウ、全画面、異なる縦横比を実際に表示する
- **THEN** 盤面と文字とリングとオーバーレイが表示領域へ追従し、周囲の余白とクリック対象が見た目に一致する

#### Scenario: NREQ-001-S04 - 盤面優先の配置

- **GIVEN** 最小、標準、拡大された表示領域
- **WHEN** 戦闘を表示して盤面と情報とメニューを操作する
- **THEN** 正方形の盤面が右下のメニューに縮小を強いられず、右情報との余白を持ち、左右の情報、円形予測、通知と操作部品が盤面に重ならず画面内へ収まり、表示とクリック位置が一致する

### Requirement: REQ-033 - 円形の位相予測

WHILE 経路後の位相を予測する間、画面は3リングを維持して周囲へCORE、GEAR、ARMSと最終重なりの4輪郭を共通の半径付近で重ねて表示し、実際の領域境界の色をグラデーションで接続し、実際の配分と回転に沿う色分類と形、同じステータスの一致が多いほど鮮明な色で局所的な重なりを表し、時間や乱数で変形させず、戦闘式と保存内容を変更せずに経路と配色へ追随しなければならない(SHALL)。

#### Scenario: REQ-033-S01 - 局所的な一致

- **GIVEN** 各ステータスが20ずつの3リング
- **WHEN** VIT領域の中央に相当する同じ角度を表示する
- **THEN** 位相の組み合わせに応じて次の重なりとなり、一致が多いほど結果の色が鮮明になる

| COREの位相 | GEARの位相 | ARMSの位相 | 重なり |
| --- | --- | --- | --- |
| 0 | 0 | 0 | 3つのVITが一致 |
| 0 | 0 | 72 | COREとGEARのVITだけが一致 |
| 0 | 72 | 144 | 同じステータスの一致がない |

#### Scenario: REQ-033-S02 - 決定的な更新

- **GIVEN** 有効な配分と突然変異、回転角、カスタム色を持つ予測
- **WHEN** 予測を表示する
- **THEN** 全周の色分類と形が実際の領域を反映して閉じ、同じ入力では同じ4輪郭になり、経路と配色の変更時に更新され、入力の状態と保存は変化しない

#### Scenario: REQ-033-S03 - 実表示の比較

- **GIVEN** 一致する位相とずれた位相、既定と変更した配色、基準と最小の画面
- **WHEN** Godotで予測を比較する
- **THEN** 内側の3リングとHP、周囲の4輪郭を区別でき、リング下のINFとRESの最終同期率は表示せず、拡大マップと左右の情報が重ならず、経路の選択と対象への操作を続けられる

#### Scenario: REQ-033-S04 - 重なる輪郭と境界の連続色

- **GIVEN** 同じステータス配分で一致または不一致となる位相と有効な配色
- **WHEN** 円形予測を表示する
- **THEN** 4輪郭が近い半径で重なり、各色領域の中央では指定色を保ち、境界では隣接する実際の色へ連続的につながり、完全一致の輪郭は不一致より鮮明で、同期率と戦闘状態を変えない
