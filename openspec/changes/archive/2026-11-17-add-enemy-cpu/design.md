# 設計

## 背景と制約

openspec/tech.mdの決定的な計算、保存の境界と表示原則を使う。
現行battleは手動の入力だけで進み、検証専用の探索を本番へ接続していない。
新しい判断部品と表示進行部品から既存battleの公開操作を呼び、戦闘式と終局の時機を共用する。

## 設計判断

### D-01 - 公開状態から合法手を比較する

- 選択: game/cpu_policy.gdを独立させ、移動上限までの経路、装備済みACTIVEとWAITを評価する。\
  パネルを経路順に適用した複製と既存のeffectを使い、即時の勝敗はbattleの複製へ操作を適用して判定する。\
  自陣営の即時勝利、次の敵行動による敗北の阻止、撃破、目標への距離、実効回復、反撃と反復を評価する。\
  同点は決定的な列挙順とし、乱数と非公開の入力を使わない。\
  反撃候補は到達可能な経路と手番時刻に基づき、全探索による複数手先の最善手は保証しない。\
  回復の基礎重み0.85、ダメージ1.2、撃破120、反撃0.7、反復18と履歴8件をgame/tuning.gdへ定義する。\
  回復連続時は同じユニットの回復点を抑え、終局と危険回避はその調整より優先する。
- 理由: 位相と目標へ応じて戦い、短期的な回復だけの循環を抑える。
- 代替案: 検証用の特定の配置に依存する攻略、能力の補正と学習型AIは採用しない。
- 昇格: openspec/tech.md の アーキテクチャ、openspec/structure.md の 配置原則。

### D-02 - 表示進行と戦闘の時間を分ける

- 選択: ui/cpu_turn.gdを状態機械とし、THINK、ROUTE、COMMIT、ACTION、TARGET、RESULTを順に進める。\
  THINK0.30秒、1歩0.16秒、確定0.14秒、行動0.18秒、対象0.20秒、結果0.40秒をgame/tuning.gdへ置き、最大4歩でも概ね1から2秒へ収める。\
  早送りは4倍とし、一時停止、補助画面とフォーカス喪失中は時間を蓄積しない。\
  非同期タイマーを残さず、各段階で元の手番との一致を確認し、resetでRESTARTと終局の処理を破棄する。\
  CPUの表示が残る間は手番が人へ移っていても変更入力を拒否する。
- 理由: 経路と予測を読め、速度によって二重実行やゲーム時刻のずれを生じない。
- 代替案: 偽の通信待ち、無意味なカーソルと長いダイアログ、移動ごとの戦闘確定は採用しない。
- 昇格: openspec/tech.md の 技術上の判断基準。

~~~mermaid
stateDiagram-v2
  state "考慮" as THINK
  state "経路予測" as ROUTE
  state "移動確定" as COMMIT
  state "行動選択" as ACTION
  state "対象表示" as TARGET
  state "結果の間" as RESULT
  state "次の手番" as NEXT
  THINK --> ROUTE
  ROUTE --> COMMIT
  COMMIT --> ACTION
  ACTION --> TARGET
  TARGET --> RESULT
  ACTION --> RESULT: WAIT
  RESULT --> NEXT
~~~

終局は確定または実行直後にRESULT画面へ移り、未処理の段階を破棄する。
閉塞時は経路と確定を省いてWAITへ進む。
中断は全段階で現在状態を保つ。

### D-03 - 手動とセーブを維持する

- 選択: 起動時は従来の手動とし、BUILDのENEMY CPUのチェックで切り替える。\
  モード、早送りと停止は実行中だけの値とし、保存と設定へ加えない。\
  戦闘中は右情報の下の空間にCPU名と段階、速度とPAUSEを置き、盤面とメニューの位置を維持する。\
  CPU中も盤面とタイムラインの情報選択、HELP、SETTINGSとRESTARTを許可するが、経路と行動の変更を拒否する。\
  手動のBUILDの正確な操作集合の検査は承認済みのチェック追加へ更新し、他の情報と操作は維持する。
- 理由: CPUを試しながら既存の手動対戦と保存を壊さず戻せる。
- 代替案: 既存セーブの移行と自動保存、敵CPUの強制は採用しない。
- 昇格: openspec/tech.md の 技術上の判断基準。

判断の検査は部品で、停止と段階の検査は表示進行部品で行う。
UIでは接続と入力の競合だけを代表例で確かめる。
複数のシードと構成で対戦を再生し、終局、反復、計算時間と合法性を観測する。
通常の実Godotで現在のビルドから一戦を可能な限り最後まで操作し、観察、主観と未確認を分ける。

## リスクと移行

探索の時間と回復の停滞は測定し、調整値で明白な欠陥を改善して再検証する。
生存評価は合法な反撃候補に基づく短期評価であり、全局面の勝利を保証しない。
モードと速度の保存形式の移行はない。
既存セーブと実設定を保存せず、検証専用のパスを使う。
