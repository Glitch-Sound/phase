# 設計

## 背景と制約

openspec/tech.mdの技術上の判断基準とテスト方針、openspec/structure.mdの配置原則に従う。
新しい選択は同じ黒い面、下線のフォーカスと余白を用い、背景のビルドを候補選択で変更しない。

## 設計判断

### D-01 - 選択候補と確定を分離する

- 選択: game/build_choices.gdで種類別の候補、可否、説明と純粋な候補構成を生成し、ui/build_dialog.gdの共通画面へ渡す。\
  現在と候補の実リングを並べ、APPLYだけが原本へ反映する。\
  CANCELとEscは原本を保つ。\
  装備は126配分を能力値の下限で絞り、値順へ並べ、変異は120件の別リストにする。\
  既存所持品が標準集合外なら明示的な候補として加えるが、旧配分を丸める処理は追加しない。\
  未解放と他枠で使用中のスキルは非活性にし、現在装備と選択中を区別する。\
  CLASSはCOREのみの2順序、変異は対応装備のみの順序、スキルは実際の対象差分を図示する。\
  OPERATIONは現在の目標、説明と初期配置を表示する。\
  操作位置はtuningへ集約し、ダイアログは1280x820を基準にリストと比較を分ける。\
  UNLOCK ALLとENEMY CPUは同じCheckButtonで状態を示し、デバッグの保存境界を維持する。
- 理由: 126と120の積を作らず、実値と可否の規則を一つにして誤った確定と取消を防ぐ。
- 代替案: 即時に確定するドロップダウンと全組合せ一覧、別々の選択画面は使わない。
- 昇格: openspec/tech.md の 技術上の判断基準、openspec/structure.md の 配置原則。

~~~mermaid
flowchart LR
  BUILD["現在の3体構成"] --> OPEN["共通選択を開く"]
  OPEN --> PICK["候補と絞り込み"]
  PICK --> PREVIEW["独立した候補の実リング"]
  PREVIEW --> APPLY["解放と重複を再検査して確定"]
  APPLY --> BUILD
  PREVIEW --> CANCEL["取消またはEsc"]
  CANCEL --> BUILD
~~~

### D-02 - 陣営とIDから6体を扱う

- 選択: 通常の編成数を3とし、配列は01、02、03、A、B、Cの固定順にする。\
  標準配置はPLAYERの(3,4)、(3,6)、(3,2)と、左右反転したENEMYの(6,4)、(6,6)、(6,2)を基本にする。\
  初期ENEMYの構成も同じ3役を複写して左右の初期条件を揃える。\
  固有ステージはAの守備とBの到達役をIDで維持し、3体目を空き初期セルへ置く。\
  戦闘式と目標そのものは変えず、CPUのB生存判定を添字からIDへ置き換える。\
  timelineは陣営から左右を選び、同陣営の3枚を既存範囲内で間隔を保って配置する。\
  新規保存は3構成とし、有効な2構成の読込は元の2体と収集を保持して3体目だけをメモリへ追加する。\
  補完構成は既定の3体目を基本に、所持していない装備とスキルがあれば所持品から有効なものを選び、読込元へ自動保存しない。\
  2と3以外の数と不正な既存構成は拒否する。\
  過去の2対2の条件に依存する機械的な検査だけは、明示的な旧fixtureを使う。
- 理由: 3体目を敵と扱う固定添字、敵全滅を2体で判断する検査、IDと描画の対応漏れを避ける。
- 代替案: プレイヤーだけ増やす方式と、既存の2体を作り直す移行は使わない。
- 昇格: openspec/tech.md の テスト方針。

### D-03 - 英語の説明と予測見出しを整理する

- 選択: 現行HELPの重要な規則を短い英語へ訳し、スキルと周囲のページを維持する。\
  パネルのツールチップを概要と薄い詳細へ分け、CORE専用と通常回転、周囲倍率の意味を保つ。\
  PREVIEWはTURNと同じフォントと灰色で左下へ置き、既存リングと波形をずらさない。\
  STARTは文字を中央、アイコンを左に置き、互いを重ねない。\
  ユーザー向け文字列だけを英語にし、ソースの日本語コメントと仕様文書は維持する。
- 理由: 操作の説明を失わず、実戦と編集を同じ視覚言語へ揃える。
- 代替案: 説明画像と多言語切替は追加しない。
- 昇格: なし。

共通候補の可否とプレビューは部品、画面は確定と取消、フォーカスと各入口の接続を確認する。
6体の生成、手番と保存は下層で確認し、既存の戦闘検査を重複させない。
バランスの固定勝敗と手数は追加せず、実戦の観測と分ける。
最小、基準、拡大でダイアログの末尾、3体とHELP、クリックと取消を実GPUで確認する。
実ユーザーの保存と設定のハッシュ、更新時刻を前後で照合し、確認画像はローカルにだけ保存する。

## リスクと移行

2体から3体への補完はメモリ内だけとし、ファイルは削除せず自動保存もしない。
一覧の大量フォーカスとスクロールはHomeとEnd、上下キーと可視化で補い、閉じると呼出元へ戻す。
旧検査の構成数とドロップダウンに関する期待だけは承認された仕様変更に合わせ、戦闘式と基本ルールの合否を弱めない。
