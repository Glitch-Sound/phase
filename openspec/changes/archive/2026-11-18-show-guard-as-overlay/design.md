# 設計

## 背景と制約

openspec/tech.mdの表示原則、テスト方針とopenspec/structure.mdの配置原則に従う。
防御はguard_activeだけで識別できる既存の状態であり、戦闘の状態遷移を変えずに表示を置き換える。

## 設計判断

### D-01 - リング間へ薄い多角形を共通描画する

- 選択: visualsの記号データに、防御中の生存ユニットだけの八角形を加える。\
  HPとCOREの間に収め、低不透明度の面と細線をリングより先に描き、中央名とHPを上へ描く。\
  game/tuning.gdに辺数8、半径比0.52、線幅比0.018、最小物理線幅0.85、面の不透明度0.045、線の不透明度0.55を集約する。\
  彩色リングの情報を増減せず、現在の白いHPと区別するため線を半透明にする。\
  従来の右上の小さな盾と状態文、GUARD対象の文字チップと発動トーストを除く。\
  予測は複製だけへ防御を付け、盤面の対象と左下、右詳細で同じ図形を使い、右にPREVIEWだけを示す。\
  BUILD、スキル一覧と行動ボタン、HELPのGUARD名と操作説明は残す。
- 理由: 既存リングの外形と経路線の領域を変えず、文字の追加なしに防御を識別できる。
- 代替案: 外周の盾は経路やセル境界と干渉するため使わず、HPを覆う濃い面と発光も使わない。
- 昇格: なし。

  TARGET["GUARDの対象予測"] --> COPY["防御ありの独立した複製"]
  COPY --> GLYPH
  GLYPH --> BOARD["盤面と手番一覧"]
  GLYPH --> DETAIL["詳細と予測"]
  HIT["攻撃で防御を消費"] --> LIVE

## リスクと移行

小さな記号では線がHP円弧と混同されやすいため、位置をリング間へ限定して物理線幅と実ピクセルを確認する。
防御は攻撃で解除される既存の値を参照し、予測だけで原本を変えないことを確認する。
データの移行はなく、既存のセーブと配色設定へ保存しない。
