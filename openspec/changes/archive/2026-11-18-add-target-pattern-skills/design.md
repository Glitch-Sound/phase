# 設計

## 背景と制約

openspec/tech.mdの技術上の判断基準、テスト方針と表示原則を使う。
現行はスキルIDと隣接距離をモデル、表示とCPUが個別に判定している。
追加6種の作用は既存のDAMAGEとHEALに一致し、調整定数と保存の版は変更しない。

## 設計判断

### D-01 - 対象位置を一か所で定義する

- 選択: game/catalog.gdへ4種類の4方向オフセットと、種別、陣営、生存、負傷を含む対象条件を集約する。\
  既存のACTIVE_DAMAGE_ADJACENTとACTIVE_HEAL_ADJACENT、受動MOVEのIDと順序を維持する。\
  追加IDはACTIVE_DAMAGE_DIAGONAL_ONE、ACTIVE_DAMAGE_ORTHOGONAL_TWO、ACTIVE_DAMAGE_DIAGONAL_TWOと対応するHEALとする。\
  モデルとCPUは同じ対象条件、表示は同じオフセットを使い、盤外は表示しない。\
  2マス先は中間セルを含めず、占有による遮蔽を加えない。\
  game/phase_math.gdとgame/tuning.gdは変更せず、作用の種類だけを既存の計算へ渡す。
- 理由: 斜めや距離の違いを画面とCPUだけ別に解釈する退行を避ける。
- 代替案: 距離のしきい値を広げる方法は近いセルや途中セルまで対象にするため使わない。
- 昇格: openspec/tech.md の 技術上の判断基準。

~~~mermaid
flowchart LR
  SKILL["スキルと4方向の対象条件"] --> MODEL["戦闘の対象判定"]
  SKILL --> UI["範囲と有効対象の表示"]
  SKILL --> CPU["行動候補と反撃"]
  MODEL --> EFFECT["既存の単体効果と手番終了"]
  CPU --> MODEL
~~~

### D-02 - 初期状態と版1の保存を維持する

- 選択: 上下左右1マスの旧2種だけを初期解放し、追加6種はMOVE+1と同じ未開放候補へ含める。\
  3枠と重複拒否、同じIDを両PLAYERで共有できる構成を維持する。\
  版1の文字列IDの配列形式を維持し、旧保存へ追加品を自動補完しない。\
  敵の初期スキルは従来どおりとし、新種を装備したCPUの検証では専用の構成を明示する。
- 理由: 新品の取得機会を残し、既存のプレイ状態を上書きしない。
- 代替案: 全品の初期解放と敵の自動再装備は既存構成を変えるため行わない。
- 昇格: なし。

### D-03 - 表示とCPUを作用の種類へ接続する

- 選択: 旧ADJACENTのラベルと説明を保ち、新種はDIAGONAL 1、ORTHO 2、DIAGONAL 2とする。\
  DAMAGEとHEALの表示色、符号、回復上限と反復評価は個別IDではなくeffectで判定する。\
  行動選択は装備ACTIVEだけを表示し、有効対象がなければ無効にする。\
  CPUの反撃は1攻撃者と対象の最大1回を維持し、複数の攻撃種で二重計上しない。\
  HELPのACT欄だけを4行へ収めて位置関係を説明し、他の説明と装備3枠の寸法を維持する。
- 理由: 新しい回復を攻撃色にしたり、回復種の切替で反復を回避したりする例外を防ぐ。
- 代替案: 新種ごとのUIと評価の分岐は増やさない。
- 昇格: なし。

新しい非機能要件はなく、既存の最小、基準、拡大と縦長で収まりと操作を確認する。

## リスクと移行

同じ威力でも遠距離と斜めが位置取りを変えるため、実戦で使用と操作の読み取りを観測する。
敵の通常の初期構成には追加品がない点を報告し、検証用の新種CPUと区別する。
旧ID、既存の開放と構成は保持し、実セーブと色設定には触れない。
追加6種の取得で既存の未取得MOVEの抽選候補が増えるが、件数や抽選式は調整しない。
