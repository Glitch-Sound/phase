# 設計

## 背景と制約

- 提案: [proposal.md](proposal.md)
- 前提: openspec/tech.md の 技術上の判断基準とテスト方針、openspec/structure.md の UI。

## 設計判断

### D-01 - 到達と計算を分離する表示所有

- 選択: UIの専用部品が確定済みの行動と所有戦闘を保持し、飛行、到達、反応を進める。到達イベントで既存のactを一度だけ呼び、結果画面は反応後に開く。
- 理由: HPを早く変えず、既存のモデルとCPU判断を共用し、退出と停止を安全に扱える。
- 代替案: モデルへ演出時間を入れる案はゲーム内時間と表示が結合するため採らない。
- 昇格: openspec/structure.md の UI

```mermaid
flowchart LR
  A["最終確定"] --> B["既存の移動と一拍"]
  B --> C["細い光の飛行"]
  C --> D["既存のactを一度実行"]
  D --> E["局所反応と数値"]
  E --> F["次手番または結果"]
```

### D-02 - 細い輪郭と安全な幾何

- 選択: 二次曲線上の短い光と局所の線を描き、盤面と全ユニットのリング外形で線分を切り取る。攻撃は短い切れ目、回復は開いた円弧とする。
- 理由: 近接と盤端でもHPと名前を覆わず、色覚と変更色だけに依存せず区別する。
- 代替案: 素材の粒子と画面全体の発光は暗い画面と干渉するため採らない。
- 昇格: openspec/tech.md の 表示原則

### D-03 - 短い調整値

- 選択: game/tuning.gdの1か所に飛行の基準0.18秒、距離加算0.025秒、上限0.24秒、攻撃反応0.16秒、回復反応0.24秒、主線1.8pxを置く。強いINFの幅と反応は最大25%の強調に留める。
- 理由: 読み取れる到達を保ちつつ一手の追加時間を短くし、表示速度と動きを抑える設定を共用する。
- 代替案: 固定の長い待ちと威力の調整は採らない。
- 昇格: なし

## 検証計画

| シナリオID | 設計判断 | 検証方法 |

S01は表示部品の幾何とUIの到達接続で確認する。
S02は部品の所有と停止、UIの退出とCPU接続を確認し、同じ判断をモデルで再検証しない。
既存の威力、勝敗と終了手数の固定期待値は追加しない。
実描画は最小と標準のGPU画像と短い実映像で確認する。

## リスクと移行

遅れたイベントの二重実行は所有戦闘と手番の検証、到達済みフラグで防ぐ。
盤端と隣接者へのはみ出しは線分の切り取りで防ぐ。
保存形式の移行はない。
実セーブと設定、旧動画はハッシュと更新時刻で保護を確認する。
