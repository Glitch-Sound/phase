# 提案

## 目的

BUILDのCLASSが2つの抽象名だけのため、装備のMUTATIONと同じ配置の比較と選択ができない。\
COREの基準配置を同じ120候補から選べるようにし、配置コードを見て対象リングの違いを判断できるようにする。

## 変更内容

- CLASSを5ステータスの120配置へ拡張し、COREだけへ適用する。
- CLASSとMUTATIONは配置コードを主表示にし、VIRSLには小さくSTANDARDを添える。
- CLASSのVIRSLと従来の逆順VLSRIは常時利用可能、他は既存の共有変異の解放に従う。
- 旧STANDARDとREVERSEは同じ配置で読み込み、装備と収集、読込元を維持する。
- COREの移動、回転、RESETと各式は維持し、選択した配置で戦闘と予測を計算する。

## 対象外

- 変異のドロップと装備側の解放条件、戦闘式の調整は行わない。
- トグルの余白は並行する依頼の直接調整として扱い、このchangeの新規ルールへ含めない。
- 公開、push、画像アップロードと実セーブの更新は行わない。

## 対象の仕様

### 新規

- なし

### 変更

- `build-collection`: CLASSの候補、対象リング、解放、表示と保存互換を追加し、共通選択の違いを更新する。

## 影響

- 位相配置、カタログ、収集の検証、共通候補と画面、HELP、関連検査へ影響する。
- 開始HP、手番速度、パネル回転量と装備の配置は変更しない。

## 未決事項

- なし。解放と旧クラスの対応は利用者から判断を委任され、従来の2配置を維持する条件を選んだ。
