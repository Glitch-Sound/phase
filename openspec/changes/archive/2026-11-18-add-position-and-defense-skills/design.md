# 設計

## 背景と制約

openspec/tech.mdの技術上の判断基準とテスト方針、openspec/structure.mdの配置原則を使う。
既存の行動は移動後に対象を選んで一度適用するため、位置操作と防御も同じ状態遷移へ置く。
既存の8攻撃と回復、初期装備、保存の版と調整値は維持する。

## 設計判断

### D-01 - 進入と強制移動を統一する

- 選択: SWAPは上下左右の生存味方、PUSHは同じ方向の生存敵と、その外側の盤内空きセルだけを許可する。\
  SWAPの両者、PUSHの対象はそれぞれ到着先へ1歩進入したものとして、battleの共通進入処理からphase_mathの通常回転とパネル効果を使う。\
  共通進入処理が装備のPASSIVE_IGNORE_PANEL_SELFを判定して計算へ無視フラグを渡し、特殊CORE効果だけをNORMAL扱いにし、通常の装備回転を維持する。\
  強制移動ではHP、防御、対象の時刻と両者のmovedを保ち、行動者だけが通常どおり手番を完了する。\
  交換を同時に確定してから、移動した全員のREACHを敗北優先で判定し、OCCUPYは既存のENDへ渡す。
- 理由: 強制移動だけ位相が止まる例外を作らず、到達役を動かした結果を正しく判定する。
- 代替案: 強制移動で角度とCOREを固定する案は進入の意味を増やすため使わない。
- 昇格: openspec/tech.md の 技術上の判断基準。

### D-02 - 防御は戦闘中の1回の状態とする

- 選択: ACTIVE_GUARD_SELFは移動後に自分を対象としてguard_activeを付ける。\
  防御中は再付与できず、手番や回復、強制移動では消費せず、次のDAMAGEで0ダメージでも消費する。\
  通常式で整数化したダメージへgame/tuning.gdのGUARD_DAMAGE_MULTIPLIERを掛けて再度切り捨てる。\
  初期値は0.5であり、行動1回を使う防御として効果を確認しやすく、完全無効にはしない暫定値である。\
  phase_mathの予測は状態を消費せず、battleの確定だけで消費する。\
  新しい戦闘はguard_activeをfalseにし、保存へ状態を追加しない。\
  無移動でのGUARDやLAST STANDの救済は加えない。
- 理由: 重ね掛けや時刻による期限を避け、次の1攻撃という約束だけで説明できる。
- 代替案: RESの一時増加や手番数の期限は同期と待ち時間に新しい例外を増やすため使わない。
- 昇格: openspec/tech.md の 技術上の判断基準。

### D-03 - 予測と作用を共有して表示とCPUへ渡す

- 選択: 位置と防御の予測はbattleの独立したユニット複製へ適用し、確定と同じ部品を使う。\
  人の有効対象ホバーとCPUのTARGETで移動先の角枠、左の行動者予測、右の対象の移動後リングを示し、予測であることを短いラベルで区別する。\
  SWAP、PUSH、GUARDは数値の回復やダメージとして描かず、作用名を示す。\
  防御は既存Lucide shieldをリングの右上に小さく示し、詳細でGUARDを確認できる。\
  通常の配置は変えず、HELPへSKILLSの補助ページを加えて既存説明を保持する。\
  CPUはeffectで攻撃、回復と新作用を分け、合法な予測を評価し、PUSH後の敵位置から反撃経路を作り直す。\
  新作用だけの補助評価として、目標との距離差と直ちに届く攻撃機会の差を有限のスコアにし、終局の優先を保つ。\
  game/tuning.gdにCPU_UTILITY_GOAL_WEIGHTを12、CPU_UTILITY_PRESSURE_WEIGHTを0.25で置き、通常行動の既存重みは変えない。
- 理由: 新しい位置を見せるだけでモデルが旧位置のまま評価する退行や、新作用を回復扱いする分岐を避ける。
- 代替案: 見た目だけの移動先や独立したCPU用の効果式は使わない。
- 昇格: なし。

~~~mermaid
flowchart LR
  CHOICE["移動後の行動選択"] --> TARGET["対象と押し先の検証"]
  TARGET --> COPY["複製上の位置と防御の予測"]
  COPY --> UI["移動先とリングの表示"]
  COPY --> CPU["目標と危険の比較"]
  TARGET --> APPLY["同じ効果を実状態へ確定"]
  APPLY --> GOAL["移動した全員のREACH"]
  GOAL --> END["既存の手番終了"]
~~~

### D-04 - 4品を既存の収集と3枠へ加える

- 選択: ACTIVE_SWAP_ADJACENT、ACTIVE_PUSH_ADJACENT、ACTIVE_GUARD_SELF、PASSIVE_IGNORE_PANEL_SELFを一覧の末尾へ追加する。\
  旧9IDと順序、初期2種、敵の初期装備と3枠を維持し、新4品は戦利品から取得して共有する。\
  版1の保存形式を維持し、古い保存へ自動補完しない。\
  新CPUの検証は新種を明示した検証用構成と通常の敵を区別する。
- 理由: 既存の進行と構成を上書きせず、スキル枠に選択の対価を残す。
- 代替案: 全品初期解放や枠の増加は行わない。
- 昇格: なし。

新しい非機能要件と外部依存はない。

## リスクと移行

強制移動とパネルは新しい目標達成の経路を作るため、本人以外の到達と敗北優先を直接検査する。
防御は待つほど強くなる累積ではないが、回復と組み合わせた長期戦の強さは実プレイで継続判断する。
CPUは1手先の公開状態を比較するため、長い連携や人間の読み合いの完全な再現を保証しない。
既存の実セーブと配色設定へ保存せず、検証専用のパスと構成を使う。
新4品のIDだけを保存し、実行時状態の移行と保存の版更新はない。
